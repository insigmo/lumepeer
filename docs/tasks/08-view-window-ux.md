# 08 — Окно просмотра: полный экран, масштаб, горячие клавиши

**Зависимости:** нет. Задача целиком в `apps/desktop`, TCB не трогается.

## Что уже есть

- `apps/desktop/src/view-window.ts` — разбор бинарного кадра из IPC
  (`status:u8 | input:u8 | width:u32 | height:u32 | timestamp_us:u64 | RGBA8`),
  `paintFrame` подгоняет `canvas.width/height` под размер удалённого экрана и
  рисует через `putImageData`.
- `apps/desktop/src/view.ts` — цикл `view_next_frame`, проброс ввода.
- `apps/desktop/src/toolbar.ts` — плавающая панель: настройки (выбор
  разрешения), мониторы, чат, микрофон, Ctrl+Alt+Del, свернуть/развернуть.
- Понижение разрешения на стороне **хоста** — `crates/media/src/scale.rs`,
  ADR 0018.

## Чего нет

`grep -rn "fullscreen\|zoom\|scale\|fit" apps/desktop/src/view-window.ts apps/desktop/src/view.ts`
даёт пусто. Нет полноэкранного режима, нет вписывания в окно, нет 1:1, нет
масштабирования и панорамирования, нет клиентских горячих клавиш.

## Задача 1 — Режимы отображения: fit / 1:1 / масштаб

**Файлы:** `view-window.ts`, `view.ts`, `toolbar.ts`, `i18n.ts`

- Три режима: **Вписать** (по умолчанию, сохраняя пропорции), **1:1**
  (пиксель в пиксель, при необходимости со скроллом), **Масштаб** (ползунок
  или Ctrl+колесо).
- Масштабировать **CSS-размером** элемента `canvas`, не переписывая
  `canvas.width/height`: буфер должен оставаться нативного размера кадра,
  иначе `putImageData` придётся масштабировать вручную каждый кадр.
- Для 1:1 и увеличения учитывать `devicePixelRatio`, иначе на HiDPI «1:1»
  окажется не 1:1.
- Режим запоминается на сессию.

## Задача 2 — Панорамирование ⚠️ вместе с исправлением маппинга ввода

**Файл:** `view-window.ts`

`ViewInput` (~стр. 209) переводит координаты указателя так:

```
const rect = canvas.getBoundingClientRect();
const x = ((event.clientX - rect.left) / rect.width) * POINTER_RANGE;
```

Пока canvas всегда занимает всю область целиком, это верно. **Как только
появляется зум и панорамирование, эта формула начнёт слать хосту не те
координаты**, и клики поедут — тихо, без ошибок.

Делать: вынести преобразование «координата в окне → нормализованная координата
удалённого экрана» в одну чистую функцию, принимающую текущие масштаб и
смещение, и **покрыть её юнит-тестами** для каждого режима (fit, 1:1,
увеличение со смещением, HiDPI). `view-window.test.ts` уже гоняется в jsdom —
там же и тестировать.

Панорамирование: перетаскивание средней кнопкой или пробел+drag. **Не** левой
кнопкой — она уходит на удалённую машину.

## Задача 3 — Полноэкранный режим

**Файлы:** `view.ts`, `toolbar.ts`, `capabilities/view.json`

- Кнопка в тулбаре и горячая клавиша.
- Проверить, что нужное право окна есть в `capabilities/view.json`. Оно
  намеренно узкое, и его описание объясняет почему — **добавляй ровно одно
  недостающее право, не `core:default`** и не подстановочные записи.
- В полноэкранном режиме тулбар остаётся достижимым (автоскрытие с
  появлением по наведению к краю) — иначе из режима нельзя выйти мышью.

## Задача 4 — Горячие клавиши клиента

**Файл:** `view.ts` / новый `view-hotkeys.ts`

- Минимум: выход из полного экрана, переключение режима отображения,
  открыть/закрыть чат, отправить Ctrl+Alt+Del, свернуть тулбар.
- **Главная опасность:** окно просмотра пересылает ввод на удалённую машину.
  Любая клиентская горячая клавиша ворует нажатие у гостя. Поэтому:
  использовать префикс-модификатор, которого нет в обычной работе (например
  `Ctrl+Alt+Shift+…`), перехватывать **только** точное совпадение и
  обязательно вызывать `preventDefault` ровно для перехваченного, пропуская
  всё остальное дальше без изменений.
- Список клавиш показывать в подсказке — невидимые горячие клавиши
  неотличимы от бага.

## Задача 5 — Тесты и доступность

- `view-window.test.ts`: чистая функция маппинга координат — по тесту на
  режим; `paintFrame` не ломается при смене размера удалённого экрана на лету.
- `toolbar.test.ts`: новые кнопки, их `aria-label`, достижимость с клавиатуры.
- `accessibility.test.ts` (axe-core) и `keyboard-nav.test.ts` обязаны пройти.
- Все новые строки — ключи i18n в `en` **и** `ar`. Арабский здесь не
  формальность: он RTL, и панель, положение тулбара и направление
  панорамирования обязаны выглядеть осмысленно при `dir="rtl"`.

## Ловушки

- Кадр приходит через IPC как RGBA и ограничен `MAX_PICTURE_PIXELS`
  (1920×1080) — узкое место здесь IPC, а не энкодер. Не пытайся «улучшить
  качество» увеличением разрешения на клиенте: масштабирование чисто
  презентационное.
- Не трогай разбор заголовка кадра и `POINTER_RANGE`: это контракт с
  Rust-стороной.
- Никакого фреймворка. UI — `lit-html` и ничего сверх него.
