# 04 — Постоянный доступ: пароль устройства и TOTP

**Зависимости:** `01`. **Блокирует:** `05`.

## ⚠️ Сначала разреши противоречие, потом пиши код

`CLAUDE.md` и `README.md` перечисляют «**No unattended access**» среди
нерушимых правил. При этом `crates/core/src/unattended.rs` (460 строк) уже
реализует пароль устройства на Argon2id, TOTP по RFC 6238 и блокировку от
перебора, и ссылается на ADR 0021 — **файла которого в `docs/adr/` нет**.

Это не задача для самостоятельного решения агентом. Первым делом:
1. Найти или восстановить ADR 0021 (см. `15-docs-and-adr-debt.md`).
2. Если решение действительно принято — обновить `CLAUDE.md` и `README.md`,
   заменив «no unattended access» на точную формулировку того, что разрешено.
3. Если подтверждения нет — **остановиться и спросить владельца репозитория**,
   а не расширять модель доверия по своей инициативе.

Что остаётся нерушимым в любом случае: **никакого скрытого захвата**. Хост,
отдающий экран без человека за ним, обязан показывать это на своей стороне —
видимый индикатор идущей сессии, который нельзя выключить из UI гостя.

## Что уже есть

`UnattendedAccess` с `set_password`, `restore_password_hash`, `stored_secret`,
`set_totp_secret`, `totp`, `locked_out`, `verify_full`. Константы
`UNATTENDED_TOTP_STEP_SECS`, `UNATTENDED_MAX_FAILED_ATTEMPTS`,
`UNATTENDED_LOCKOUT_DURATION_SECS`. Единственная ссылка на модуль во всём
репозитории — строка `pub mod unattended;` в `crates/core/src/lib.rs`.

## Задача 1 — Хранение секретов в OS-keystore

**Файл:** `crates/net/src/keystore.rs`

Трейт `Keystore` сейчас умеет только идентичность эндпоинта
(`load_identity`/`store_identity`/`delete_identity`). Нужен обобщённый слот:
`load_secret(entry: &str)`, `store_secret(entry: &str, bytes: &[u8])`,
`delete_secret(entry: &str)`, а `*_identity` выразить через них, сохранив
`IDENTITY_ENTRY` как имя записи.

- Реализовать во **всех** бэкендах: Secret Service, Apple Keychain, Windows
  Credential Manager, `FileKeystore`, `MemoryKeystore`.
- PHC-строка пароля и секрет TOTP идут туда. **Не в `config/*.toml`** —
  `CLAUDE.md` прямо запрещает секреты в конфиге.
- Отсутствие записи — это `Ok(None)`, а не ошибка.

## Задача 2 — Путь входа без диалога согласия

**Файл:** `apps/desktop/src-tauri/src/network.rs`

- Гость, дозвонившийся до хоста с включённым постоянным доступом, вместо
  `ConsentRequest` получает запрос учётных данных, отвечает паролем и — если
  включён — кодом TOTP, и хост зовёт `UnattendedAccess::verify_full`.
- Решение принимает **только** `crates/core`. Actor передаёт ответ и получает
  вердикт; никакой логики сравнения в `src-tauri`.
- Роль после успешной проверки берётся из настройки хоста, снятой снапшотом в
  момент выдачи. Независимые гранты из `01` — по умолчанию все выключены.
- Отказ отдаёт ровно то, что говорит `UnattendedError`: `BadPassword`,
  `BadCode`, `LockedOut { remaining_secs }`. **Никаких уточнений** вроде
  «пароль верный, код нет» — тип уже намеренно огрублён, не разглашай больше.
- Блокировка от перебора уже в `verify_full`. Не добавлять второй счётчик.

Новые сообщения протокола (запрос и ответ на учётные данные) — по правилам из
`03-file-transfer.md`, задача 1: только в конец `MessageKind`, поднять
`PROTOCOL_MINOR`, новая строка `FEATURE_*`, новые golden-векторы дописать в
конец `tests/interop/golden_vectors.txt`, старые не трогать.

## Задача 3 — UI настроек хоста

**Файлы:** `commands.rs`, `main.rs`, `capabilities/main.json`,
`apps/desktop/src/`, `i18n.ts`

- Экран: включить/выключить постоянный доступ, задать и сменить пароль,
  включить TOTP с показом секрета (QR — уже есть генератор QR для инвайтов,
  переиспользовать), роль по умолчанию.
- Команды **только из главного окна** (`check_window`), никогда из `view-*`.
- Пароль в webview не возвращается никогда — ни в каком виде, включая хеш.
  Наружу отдаётся только `enabled: bool` и `totp_enabled: bool`.
- Пока постоянный доступ включён, в UI хоста висит несъёмный индикатор.

## Задача 4 — Тесты

## Ловушки

- TOTP-окно: `verify` уже принимает соседние шаги. Не расширяй окно «чтобы
  работало» — это прямое ослабление второго фактора.
- Argon2id-параметры менять нельзя без ADR: смена делает все сохранённые PHC
  невалидными.
- Блокировка считается по времени монотонных часов (`Instant`), а не по
  системным. Не переводи её на `SystemTime` — это делает обход тривиальным
  переводом часов.
