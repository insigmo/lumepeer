# 06 — Запись сессии: довести до пользователя

**Зависимости:** `01` (грант `recording` иначе невыдаваем).

## Что уже есть

- `crates/media/src/record.rs` (466 строк) — контейнер `LMREC`: заголовок,
  затем записи `kind|reserved|t_us|len|payload`, где kind 1 = кадр H.264,
  2 = чанк Opus, 3 = событие (строка JSON). Формат append-only по построению:
  писатель никогда не делает seek, поэтому оборванная запись остаётся
  валидным префиксом, который читатель этого же модуля дочитывает до обрыва.
- `apps/desktop/src-tauri/src/recorder.rs` (259 строк) — `SessionRecorder`:
  писатель в отдельном потоке за каналом, кадры **дропаются со счётчиком**
  при переполнении очереди, чтобы медленный диск деградировал запись, а не
  сессию.
- `Actor::on_record_toggle` (`network.rs` ~стр. 2000) — проверка гранта,
  раздача рекордера в видео- и аудиоцикл, события start/stop.
- IPC-команда `recording_toggle` (`commands.rs`).

## Чего нет

1. UI не вызывает `recording_toggle` **ни разу**.
2. `recording_toggle` **не перечислена ни в одном** `capabilities/*.json` —
   значит даже при наличии кнопки вызов будет отклонён. Проверь сам:
   `grep -rn recording-toggle apps/desktop/src-tauri/capabilities`.
3. Путь файла приходит из webview произвольной строкой (см. задачу 2).
4. `MessageKind::RecordRequest` / `RecordAck` не обрабатываются нигде —
   гость не может попросить запись, только хост может её начать.
5. Экспорта в общеупотребимый контейнер нет: `.lmrec` не откроет ни один
   плеер.

## Задача 1 — Capability и UI

**Файлы:** `capabilities/main.json`, `apps/desktop/src/session-status.ts`,
`i18n.ts`

- Добавить `"allow-recording-toggle"` в `main.json` (**не** в `view.json`:
  запись начинает хост).
- Кнопка «Записывать сессию» рядом с переключателями грантов из `01`,
  активная только когда у сессии есть грант `recording`.
- Пока идёт запись — **видимый несъёмный индикатор** у обеих сторон. Это не
  украшение: «no hidden capture» из `CLAUDE.md` относится и к записи.
- Ключи i18n в `en` и `ar`.

## Задача 2 — Убрать произвольный путь из webview

**Файлы:** `commands.rs`, `network.rs`, `recorder.rs`

Сейчас `recording_toggle` принимает `path: Option<String>` и отдаёт его прямо
в `SessionRecorder::start`. Недоверенный слой представления (§2.3) не должен
выбирать, куда пишется файл.

Делать:
- Каталог назначения определяется на стороне Rust (`config::data_dir()` плюс
  подкаталог `recordings`), имя файла генерируется из времени и метки пира.
- IPC-аргументом остаётся только `on: bool`; путь возвращается наружу для
  показа, а не принимается внутрь.
- Если пользователь должен выбирать каталог — это отдельная настройка через
  нативный диалог со стороны Rust, а не строка из webview.

## Задача 3 — `RecordRequest` / `RecordAck`

**Файл:** `network.rs`, `on_inbound`

- Гость шлёт `RecordRequest`; хост показывает запрос пользователю и отвечает
  `RecordAck(bool)`. Автоматическое согласие запрещено — это отдельный грант
  ровно потому, что решение принимает человек за хостом.
- Ответ `false` — нормальный исход, не ошибка: гость просто показывает отказ.
- Ограничить частоту запросов, чтобы гость не мог задолбить хост диалогами.
  Переиспользовать подход `ConsentRateLimiter` из `crates/core/src/consent.rs`,
  не писать свой счётчик.

## Задача 4 — Экспорт в проигрываемый файл

**Файлы:** `crates/media/src/record.rs` (или новый модуль рядом)

Заголовок модуля прямо говорит: «MKV export as a later, separate step». Это
он и есть.

- Читатель `LMREC` уже написан — использовать его, а не парсить заново.
- Экспорт в MKV/Matroska: H.264 в дорожку видео, Opus в дорожку аудио,
  события — отбросить или в главы, но не в медиапоток.
- Новая зависимость проходит `cargo deny check`. Если подходящей крейт-опции
  нет, допустим экспорт в raw `.h264` + `.opus` как честный минимум — но это
  решение в ADR, а не молча.
- Экспорт **не** должен требовать держать весь файл в памяти: записи потоковые,
  читай и пиши потоково.

## Задача 5 — Тесты

- Round-trip `LMREC`: запись → чтение → те же кадры и таймстемпы.
- Оборванный файл (усечённый на середине записи) читается до места обрыва без
  паники — это заявленный контракт формата, он обязан быть под тестом.
- `on_record_toggle` без гранта `recording` → `CoreError::NotPermitted`.
- Повторный `toggle(true)` для уже пишущейся сессии — идемпотентен.
- Переполнение очереди роняет кадры и увеличивает счётчик, а не блокирует
  цикл кодирования.

## Проверка

```sh
cargo test --workspace && cargo test -p lumepeer-media && cd apps/desktop && npm test && cd -
```

## Ловушки

- `RECORD_FORMAT_VERSION` в заголовке файла: любое изменение раскладки записей
  — это его инкремент **и** сохранение чтения старой версии. Молча поменять
  формат нельзя, уже записанные файлы должны читаться.
- `AuditEvent::RecordingToggled` уже существует в `crates/core/src/audit.rs` —
  использовать его, а не заводить новый вариант.
- Не логировать путь файла записи в аудит: §15 держит пути вне аудита.
