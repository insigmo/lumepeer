# 09 — Курсор: отдельный канал и локальная отрисовка

**Зависимости:** нет.

## Как курсор выглядит сейчас

| Бэкенд | Что с курсором |
|---|---|
| Windows (`capture/windows.rs`) | Композитится в кадр. Есть кэш «чистого» фона без курсора, чтобы движение курсора не оставляло шлейф (~стр. 534–660) |
| Wayland (`capture/linux_wayland.rs`) | `CursorMode::Embedded` — компоузитор вжигает курсор в кадр |
| macOS (`capture/macos.rs`) | `config.setShowsCursor(true)` — то же самое |
| **X11 (`capture/linux_x11.rs`)** | **Курсора нет вообще.** Ни одного упоминания в файле; `XGetImage` курсор не отдаёт, а XFIXES не используется |

`MessageKind::CursorShape { shape: CursorShapeData }` и константа
`MAX_CURSOR_SHAPE_PIXELS = 128 * 128` в протоколе есть, но не обрабатываются
нигде: `grep -rn CursorShape apps crates --include=*.rs` даёт только само
объявление.

## Зачем отдельный канал

Вжатый в кадр курсор двигается со скоростью видеопотока. При 150 мс RTT
указатель отстаёт от руки, и это ощущается как «всё тормозит», даже когда
картинка идёт нормально. Отдельный канал позволяет гостю рисовать курсор
локально сразу по движению мыши — это то, ради чего doc-комментарий у
`CursorShape` и написан.

## Задача 1 — Курсор на X11 (самостоятельная ценность)

**Файл:** `crates/media/src/capture/linux_x11.rs`

X11-хост сейчас отдаёт гостю экран **без курсора вообще** — это отдельный
дефект, не связанный с остальной задачей, и его стоит закрыть первым.

- Через расширение XFIXES получить текущее изображение курсора и его hotspot.
  `x11rb` уже зависимость; включить нужную feature рядом с `xtest`.
- Композитить в кадр так же, как это делает Windows-бэкенд, **включая кэш
  фона без курсора**, иначе на статичном экране останется шлейф. Прочитай
  комментарии в `capture/windows.rs` ~стр. 631–660: там эта ошибка уже описана
  и обойдена, не повторяй её заново.
- Если XFIXES недоступен — кадр без курсора и `tracing::debug`, не отказ
  захвата.

## Задача 2 — Отдача формы курсора хостом

**Файлы:** `crates/media/src/capture/mod.rs`, бэкенды, `network.rs`

- Расширить трейт `ScreenCapturer` методом, отдающим текущую форму курсора,
  когда она **изменилась** (`Option<CursorShapeData>`), плюс позицию отдельно.
  Слать форму каждый кадр нельзя — это заметный трафик.
- Реализовать там, где платформа отдаёт форму отдельно: Windows
  (`GetFramePointerShape` уже используется), X11 (XFIXES из задачи 1).
  Wayland с `CursorMode::Embedded` формы не отдаёт — там честный `None`,
  а не выдуманная заглушка.
- Проверять `width * height <= MAX_CURSOR_SHAPE_PIXELS` **до** аллокации, на
  обеих сторонах.
- Отправлять `CursorShape` только пиру, объявившему соответствующую
  `FEATURE_*`. Правила добавления в протокол — см. `03-file-transfer.md`,
  задача 1.

## Задача 3 — Режим «курсор отдельно» и локальная отрисовка

**Файлы:** бэкенды захвата, `apps/desktop/src/view-window.ts`

- Когда обе стороны поддерживают канал курсора, хост перестаёт вжигать курсор
  в кадр (Windows и X11 это позволяют), а гость рисует его сам поверх canvas
  по последней известной форме и **локальной** позиции указателя.
- Если платформа хоста форму отдать не может (Wayland, macOS) — остаётся
  вжигание. Тогда гость **не** должен рисовать второй курсор поверх: два
  курсора хуже одного отстающего.
- Переключатель «локальный курсор» в тулбаре, по умолчанию включён там, где
  доступен.
- Отрисовка — отдельный слой над canvas, а не рисование в тот же контекст:
  иначе курсор придётся стирать вручную каждый кадр.

## Задача 4 — Тесты и мелкий долг протокола

- Юнит: отклонение формы больше `MAX_CURSOR_SHAPE_PIXELS`; форма с
  `rgba.len() != width * height * 4`; нулевые ширина/высота.
- `protocol_negative.rs`: битые `CursorShape` не роняют разбор.
- jsdom-тест: локальный курсор рисуется по hotspot, а не по левому верхнему
  углу изображения.
- Долг: поле `CursorShapeData.rgba` документировано как «premultiplied
  **BGRA**». Имя и комментарий противоречат друг другу. Определи, что на самом
  деле шлют бэкенды, и приведи в порядок **комментарий** — переименование
  поля меняет постколированную форму и требует разговора о версии протокола.

## Ловушки

- Монохромные курсоры Win32 — это XOR-маска двойной высоты. В
  `capture/windows.rs` ~стр. 940–960 это уже разобрано правильно; при переносе
  логики не потеряй деление высоты пополам.
- Позиция курсора — это данные хоста. Слать её отдельным сообщением каждый
  раз при движении мыши нельзя: гость и так знает, куда он двинул указатель.
  Позиция от хоста нужна только когда курсор двигает **не** гость.
- Захват формы курсора не должен идти без активного зрителя — правило
  «нет зрителя, нет захвата» (§8.1) распространяется и на курсор.
