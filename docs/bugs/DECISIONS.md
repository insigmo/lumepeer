# Принятые решения

Здесь зафиксировано то, что **нельзя было решить в коде**: запрошенное
поведение противоречило принятому решению (ADR, ground rules) или требовало
выбора между вариантами с разной ценой. Решения приняты владельцем продукта.

**Агент не пересматривает эти решения.** Если по ходу работы выяснится, что
решение неисполнимо в выбранном виде — остановиться, дописать в этот файл
раздел «Что выяснилось» и спросить, а не выбирать альтернативу самому.

---

## D1. Баннер «Unattended access is on» — **сделать компактным, не убирать**

**Почему был вопрос.** Корневой `README.md` (Ground rules) и ADR 0033 прямо
требуют баннер, который нельзя убрать: это часть обещания «no hidden
capture».

**Решение.** Баннер остаётся, но переезжает из блока над списком сессий в
одну строку мелким шрифтом в сайдбаре. Ground rule не нарушен, ADR не нужен.

**Где делается:** `05-settings-window.md`, задача 5.

---

## D2. «Запомнить пароль» — **OS keystore**

**Почему был вопрос.** `invite-view.ts` намеренно устроен так, что пароль
живёт только в поле ввода и в одном IPC-вызове (§15).

**Решение.** Галочка «Запомнить пароль», **по умолчанию выключена**. Пароль
уходит в keystore ОС (`crates/net` уже умеет: features `secret-service`,
`keyring`), ключ — стабильная метка хоста. Обратно в webview пароль **не
возвращается никогда**: при следующем подключении к тому же хосту Rust
подставляет его сам.

Долгоживущий токен вместо пароля — правильнее по безопасности, но это
протокольное изменение; оставлено на будущее, в этой итерации не делается.

**Где делается:** `02-connect-form.md`, задача 6. Требует ADR.

---

## D3. Длина инвайт-кода — **не укорачивать, спрятать**

**Почему был вопрос.** ~200 символов — это 64 байта подписи Ed25519 плюс
сериализованный `EndpointAddr` (`crates/net/src/ticket.rs`). Короче — только
убрав подпись (нужен ADR, ослабляет защиту от подмены адреса) или добавив
брокер коротких ссылок (появляется сервер, что противоречит пункту «убрать
P2P, оставить Serverless»).

**Решение.** Формат кода **не трогаем**. В UI — усечённый код с многоточием
плюс кнопка «Copy invite code». Полный код доступен через буфер обмена и
через `title` при наведении.

Константы `SHORT_LINK_*` в `crates/core/src/constants.rs` остаются
неиспользуемыми — это осознанно, удалять их не надо.

**Где делается:** `04-invite-code.md`.

## D4. Видео — **дешёвые правки плюс энкодер, без переделки тракта**

**Почему был вопрос.** Настоящее узкое место — гость гонит полный RGBA-кадр
(8.3 МБ на 1080p) через Tauri IPC в webview.

**Решение.** Делаем этапы A и B:

- **A.** `image-rendering: pixelated` только при масштабе ≥ 1 (при
  уменьшении это ближайший сосед, отсюда «качество знатно хуже»); замер ABR;
  убрать `applyLayout` из горячего пути.
- **B.** Проверить, что релизная Windows-сборка идёт с аппаратным
  `encode-mf` (сейчас его нет в default features); замерить
  `Complexity::Medium` и битрейт.

**Этап C (WebCodecs в webview) не делаем.** Он отменяет ADR 0019 и §11.3 —
декодер в отдельном песочном процессе. Решение может быть пересмотрено
позже, отдельно.

**Где делается:** `07-video-quality.md`.

## D5. Буфер обмена — **автоматически, включая файлы**

**Почему был вопрос.** Хост→гость уже автоматический. Гость→хост по кнопке —
намеренно: у гостя нет своего гранта (ADR 0029), нажатие и есть его согласие.
Файлов в буфере нет вообще: `clipboard_os.rs` — только текст (§9.2 v1).

**Решение.** Обе части делаем, но **двумя отдельными задачами**:

1. **Текст, обе стороны, автоматически.** Кнопка буфера из тулбара убирается.
   Чтение буфера гостя переезжает в Rust (у гостя тоже есть
   `ClipboardWorker`). **Обязательное условие:** видимый индикатор
   синхронизации на обеих сторонах — автоматическая передача буфера без
   индикации это скрытый сбор данных, а «no hidden capture» относится не
   только к экрану. Гранты `clipboard_read`/`clipboard_write` остаются:
   «автоматически» значит «без нажатия», а не «без разрешения».
2. **Файлы через буфер.** Отдельная фича: платформенное чтение списка путей
   (CF_HDROP / `text/uri-list` / `NSPasteboard`), новое протокольное
   сообщение, стыковка с существующим движком передачи файлов (ADR 0032).
   Приём файла остаётся решением человека.

Оба требуют ADR: пункт 1 отменяет объяснение в
`ToolbarCommands.clipboardPush` и часть ADR 0029/0030.

**Где делается:** `10-clipboard-auto.md` и `14-clipboard-files.md`.

## D6. Служба при установке — **Windows-служба из инсталлятора, автозапуск на остальных**

**Почему был вопрос.** ADR 0043: привилегированная служба есть только на
Windows и только ради Ctrl+Alt+Del. На Linux/macOS привилегированного
действия нет.

**Решение.**

- **Windows.** Служба ставится инсталлятором и **снимается
  деинсталлятором**. Сейчас она остаётся в системе после удаления
  приложения — это дефект сам по себе. Ручное управление из настроек
  сохраняется: правило «пользователь всегда может снять службу из
  приложения» не отменяется.
- **Linux/macOS.** Не демон под root, а пользовательский автозапуск через
  уже существующий `autostart.rs` (ADR 0042), включаемый при установке и
  снимаемый при удалении. Второй механизм автозапуска не заводить.

ADR 0043 остаётся в силе — до D8.

**Где делается:** `12-service-lifecycle.md`.

## D7. Выбор разрешения — **разрешение потока сейчас, режим экрана хоста потом**

**Почему был вопрос.** ТЗ допускало два разных механизма.

**Решение.** Обе части, разными задачами и в этом порядке:

1. **Разрешение потока.** Гость выбирает, в каком разрешении получать
   картинку; экран хоста не меняется. Механизм уже есть целиком
   (`QualityTarget.scale_percent`, host-side downscale ADR 0018) — нужно
   протокольное сообщение, IPC-команда и связать с существующим селектом.
   Работает на всех платформах. Список вариантов от железа не зависит,
   «собирать при установке» ничего не надо.
2. **Смена режима экрана хоста.** Позже, отдельно, **только Windows и X11**:
   на Wayland это невозможно в принципе (ADR 0010), и там должен быть
   честный отказ, а не пустой список. Список доступных режимов собирается на
   хосте и отдаётся гостю при подключении, как и просили.

Ключевое ограничение дизайна: ручной выбор задаёт **потолок**, ABR работает
под ним. Две системы не должны драться за одну переменную.

**Где делается:** `13-stream-resolution.md` и `16-host-display-mode.md`.
IPC-баги, из-за которых не работал даже выбор монитора, — `09`.

## D8. Окно UAC — **полный захват защищённого рабочего стола через SYSTEM-службу**

**Почему был вопрос.** Показать secure desktop может только процесс в
session 0 под SYSTEM. Это вторая capability для службы, и она позволяет
видеть ввод пароля администратора. ADR 0043 называется «one privileged
helper with **one** capability».

**Решение.** Делаем, но с обязательными условиями:

- **Новый ADR**, расширяющий или заменяющий ADR 0043, с честным разбором:
  что теперь может видеть привилегированный хелпер и почему это допустимо.
- **Отдельный независимый грант.** Гость с грантом `view` **не получает
  автоматически** право видеть защищённый рабочий стол. Это отдельный грант
  в терминах ground rules, выдаваемый хостом явно, как и остальные.
- Сначала — честная деградация (сообщение вместо замершей картинки плюс
  автовосстановление захвата), она полезна в любом случае и нужна как
  fallback, когда служба не установлена или грант не выдан.

**Где делается:** `11-uac-degradation.md` (деградация) и
`15-secure-desktop-capture.md` (полный захват).

## D9. Что остаётся в главном окне

Подтверждено по умолчанию, возражений не поступило.

**Уезжает в настройки:** адресная книга, постоянный доступ, записи, журнал
аудита, системные настройки, отзыв инвайт-кода.

**Остаётся в главном окне:** форма подключения, список подключений, баннер
записи (§17 — его нельзя прятать), предупреждение об отсутствии захвата или
энкодера (в настройках его никто не увидит), компактная строка unattended
(D1).

Ввод пароля становится модальным окном (`02`), к настройкам отношения не
имеет.
