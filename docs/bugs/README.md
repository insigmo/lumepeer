# Баги и доработки: рабочие документы

Каждый файл здесь — **одна задача одного агента**. Внутри файла задачи идут по
порядку и опираются друг на друга; между файлами зависимости указаны явно.

Документы на русском. Весь код, идентификаторы, комментарии в коде, имена
файлов, сообщения коммитов и ADR — **на английском**, как весь остальной
репозиторий.

Все продуктовые развилки уже закрыты — см. `DECISIONS.md`. Ничего
«ждущего решения» здесь не осталось; агент не пересматривает эти решения.

---

## Как выдавать задачи

Файлы сгруппированы в **пачки**. Пачка — это то, что один агент делает за
один заход: связанные правки в одних и тех же файлах, один общий прогон
проверок, один pull request.

Формулировка для агента — примерно такая:

> Возьми `docs/bugs/README.md`, раздел «Пачка 1». Сделай задачи из файлов
> `01`, `04`, `08` в указанном порядке. Перед началом прочитай
> `docs/bugs/DECISIONS.md` и «Ground rules» в корневом `README.md`. Отчитайся
> по чеклистам Definition of done из каждого файла.

**Пачки идут по порядку.** Внутри пачки — тоже по порядку: файлы правят одни
и те же места, и перестановка создаёт конфликты.

| Пачка | Файлы | Тема | Размер | Почему вместе |
|---|---|---|---|---|
| **1** | `01`, `04`, `08` | Трей, единственный экземпляр, инвайт-код, курсор | S | Три независимых участка, много видимого эффекта, малый риск. Хороший первый заход. |
| **2** | `06`, `09`, `07` | Чат, рассогласование IPC, качество картинки | M | Все трогают окно просмотра и его тулбар. `09` идёт до `07`, потому что чинит контракт, на который `07` опирается. |
| **3** | `02`, `03` | Форма подключения, отмена, keystore, история | M | Оба про `invite-view.ts`, `connect_status` и путь подключения. Требует пачки 1 (показ окна). |
| **4** | `05` | Окно настроек, перенос панелей, компактный баннер | M | Трогает `main.ts` целиком — не совмещать ни с чем. Требует пачек 1 и 3. |
| **5** | `13` | Разрешение потока | M | Новое протокольное сообщение. Требует пачки 2 (контракт IPC починен). |
| **6** | `10` | Буфер обмена: текст, автоматически | M | Требует ADR. |
| **7** | `12` | Служба при установке и удалении | M | Инсталляторы трёх ОС. |
| **8** | `11` | UAC: честная деградация | S | Нужна как fallback для пачки 10. |
| **9** | `14` | Буфер обмена: файлы | L | Большая фича, новый ADR. Требует пачки 6. |
| **10** | `15` | Захват защищённого рабочего стола через SYSTEM-службу | L | Большая фича, новый ADR, новый грант. Требует пачек 7 и 8. |
| **11** | `16` | Смена режима экрана хоста | L | Windows и X11. Требует пачки 5. |

Пачки 1–4 закрывают почти весь список жалоб. Пачки 9–11 — отдельные фичи,
их можно отложить.

### Что можно делать параллельно

Только если очень нужно: **1 и 8** не пересекаются по файлам, и **7** не
пересекается ни с чем из 1–5. Всё остальное — последовательно. Пачки 2, 3, 4
трогают общие файлы фронтенда и в параллель не идут.

## Как желательно, чтобы это делалось

Порядок работы внутри одной задачи:

1. **Прочитать документ целиком до первой правки**, включая разделы «Чего
   делать НЕ нужно» и «Definition of done».
2. **Прочитать код по указанным путям.** Не доверять описанию в этих файлах
   слепо: пути и имена функций надёжны, номера строк — ориентир, они
   дрейфуют.
3. **Воспроизвести баг.** Если корневая причина в документе помечена как
   гипотеза — подтвердить её логом, тестом или отладочной сборкой. Если
   гипотеза не подтвердилась — дописать в документ раздел «Что оказалось на
   самом деле» и только потом чинить.
4. **Сначала падающий тест, потом фикс.** Для каждого бага, который можно
   выразить тестом — а это почти все, кроме чисто визуальных, — порядок
   такой: тест, который падает на текущем коде → фикс → тест зелёный. Тест
   без фикса лучше, чем фикс без теста.
5. **Один коммит на одну задачу из документа.** Не «весь файл одним
   коммитом» и не «коммит на каждую строку». В сообщении коммита — ссылка на
   файл и номер задачи.
6. **Прогнать проверки** (ниже) до отчёта, а не после.
7. **Отчитаться по чеклисту Definition of done**, честно: что сделано, что
   нет и почему.

Чего в работе быть не должно:

- **Правок вне списка «Что сделать».** Каждая изменённая строка должна
  прослеживаться к пункту документа. Не «улучшать» соседний код, не
  переформатировать, не рефакторить то, что не сломано.
- **Молчаливых отклонений от плана.** Если план не работает — остановиться и
  сказать, а не выбрать другой путь самому.
- **Починки попутно найденного.** Нашёл другой дефект — допиши его в конец
  соответствующего файла разделом «Найдено попутно», но не правь.
- **Подгонки числовых констант «на глаз».** Любая новая величина —
  константа в `crates/core/src/constants.rs` с doc-комментарием и ссылкой на
  §. Изменение существующей — только с числом замера.
- **Отчёта «сделано» при красных проверках.**

## Обязательно к прочтению перед любой задачей

1. `docs/bugs/DECISIONS.md` — принятые продуктовые решения.
2. Раздел «Ground rules» в корневом `README.md`. Он важнее любого текста
   здесь.
3. `docs/tasks/README.md`, раздел «Правила, нарушение которых заворачивает
   работу». Всё, что там написано, действует и тут.
4. Профильный ADR из `docs/adr/`, если задача трогает поведение, которое
   выглядит намеренным. Оно почти всегда намеренное.

Ключевые правила, которые нарушают чаще всего:

- **`crates/core` — единственная точка авторизации.** Ни webview, ни
  `apps/desktop/src-tauri`, ни гость не могут расширить грант.
- **Гранты независимы:** `view`, `input`, `clipboard_read`,
  `clipboard_write`, `file_transfer`, `recording`. Никогда не выводить один
  из другого.
- **Новая IPC-команда регистрируется в двух местах:**
  `main.rs::invoke_handler` **и** `apps/desktop/src-tauri/capabilities/`.
  Забыть второе — самая частая ошибка в этом проекте, команда просто не
  вызовется из webview.
- **Любая новая строка в UI требует ключа и в `en`, и в `ar`** в
  `apps/desktop/src/i18n.ts`, иначе `i18n.test.ts` упадёт.
- **Отклонение от спеки — это ADR.** Новый файл `docs/adr/00NN-*.md` по
  образцу соседних. Следующий свободный номер — **0044** (проверено по
  ссылкам в коде, не только по листингу каталога). Если пачка заводит
  несколько ADR — номера идут подряд.

## Проверка перед завершением любой задачи

Сборка webview обязательна до любой cargo-команды, трогающей `apps/desktop`:
`tauri-build` читает `frontendDist` во время компиляции.

```sh
cd apps/desktop && npm install && npm run build && cd -
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Если трогал TypeScript:

```sh
cd apps/desktop && npm run typecheck && npm test && cd -
```

`npm test` включает аудит доступности (axe-core) и проверку полноты i18n.

Если трогал платформенные бэкенды media:

```sh
cargo clippy -p lumepeer-media --all-targets --features capture-x11,encode-openh264 -- -D warnings
cargo clippy -p lumepeer-media --all-targets --features capture-portal -- -D warnings
```
