# 11 — UAC: честное сообщение и восстановление захвата

**Зависимости:** нет. Пачка 8.

Решение принято, см. `DECISIONS.md`, **D8**. Полный захват защищённого
рабочего стола — отдельная задача `15-secure-desktop-capture.md`. Здесь —
уровни 1 и 2, которые нужны в любом случае: они же fallback, когда служба не
установлена или грант не выдан.

**Файлы:**
- `crates/media/src/capture/windows.rs`
- `crates/media/src/error.rs`
- `apps/desktop/src-tauri/src/view.rs`
- `apps/desktop/src/view-window.ts`, `apps/desktop/src/i18n.ts`
- `crates/core/src/constants.rs`

## Симптом со слов пользователя

«когда открывается окно администратора, через люмпир не видно это окно, оно
просто зависает и ничего не происходит»

## Корневая причина — подтверждена

Windows показывает запрос UAC на **защищённом рабочем столе**
(`Winsta0\Winlogon`). Обычный процесс в пользовательской сессии его не видит
— в этом и есть смысл защищённого рабочего стола.

В коде это обработано, но только как ошибка.

`crates/media/src/capture/windows.rs`, `map_start_error`:

```
E_ACCESSDENIED → "the secure desktop (lock screen, UAC prompt or fast user
switch) is in the foreground"
```

`map_runtime_error`:

```
DXGI_ERROR_ACCESS_LOST | E_ACCESSDENIED →
"the desktop changed: a screen lock, a UAC prompt, a user switch or a mode
change" → MediaError::CaptureInterrupted
```

То есть при появлении UAC текущая дупликация экрана теряется и захват
останавливается. Комментарий над `map_runtime_error` объясняет, что
`CaptureInterrupted` — это сигнал «отзывать, а не повторять».

Для гостя это выглядит как «картинка замерла и ничего не происходит»: новых
кадров нет, окно просмотра показывает последний, никакого сообщения не
приходит. **Пользователь прав в главном: происходящее непонятно.**

## Что сделать

### Задача 1 — Гость узнаёт, что происходит

1. В `crates/media/src/capture/windows.rs` различать «захват прерван
   защищённым рабочим столом» и «захват прерван по другой причине». Сейчас
   обе ветки дают `CaptureInterrupted` с разным **текстом**, а текст для
   классификации не годится. Нужен отдельный вариант в `MediaError`
   (`crates/media/src/error.rs`), а не разбор строки.
2. Дальше по цепочке: `apps/desktop/src-tauri/src/view.rs` уже отдаёт статус
   в первом байте ответа `view_next_frame`. Статусы перечислены в
   `view-window.ts::STATUS_BY_CODE`:
   `waiting | live | reconnecting | failed | no-capture | no-encoder`.
   Добавить седьмой — `secure-desktop`.
   **Порядок в массиве менять нельзя**, только дописывать в конец: индекс —
   это байт протокола.
3. Проверить, не подходит ли уже существующее протокольное сообщение
   `MediaUnavailable` (ADR 0024). Если подходит — использовать его, новый
   статус не заводить.
4. В `viewOverlay` (`view-window.ts`) — текст для нового статуса: «На
   удалённой машине открыт запрос администратора. Ответьте на него на самой
   машине или подождите». Ключи в `en` и `ar`.

→ **Проверка:** вручную на Windows: гость подключён, хост запускает что-то с
UAC. В окне гостя появляется понятное сообщение, а не замершая картинка.

### Задача 2 — Захват восстанавливается сам

`DXGI_ERROR_ACCESS_LOST` — штатная ситуация: она возникает при UAC, при
блокировке экрана, при смене режима монитора, при переключении пользователя.
Правильная реакция для первых трёх — **пересоздать дупликацию**, а не
отзывать сессию.

1. В `WindowsCapturer` добавить путь восстановления: при
   `ACCESS_LOST`/`E_ACCESSDENIED` во время работы закрыть текущую дупликацию
   и пробовать открыть заново с backoff.
2. Backoff и максимальное число попыток — константы в
   `crates/core/src/constants.rs` с doc-комментарием. Не литералы.
3. Пока восстановление идёт — держать статус из задачи 1, а не `failed`.
4. Если восстановиться не удалось за отведённое число попыток — тогда уже
   `CaptureInterrupted` и текущее поведение.
5. Это меняет контракт: комментарий над `map_runtime_error` говорит, что
   вызывающий должен отзывать, а не повторять. Найти, кто ловит
   `CaptureInterrupted` (`apps/desktop/src-tauri/src/view.rs`), и сделать
   так, чтобы отзыв случался только после исчерпания попыток. Комментарий
   поправить в том же коммите.

→ **Проверка:** вручную: ответить на UAC (или заблокировать и разблокировать
экран) — картинка возвращается сама, без переподключения. Юнит-тест на логику
backoff; сам DXGI headless не тестируется.

### Задача 3 — Подготовить точку расширения для `15`

Задача `15` заменит «показать сообщение» на «показать защищённый рабочий
стол», когда служба установлена и грант выдан. Чтобы это не потребовало
переписывать всё заново:

- признак «сейчас активен secure desktop» должен быть **одним значением в
  одном месте**, а не тремя проверками в разных функциях;
- решение «что делать при secure desktop» должно приниматься там, где видно
  и состояние службы, и гранты сессии, — то есть в акторе, а не внутри
  бэкенда захвата.

Никакого кода для `15` здесь писать не надо. Только не закладывать структуру,
которую придётся ломать.

→ **Проверка:** в `15` эта ветка расширяется, а не переписывается.

## Чего делать НЕ нужно

- **Не запускать всё приложение с повышенными правами** «чтобы UAC был
  виден». Это не поможет — secure desktop это не про elevation — и ADR 0043
  прямо называет это плохой сделкой.
- **Не отключать UAC на машине хоста** ни программно, ни в инструкции.
- **Не менять порядок в `STATUS_BY_CODE`** — это байт протокола.
- **Не превращать восстановление в бесконечный цикл.** Ограничение числа
  попыток обязательно, иначе хост с отключённым монитором будет крутить
  дупликацию вечно.
- **Не начинать работу над SYSTEM-службой здесь.** Это `15`.
- Не трогать macOS и Linux бэкенды: там нет secure desktop, и у них свои
  ограничения (Wayland — ADR 0010).

## Definition of done

- [ ] Гость видит понятное сообщение вместо замершей картинки.
- [ ] Захват восстанавливается сам после UAC и после блокировки экрана.
- [ ] Классификация идёт по варианту `MediaError`, а не по тексту.
- [ ] Backoff и лимит попыток — константы с обоснованием.
- [ ] Порядок статусов в протоколе не изменён, только дополнен.
- [ ] Новые строки есть в `en` и `ar`.
- [ ] Устаревший комментарий над `map_runtime_error` поправлен.
- [ ] Проверено вручную на Windows.
- [ ] Все проверки из `docs/bugs/README.md` пройдены.
