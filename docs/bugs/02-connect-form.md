## Симптомы со слов пользователя

1. «кнопка Connect меняется в длине, когда добавляет точки. Сделай достаточной
   длины эту кнопку, чтобы она не менялась в длине. Хотелось бы чтобы внизу
   появилась надпись которая также меняется, а вместо кнопки коннект после
   нажатия появился бы Cancel, который отменяет процесс подключения»
2. «Когда подключаешься по паролю, если ввел неправильно, то правишь пароль и
   нажимаешь интер, то не пускает больше»
3. «При вводе пароля нет кнопки запомнить пароль. Стоит добавить»
4. «когда подключаешься к другому клиенту, появляется поле куда ввести
   пароль, а нужно окно где можно вводить пароль»

## Корневые причины

### 1. Кнопка «дышит» — подтверждено

`connectPanel` в `invite-view.ts` рисует подпись кнопки как
`${t(locale,'invite.connecting')}${'.'.repeat(connectingDots)}` — от одной до
трёх точек, раз в 400 мс. У `.connect-btn` в `app.css` нет ни `min-width`, ни
фиксированной ширины, поэтому кнопка меняет размер четыре раза в секунду.

### 2. После неверного пароля Enter больше не работает — **подтверждено,
это главный баг файла**

В `invite-view.ts` есть флаг `submitting`. Он ставится в `true` в
`submitCredentials` и сбрасывается **только здесь**, в `setConnectPhase`:

```ts
if (submitting && next !== 'awaiting_credentials') {
    submitting = false;
}
```

А при неверном пароле хост оставляет гостя ровно в фазе
`awaiting_credentials` — просто с кодом ошибки `UNATTENDED_BAD_PASSWORD`.
Значит `next === 'awaiting_credentials'`, значит `submitting` навсегда
остаётся `true`, значит кнопка `.credentials-submit` навсегда `disabled`.

А раз единственная submit-кнопка формы отключена, браузер **не выполняет
implicit submission** — Enter в поле ввода перестаёт что-либо делать. Ровно
тот симптом, что описал пользователь: пароль правится, Enter не работает.

Условие сброса должно быть не «фаза сменилась», а «пришёл ответ на нашу
отправку». Признак ответа — появление или смена `credentialCode` (в
`setConnectPhase` он и так вычисляется), либо смена фазы.

### 3. Пароль вводится в панели, а не в окне — подтверждено

`main.ts::renderNow` вставляет `credentialsPanel(locale)` **в поток главной
панели**, между баннерами и формой подключения:

```
${isAwaitingCredentials() ? credentialsPanel(locale) : ''} ${connectPanel(locale)}
```

То есть это обычный блок в вёрстке, который легко проскроллить мимо. Для
сравнения, `consentDialog` в том же файле рендерится **вторым корневым
элементом** и имеет `.consent-backdrop` + `role="dialog"` +
`aria-modal="true"` — вот шаблон, по которому надо сделать и этот.

### 4. Отмены подключения нет — подтверждено

Ни в `invite-view.ts`, ни в списке команд `main.rs::invoke_handler`, ни в
`capabilities/main.json` нет ничего вроде `connect_cancel`. Пока идёт
`dialing` / `awaiting_consent` / `awaiting_credentials`, у пользователя нет
способа прекратить попытку — только ждать таймаута.

На стороне Rust отменять есть что: `spawn_dial` в `network.rs` запускает
`tokio::spawn` с `dial_with_retries`, и результат приходит событием
`ActorEvent::Dialed`. `on_dialed` уже умеет отбрасывать устаревший результат
по условию `if self.connect_peer != Some(peer)`. Это и есть готовая точка для
отмены.

## Что сделать

### Задача 1 — Кнопка не меняет ширину

В `app.css`, `.connect-btn`: задать `min-width` в `ch`, рассчитанный на
самую длинную подпись из всех локалей (`invite.connect`, `invite.connecting`
плюс три точки, `invite.cancel` из задачи 3), плюс `text-align: center`.

Проще и надёжнее: убрать анимацию точек из подписи кнопки совсем (см.
задачу 2) — тогда подпись меняется только между «Connect» и «Cancel», и
`min-width` считается по двум коротким словам.

→ **Проверка:** jsdom-тест в `invite-view.test.ts`: подпись кнопки при
`isConnecting() === true` не содержит точек. Визуально — кнопка не дёргается.

### Задача 2 — Статус под формой вместо точек в кнопке

Перенести «Connecting…» из подписи кнопки в отдельную строку под формой,
рядом с тем местом, где уже рендерится `.connect-error`.

- Новый элемент `.connect-status` с `role="status"` и
  `aria-live="polite"` — это прогресс, а не ошибка, `role="alert"` тут
  неуместен.
- Текст зависит от фазы, а не от одного слова:
  `dialing` → «Подключаемся…», `awaiting_consent` → «Ждём ответа другой
  стороны…», `awaiting_credentials` → «Устройство просит пароль».
  Три новых ключа i18n, **в `en` и в `ar`**.
- Анимацию точек (`connectingDots`, `connectingTimer`,
  `syncConnectingAnimation`, `CONNECTING_DOT_INTERVAL_MS`,
  `CONNECTING_DOT_MAX`) можно оставить, но применять к этой строке. Если
  выбрана CSS-анимация — таймер и все пять символов удалить целиком, а не
  оставлять мёртвыми.

→ **Проверка:** jsdom-тест: при фазе `awaiting_consent` в документе есть
элемент с `data-testid="connect-status"` и текстом про ожидание ответа.

### Задача 3 — Кнопка Cancel

**Rust:**

1. Новая команда `connect_cancel` в `commands.rs` рядом с `connect_status`.
   Без аргументов: отменяемая попытка всегда одна.
2. Новый вариант в enum команд актора и обработчик в `network.rs`. Он должен:
   - сбросить `connect_peer` в `None` (тогда `on_dialed` сам выбросит
     результат уже летящего дозвона — механизм готов);
   - перевести `connect_phase` в `ConnectPhase::Idle`, не в `Failed`:
     отмена пользователем — не ошибка и не должна показывать красный текст;
   - очистить `connect_failure`, `connect_code_required`,
     `connect_retry_secs`;
   - если соединение уже установлено и ждёт согласия — закрыть его. Здесь
     **не** использовать `close_connection`: он закрывает кодом
     `CLOSE_MALFORMED`, а это штатный выход (см. `03`, задача 3). Закрыть
     штатным кодом.
3. Зарегистрировать команду в `main.rs::invoke_handler` **и** добавить
   `"allow-connect-cancel"` в `capabilities/main.json`. Без второго команда
   из webview не вызовется вообще.

**TypeScript:**

4. В `connectPanel`: при `isConnecting()` вместо отключённой кнопки
   `Connect` рисовать активную кнопку `Cancel` (`type="button"`, не submit),
   которая вызывает `connect_cancel`.
5. Локальное состояние (`dialing`, `phase`, `connectError`) сбросить сразу
   после успешного вызова, не дожидаясь следующего опроса, — иначе кнопка на
   секунду останется «Cancel».
6. Ключ i18n `invite.cancel` в `en` и `ar`.

→ **Проверка:** jsdom-тест: во время подключения кнопка не `disabled`, имеет
подпись отмены, клик вызывает `connect_cancel`. Вручную: подключиться к
недоступному хосту, нажать Cancel — форма немедленно возвращается в исходное
состояние, красной ошибки нет.

### Задача 4 — Enter после неверного пароля (**самое важное**)

В `invite-view.ts::setConnectPhase` заменить условие сброса `submitting`.
Сбрасывать, если выполнено **любое** из:

- фаза сменилась на что угодно, кроме `awaiting_credentials`;
- фаза осталась `awaiting_credentials`, но `code` (то есть новый
  `credentialCode`) не пустой — хост ответил отказом.

Проще всего это выразить так: `submitting` сбрасывается всегда, когда
`setConnectPhase` вызван с непустым `code` **или** со сменой фазы.

Дополнительно: после отказа поле пароля должно получить фокус, а не просто
разблокироваться. Это делается в `credentialsPanel` через директиву lit-html
или в колбэке после рендера — не через `autofocus`, потому что панель
перерисовывается каждую секунду и `autofocus` сработает один раз.

**Обязательный порядок работы:** сначала написать jsdom-тест, который падает
на текущем коде.

```
1. setConnectPhase('awaiting_credentials')
2. submit формы с паролем
3. setConnectPhase('awaiting_credentials', 'UNATTENDED_BAD_PASSWORD')
4. ожидаем: кнопка submit НЕ disabled
5. второй submit доходит до unattended_submit
```

Шаг 4 на текущем коде падает. Только после этого чинить.

→ **Проверка:** тест выше зелёный. Вручную: ввести неверный пароль, потом
верный, нажать Enter — подключение проходит.

### Задача 5 — Пароль в модальном окне

Переделать `credentialsPanel` по образцу `consent-dialog.ts`:

- обёртка `.credentials-backdrop` (стили копируются с `.consent-backdrop`,
  не изобретаются заново);
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок;
- фокус при открытии — на поле пароля;
- Escape закрывает и отменяет попытку — вызывает ту же `connect_cancel` из
  задачи 3;
- в `main.ts::renderNow` панель уезжает из потока главной панели во второй
  корневой элемент `render([...])`, рядом с `consentDialog`.

Плюс: когда фаза становится `awaiting_credentials`, окно приложения гостя
должно выйти на передний план — тем же механизмом, что в `01`, задача 4, но
по событию на стороне гостя. Если в `ActorNotification` подходящего варианта
нет — добавить его (`UnattendedChallenge` или аналогичный), **без
идентичности пира внутри**.

→ **Проверка:** axe-core-тест (`accessibility.test.ts`) не ругается на новый
диалог. jsdom-тест: Escape вызывает `connect_cancel`. Вручную: гость свернул
окно, хост просит пароль — окно гостя всплывает с модальным диалогом.

### Задача 6 — «Запомнить пароль» (решение **D2**)

Пароль хранится в keystore ОС и **никогда не возвращается в webview**.

**TypeScript:**
1. В `credentialsPanel` — чекбокс «Запомнить пароль для этого устройства»,
   `checked` по умолчанию **false**. Ключ i18n в `en` и `ar`.
2. Значение чекбокса уходит третьим полем в `unattended_submit`:
   `{ args: { password, code, remember } }`. Поле в snake_case, если имя
   составное.

**Rust:**
3. `UnattendedSubmitArgs` в `commands.rs` получает поле `remember: bool`.
4. В `network.rs`, в обработчике отправки учётных данных: если `remember` и
   попытка **удалась**, положить пароль в keystore под ключом, производным от
   стабильной метки хоста (той же, что использует `ConnectionHistory` —
   `host_tag`). При неудаче не сохранять ничего.
5. Хранилище — то, что уже есть в `crates/net` (features `secret-service`,
   `keyring`). Посмотреть, как это делает `unattended_store.rs` на стороне
   хоста, и переиспользовать тот же слой, а не заводить второй.
6. При подключении к хосту, для которого пароль сохранён, и приходе
   `UnattendedChallenge` — подставить сохранённый пароль автоматически, **не
   показывая модальное окно**. Если хост его отверг — стереть запись из
   keystore и показать окно обычным порядком. Молча повторять с тем же
   паролем нельзя: это съест лимит попыток и приведёт к блокировке.
7. Второй фактор (одноразовый код) **не сохранять никогда**, даже когда
   `remember` включён. В этом весь смысл второго фактора.
8. Забыть сохранённый пароль можно: кнопка в настройках, рядом с адресной
   книгой. Хранилище, из которого нельзя удалить, — это дефект.

**Обязательно:** ADR. Решение отменяет объяснение в комментарии к
`credentialsPanel` («nothing in this module keeps a copy») — комментарий
поправить в том же коммите: копии в модуле по-прежнему нет, копия в keystore
есть, и это разные утверждения.

→ **Проверка:** unit-тест на слой хранения (сохранить, прочитать, стереть).
Вручную: подключиться с галочкой, отключиться, подключиться снова — окно
пароля не появляется. Сменить пароль на хосте — окно появляется снова, старая
запись стёрта.

## Чего делать НЕ нужно

- **Не хранить пароль в модуле `invite-view.ts` ни в каком виде** — ни для
  повторной отправки, ни для «а вдруг понадобится». Комментарий к
  `credentialsPanel` объясняет, почему; он не устарел.
- **Не показывать, какой из факторов не подошёл**, кроме тех четырёх кодов,
  что уже есть в `CREDENTIAL_ERROR_TEXT`. Словарь отказов — это модель
  безопасности, а не текст.
- **Не превращать отмену в ошибку.** `ConnectPhase::Failed` после Cancel —
  дефект.
- **Не трогать `dial_with_retries`** и логику ретраев в `crates/net`. Отмена
  делается на уровне актора, отбрасыванием результата.
- **Не добавлять команду в `invoke_handler`, забыв про `capabilities`** —
  это самая частая ошибка в этом проекте, команда просто не вызовется.
- Не переносить сюда работу из `04` (инвайт-код) и `05` (окно настроек),
  даже если правишь соседние строки в тех же файлах.

## Definition of done

- [ ] Кнопка Connect не меняет ширину.
- [ ] Под формой есть строка состояния, разная для трёх фаз ожидания.
- [ ] Во время подключения кнопка превращается в работающий Cancel; отмена
      возвращает форму в исходное состояние и не показывает ошибку.
- [ ] После неверного пароля можно исправить его и нажать Enter — есть
      падавший до фикса тест.
- [ ] Пароль вводится в модальном окне, окно всплывает поверх, Escape
      отменяет попытку.
- [ ] Галочка «Запомнить пароль» выключена по умолчанию; пароль хранится в
      keystore, в webview не возвращается, второй фактор не сохраняется.
- [ ] Сохранённый пароль можно стереть из настроек.
- [ ] Отклонение оформлено ADR.
- [ ] Новые строки есть и в `en`, и в `ar`; `i18n.test.ts` зелёный.
- [ ] Команда `connect_cancel` зарегистрирована и в `invoke_handler`, и в
      `capabilities/main.json`.
- [ ] Все проверки из `docs/bugs/README.md` пройдены.
