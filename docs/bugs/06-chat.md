# 06 — Чат: нельзя писать, нельзя скрыть, открыт по умолчанию

**Зависимости:** нет. **Пачка 2**, первым в пачке.

Трогает `apps/desktop/view.html` — как `07` и `08`. Внутри пачки это
безопасно (файлы правятся по очереди), но параллельно с пачкой 1, где идёт
`08`, эту работу вести нельзя.

**Файлы:**
- `apps/desktop/view.html`
- `apps/desktop/src/view.ts`
- `apps/desktop/src/view-window.ts`
- `apps/desktop/src/view-hotkeys.ts`
- `apps/desktop/src/toolbar.ts`
- `apps/desktop/src/view-window.test.ts`, `apps/desktop/src/chat.test.ts`

## Симптомы со слов пользователя

1. «в чат нельзя ничего написать, просто есть»
2. «Чат нельзя скрыть. Нажимаю на иконку чата плашки внутри окна и ничего не
   происходит»
3. «по умолчанию чат должен быть скрыт»

Все три — в окне просмотра (`view-*`), не в главном окне.

## Корневые причины

### 1. Нельзя писать — **подтверждено чтением кода**

`ViewInput` в `apps/desktop/src/view-window.ts` вешает обработчики клавиатуры
**на `document`**, а не на канвас:

```ts
this.keyboard.addEventListener('keydown', this.onKeyDown as EventListener);
```

(`keyboard` по умолчанию — `surface.ownerDocument`, и `view.ts` передаёт туда
именно `document`.)

А `forwardKey` для каждой узнанной клавиши делает:

```ts
event.preventDefault();
this.sink.press(logical, 0, modifiersOf(event), pressed);
```

Значит любое нажатие, включая набор в поле чата, перехватывается,
отменяется и уходит **на удалённую машину**. Поле чата не получает ни одного
символа.

Комментарий в `chat.ts` утверждает обратное — «typing into the panel never
reaches the host, because focus sits in the panel's input, not on the canvas
surface». Он неверен: слушатель висит на документе, фокус ни на что не
влияет. Комментарий надо исправить вместе с кодом.

То же касается `installHotkeys` (`view-hotkeys.ts`) — он тоже слушает
`document` в фазе capture, и его чорды тоже сработают при наборе текста.

### 2. Чат не скрывается — **подтверждено, причина в CSS**

`view.html` объявляет:

```css
#chat-panel {
  position: absolute;
  ...
  display: flex;
  ...
}
```

Специфичность селектора `#chat-panel` — (1,0,0). Правило браузера по
умолчанию для атрибута `hidden` — `[hidden] { display: none }`, специфичность
(0,1,0). **Правило страницы выигрывает**, поэтому `chatPanel.hidden = true`
не скрывает ничего: панель остаётся `display: flex`.

Кнопка чата в тулбаре при этом честно вызывает `hooks.toggleChat()`, и тот
честно переключает `hidden` — просто это ни на что не влияет.

Доказательство, что проблема известна и уже решалась в этом же файле: для
курсора там же явно написано

```css
#cursor[hidden] { display: none; }
```

Для `#chat-panel` такого правила забыли.

Второстепенно: `toggleChat` не перерисовывает тулбар, поэтому состояние
`is-active` и `aria-pressed` на кнопке чата не обновляется даже когда панель
всё-таки скроется.

### 3. Чат открыт по умолчанию — подтверждено

`view.ts::main()`:

```ts
if (chatPanel) {
  chatPanel.hidden = false;
  startChatPolling(...);
}
```

Панель принудительно показывается при старте окна.

## Что сделать

### Задача 1 — Не перехватывать клавиатуру, когда фокус в поле ввода

В `view-window.ts`, в `ViewInput.forwardKey`, **до** `preventDefault()`,
добавить проверку: если цель события — редактируемый элемент, ничего не
пересылать и ничего не отменять.

Редактируемым считать: `<input>`, `<textarea>`, `<select>`, элемент с
`isContentEditable`. Проверять надо `event.target`, а не `document.activeElement`.

Оформить это отдельной экспортируемой чистой функцией — например
`export function isLocalTextTarget(target: EventTarget | null): boolean` — и
покрыть её unit-тестами. Она понадобится дважды.

Ту же проверку добавить в `installHotkeys` (`view-hotkeys.ts`): чорды окна
не должны срабатывать во время набора текста. Именно поэтому функция общая,
а не два инлайн-условия.

**Порядок работы:** сначала jsdom-тест, который падает.

```
1. смонтировать ViewInput с фейковым sink, setEnabled(true)
2. создать <input>, задиспатчить на нём keydown 'a'
3. ожидать: sink.press НЕ вызван, event.defaultPrevented === false
4. задиспатчить keydown 'a' на body
5. ожидать: sink.press вызван
```

Шаг 3 на текущем коде падает.

Заодно исправить неверный комментарий в `chat.ts` над `renderChat` — он
объясняет несуществующий механизм.

→ **Проверка:** тест выше зелёный. Вручную: открыть чат в окне просмотра,
набрать текст, нажать Enter — сообщение ушло, на удалённой машине ничего не
напечаталось.

### Задача 2 — Чат действительно скрывается

В `view.html`, в `<style>`, добавить рядом с существующим правилом для
курсора:

```css
#chat-panel[hidden] { display: none; }
```

В `view.ts`, в хуке `toggleChat`, после переключения `hidden` вызвать
`toolbar?.redraw()` — иначе `aria-pressed` и подсветка кнопки врут. То же в
обработчике горячей клавиши `toggle-chat` (там `redraw` уже есть — проверить,
что вызывается в обоих местах).

→ **Проверка:** jsdom-тест в `view-window.test.ts` или новом файле: после
`hidden = true` вычисленный `display` панели — `none`. Вручную: кнопка чата
показывает и прячет панель, состояние кнопки меняется.

### Задача 3 — Чат скрыт по умолчанию

В `view.ts::main()` заменить `chatPanel.hidden = false` на
`chatPanel.hidden = true`.

Опрос транскрипта (`startChatPolling`) при этом **оставить запущенным**: он
дешёвый (раз в секунду) и нужен, чтобы при открытии панели история была уже
там, а не появлялась через секунду.

Подумать про индикацию нового сообщения: если панель скрыта и в транскрипте
появилось входящее сообщение, кнопка чата в тулбаре должна это показать
(точка на иконке или `is-active`). Это не обязательное требование ТЗ, но без
него скрытый по умолчанию чат означает, что сообщения хоста гость просто не
увидит. **Сделать минимальный вариант**: булев флаг «есть непрочитанные»,
сбрасываемый при открытии панели; никаких счётчиков и звуков.

→ **Проверка:** jsdom-тест: при монтировании окна панель скрыта; после
входящего сообщения кнопка чата помечена; после открытия панели пометка
снята.

## Чего делать НЕ нужно

- **Не отключать `ViewInput` целиком, когда открыт чат.** Клавиатура должна
  продолжать работать, когда фокус на картинке, — окно просмотра для этого и
  существует. Условие — фокус, а не факт открытой панели.
- **Не менять `chat.ts`, кроме комментария.** Компонент чата рабочий: и
  `renderChat`, и `startChatPolling`, и IPC-обёртки. Баг не в нём.
- **Не менять `hidden` на класс** (`.is-hidden`). `hidden` — правильный
  атрибут, у него есть семантика для скринридеров. Чинится CSS, а не разметка.
- **Не переносить сюда host-side чат** (`#host-chat-panel` в
  `apps/desktop/index.html`). У него в `app.css` правило
  `.host-chat-panel[hidden] { display: none }` уже есть, и он работает.
- **Не добавлять звуки, всплывающие уведомления и счётчики сообщений.**
- Не трогать `POINTER_BUTTON_PAN`, `installPan` и логику панорамирования.
