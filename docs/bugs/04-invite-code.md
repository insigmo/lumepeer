# 04 — Инвайт-код: кнопки и то, что видно на экране

**Зависимости:** нет. **Пачка 1**.

Трогает `apps/desktop/src/invite-view.ts` — как `02` (пачка 3) и `05`
(пачка 4). Параллельно с ними эту работу вести нельзя.

**Пачка 1.** Решение принято, см. `DECISIONS.md`, **D3**: формат кода не
трогаем, укорачиваем только то, что видно на экране.

**Файлы:**
- `apps/desktop/src/invite-view.ts`
- `apps/desktop/src/i18n.ts`
- `apps/desktop/src/app.css`
- `apps/desktop/src/invite-view.test.ts`

## Симптомы со слов пользователя

1. «убрать рефреш код, так как он не актуален»
2. «Убрать кнопку инвайт код и вместо нее создать кнопку `Copy invite code`,
   который копирует инвайт код»
3. «Постараться сделать короче инвайт код»

## Что сейчас в коде

`inviteCodePanel` в `invite-view.ts` рисует, сверху вниз:

| Элемент | Класс | Что делает |
|---|---|---|
| подпись «Your invite code» | `.field-label` | — |
| сам код как кнопка | `.code-box` | клик копирует код |
| кнопка «Copy code» с иконкой | `.copy-btn` | клик копирует код |
| кнопка «Refresh invite» | `.create-btn` | вызывает `invite_create` заново |

То есть **две кнопки делают одно и то же** (`copyCode`), и это то, на что
жалуется пользователь: кнопка с кодом лишняя.

### Про «Refresh invite»

Кнопка вызывает `createInvite()` → IPC `invite_create`. На стороне хоста
выдача нового инвайта вызывает `TicketRegistry::retire_all()`
(`crates/net/src/ticket.rs`), то есть **гасит все ранее выданные коды**. Это
записано в ADR 0016 как способ для хоста отозвать выданный код.

Значит убирать кнопку нельзя молча: вместе с ней исчезает единственный
способ отозвать инвайт. Функцию надо **перенести в окно настроек** (задача
`05`) под честным названием «Отозвать код и выдать новый», а не удалять.

### Про длину кода

`InviteTicket::to_code` — это base32 без паддинга от postcard-сериализации
структуры, где 64 байта занимает подпись Ed25519 и ещё десятки байт —
сериализованный `EndpointAddr`. Итог — порядка 200 символов. Разбор вариантов
и принятое решение — в `DECISIONS.md`, D3.

## Что сделать

### Задача 1 — Убрать вторую кнопку копирования

Из `inviteCodePanel` убрать кликабельность у `.code-box`: код превращается из
`<button>` в обычный элемент. Копирование остаётся только на `.copy-btn`.

- `.code-box` должен остаться **выделяемым мышью** (`user-select: text`) —
  это единственный запасной путь, если буфер обмена недоступен, о чём прямо
  сказано в комментарии к `copyCode`.
- `aria-label` и `title` со всего кода перенести на `.copy-btn`.
- Подпись кнопки — `Copy invite code`, не `Copy code`. Ключ
  `sidebar.copyCode` уже есть, поменять его текст в `en` и в `ar`.
- Состояние «скопировано» (`copied`, `COPIED_FEEDBACK_MS`) сохранить как
  есть — это хорошая обратная связь.

→ **Проверка:** jsdom-тест: в панели ровно одна кнопка, копирующая код;
элемент с кодом не является кнопкой; `navigator.clipboard.writeText` вызван
с полным кодом.

### Задача 2 — Убрать «Refresh invite» из сайдбара

Удалить третью кнопку из `inviteCodePanel`. Функцию `createInvite` **не
удалять** — она нужна и для первой выдачи кода, и для задачи `05`.

Ключ `invite.refresh` пока оставить в `i18n.ts`: он понадобится в окне
настроек. Если задача `05` ещё не сделана — оставить ключ с комментарием
`// used by the settings window (docs/bugs/05)`, чтобы линтер неиспользуемых
ключей (если он есть) не снёс его.

→ **Проверка:** в сайдбаре нет кнопки обновления кода; `i18n.test.ts`
зелёный.

### Задача 3 — Код в сайдбаре не занимает пол-экрана

Даже без укорачивания самого кода его не надо показывать целиком:

- `.code-box` в `app.css`: одна строка, `overflow: hidden`,
  `text-overflow: ellipsis`, `white-space: nowrap`, моноширинный шрифт.
- `title` элемента — полный код (уже есть, сохранить), чтобы он был виден по
  наведению.
- Полный код по-прежнему уходит в буфер обмена целиком — усечение только
  визуальное.

→ **Проверка:** визуально — сайдбар не растягивается кодом. jsdom-тест:
`title` содержит полный код, даже когда текст усечён CSS.

### Задача 4 — Формат кода не трогаем (решение **D3**)

Укорачивать сам код **не надо**. Оба способа это сделать имеют цену, которую
решено не платить: брокер коротких ссылок добавляет сервер (противоречит
пункту «убрать P2P, оставить Serverless»), снятие подписи Ed25519 ослабляет
защиту от подмены адреса узла.

Задачи 1–3 закрывают ощущаемую проблему: на экране код больше не занимает
пол-сайдбара, а полный код доступен копированием.

`crates/net/src/ticket.rs` в этой задаче **не трогаем вообще**. Константы
`SHORT_LINK_*` в `crates/core/src/constants.rs` остаются неиспользуемыми —
это осознанно, удалять их не надо.

## Чего делать НЕ нужно

- **Не удалять `createInvite`, `creatingInvite` и `invite.refresh`.**
  Отзыв инвайта — функция безопасности, она переезжает, а не исчезает.
- **Не трогать `crates/net/src/ticket.rs`.** Формат кода решено не менять
  (D3), и никакая задача из этого файла его не касается.
- **Не превращать `.code-box` в `<input readonly>`** ради выделения: это
  добавит его в tab-порядок как поле ввода, чего он не является. Достаточно
  `user-select: text`.
- **Не убирать `title` с полным кодом** ради «чистоты» — это единственный
  способ прочитать код глазами.
- Не переносить сюда работу по окну настроек: тут только сайдбар.
