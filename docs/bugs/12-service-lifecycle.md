# 12 — Служба при установке и удалении

**Зависимости:** нет. Пачка 7.

Решение принято, см. `DECISIONS.md`, **D6**: на Windows — служба из
инсталлятора, на Linux и macOS — пользовательский автозапуск, без root.

**Файлы:**
- `apps/desktop/src-tauri/tauri.conf.json` (секция `bundle`)
- `crates/service/src/install.rs`, `crates/service/src/windows_service.rs`
- `apps/desktop/src-tauri/src/service_control.rs`
- `apps/desktop/src-tauri/src/autostart.rs`
- `install.ps1`, `install.sh`
- скрипты инсталляторов (NSIS, deb `postinst`/`prerm`, rpm `%post`/`%preun`)

## Симптом со слов пользователя

«при установке люмпира создается служба на винде, сервисы на линуксе и макос,
автоматом. А при удалении люмпира, они тоже подчищаются»

Формулировка описывает желаемое. Сейчас так не работает.

## Что есть сейчас

### Windows

Привилегированная служба существует: `crates/service`, установка и удаление —
`crates/service/src/install.rs`, обёртка для UI —
`apps/desktop/src-tauri/src/service_control.rs`.

Ставится **вручную**, из панели настроек: `service_set(enabled: true)` →
`windows_impl::elevate("--install")` → один запрос UAC. Снимается тем же
способом.

Смысл службы ровно один — доставка Ctrl+Alt+Del (ADR 0043).

Инсталлятор (NSIS/WiX, собирается Tauri по `bundle` в `tauri.conf.json`)
службу **не трогает**: ни при установке, ни при удалении. Значит после
деинсталляции приложения служба остаётся зарегистрированной. **Это дефект
сам по себе.**

### Linux и macOS

`service_control.rs::state()` возвращает `Unsupported` вне Windows. Службы
нет и не планировалась — ADR 0043 объясняет, почему: там нет
привилегированного действия, ради которого её стоило бы заводить.

Автозапуск при этом **есть**, и это другой механизм: `autostart.rs` (ADR
0042) — реестр Run на Windows, файловые записи на Linux и macOS.

## Что сделать

### Задача 1 — Windows: служба ставится и снимается инсталлятором

1. **Деинсталляция** (важнее установки: сейчас служба остаётся в системе).
   В `tauri.conf.json`, `bundle.windows.nsis`, добавить `installerHooks` со
   скриптом, который в секции `un.` вызывает
   `lumepeer-service.exe --uninstall`. Служба и её exe лежат рядом с
   приложением — они уже перечислены в `bundle.externalBin`.
2. **Установка.** Там же, в секции установки, вызвать `--install`.
   Инсталлятор уже идёт с правами администратора, второй запрос UAC не нужен.
3. Проверить актуальные имена полей в схеме `tauri.conf.json` (`$schema`
   указан в начале файла), а не писать по памяти.

→ **Проверка:** на чистой Windows-машине: установка → `sc query` показывает
службу в состоянии Running → Ctrl+Alt+Del работает без ручных действий →
деинсталляция → `sc query` службу не находит.

### Задача 2 — Идемпотентность установки и удаления

Обязательное условие: `--install` на уже установленной службе и
`--uninstall` на отсутствующей должны завершаться **успешно**, а не падать.
Иначе обновление приложения сломает установку.

Проверить, так ли ведёт себя `crates/service/src/install.rs`, и **дописать
тесты**, если нет.

→ **Проверка:** unit-тесты на обе операции, вызванные дважды подряд.

### Задача 3 — Ручное управление остаётся

Кнопка установки и снятия службы в настройках **не удаляется**. Правило из
шапки `service_control.rs`: «A privileged service a person cannot uninstall
from the app that installed it is the thing this project must not ship.»

Проверить, что после автоматической установки инсталлятором
`service_status` показывает `Running`, кнопка предлагает снять, и снятие
работает.

→ **Проверка:** вручную, после задачи 1.

### Задача 4 — Linux и macOS: автозапуск из пакета, без root

1. **Linux, deb:** `postinst` включает автозапуск, `prerm` выключает.
   Tauri поддерживает свои скрипты в `bundle.linux.deb` — свериться со
   схемой. rpm — `%post` / `%preun`.
2. **macOS:** `.dmg` — это перетаскивание, хуков установки у него нет.
   Значит автозапуск включается **при первом запуске приложения**, а не при
   установке. Удаление: LaunchAgent при старте проверяет, что приложение на
   месте, и снимает сам себя, если его нет.
3. Автозапуск делается через уже существующий `autostart.rs`. **Второй
   механизм не заводить**, инсталлятор дёргает существующий.
4. Включать по умолчанию можно только потому, что выключатель на виду —
   он уже есть в `systemSettings`. Принцип сформулирован в шапке
   `system-settings.ts`: «software that arranges to start with the session
   and cannot be told to stop from its own settings is the thing this app
   must not become». Не нарушить его.
5. **Никакого root.** Только пользовательский автозапуск.

→ **Проверка:** на Linux-хосте (см. заметки в памяти проекта про доступные
машины): установка deb → перелогин → приложение поднялось → удаление deb →
перелогин → не поднялось, файла автозапуска нет.

### Задача 5 — Деинсталляция не уничтожает данные

Проверить, что удаление приложения и службы **не удаляет** конфиг, историю
подключений, журнал аудита и записи сессий. Деинсталлятор не должен быть
средством уничтожения данных без спроса.

Если что-то из этого удаляется — исправить. Если решено, что часть данных
удалять всё же надо, — только с явным вопросом пользователю в инсталляторе.

→ **Проверка:** после деинсталляции файлы приложения в пользовательском
каталоге на месте.

## Чего делать НЕ нужно

- **Не убирать ручное управление службой** из настроек.
- **Не строить командную строку из путей и не отдавать её оболочке.** Причина
  подробно расписана в шапке `service_control.rs` и в ADR 0043: одна ошибка
  экранирования — и это запуск произвольного кода под SYSTEM. Повышать права
  можно только у **своего** бинаря с флагом.
- **Не запускать демон под root на Linux/macOS.** Решение D6: там
  пользовательский автозапуск.
- **Не заводить второй механизм автозапуска** рядом с `autostart.rs`.
- **Не удалять пользовательские данные при деинсталляции** без явного
  вопроса.
- **Не расширять возможности службы.** Вторая capability — это `15`, и она
  идёт с собственным ADR.

## Definition of done

- [ ] На Windows служба ставится инсталлятором и **снимается
      деинсталлятором**.
- [ ] `--install` и `--uninstall` идемпотентны, есть тесты.
- [ ] Ручное управление службой из настроек работает как раньше.
- [ ] На Linux и macOS автозапуск включается при установке и снимается при
      удалении, без root, через существующий `autostart.rs`.
- [ ] Пользовательские данные при деинсталляции не удаляются молча.
- [ ] Проверено на чистых машинах, а не только сборкой.
- [ ] Все проверки из `docs/bugs/README.md` пройдены.
