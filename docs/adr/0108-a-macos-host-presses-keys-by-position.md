# ADR 0108 — macOS-хост жмёт клавиши по позиции

**Статус:** принято. **Дата:** 2026-09-22.
**Контекст:** `docs/bugs/20-hotkeys-and-vmware-grab.md`, пункт 6 отчёта.
**Развивает:** ADR 0065 (аккорд — это позиция на клавиатуре), ADR 0090
(системные аккорды забирает хук гостя).

## Проблема

ADR 0065 постановил: `InputEventPayload::scancode` несёт evdev-код, и хост под
Ctrl/Alt/Meta жмёт **по позиции**, а не печатает символ. Причина там же:
команда адресована клавише, а не букве. `Ctrl+C` — это `VK_CONTROL` плюс `'C'`,
и хост, которому подсунули 'c' через путь «вставь символ», порождает лишний
символ при зажатом Ctrl и никакого копирования.

Windows это исполняет (`capture::windows::physical_key`), X11 исполняет
(`X11Injector::keycode`). **macOS — нет.** `MacosInjector::key` принимал
сигнатуру `(logical, pressed)`: поле `scancode` не читалось вообще, и
позиционного пути на этой платформе не существовало. Это было записано в
`docs/bugs/17-remote-hotkeys.md` как «не сделано» и осталось несделанным.

Два следствия, и оба — ровно симптомы из отчёта:

1. **Аккорд не срабатывал.** `Cmd+C` уходил в
   `CGEventKeyboardSetUnicodeString`, который не несёт key code вовсе, так что
   приложение видело лишний символ при зажатом Cmd и не видело команды.
2. **Системный аккорд не доезжал совсем.** У клавиши, перехваченной
   `crates/guestkeys`, `logical` равен 0 — так задумано, это и есть «у этой
   клавиши нет символьного смысла, жми по позиции» (ADR 0090). На macOS ветка
   `logical == 0` возвращала `InputUnavailable`. То есть `Win+…`, `Alt+Tab` и
   всё остальное, что забирает хук, на macOS-хосте не нажималось никогда.

## Решение

Третья таблица трансляции — evdev → `kVK_*` — и тот же порядок решения, что уже
стоит на двух других платформах:

```rust
fn key(logical: u32, scancode: u32, modifiers: u32, pressed: bool) -> Result<()> {
    if let Some(vk) = key_code_at(scancode)
        && (is_chord(modifiers) || names_a_key(logical))
    {
        return Self::key_vk(vk, pressed);
    }
    if let Some(vk) = named_key_vk(logical) { ... }   // гость старше ADR 0065
    ...                                               // иначе печатаем символ
}
```

Ничего нового не изобретается: `is_chord` и `names_a_key` — те же самые
функции `lumepeer-core`, и порядок веток скопирован с `WindowsInjector::key`
намеренно, чтобы три платформы расходились только таблицей.

### Почему таблица лежит вне `macos.rs`

`crates/media/src/capture/macos_keys.rs` собирается на **всех** платформах, а
не под `#[cfg(target_os = "macos")]`. Это отступление от того, как устроены
соседние бэкенды, и у него одна причина: воркспейс собирают не на Mac. Таблица
из сотни магических чисел, которую никто не может ни собрать, ни прогнать, —
это таблица, которую никто не может и проверить.

Прецедент в дереве уже есть: `crates/guestkeys` держит свои Windows-таблицы
ровно так же и по той же причине («Windows-only values, but the table and the
decision that reads it are plain integers, so both compile — and are tested —
everywhere»). Здесь это нужнее, чем там.

Проверяет таблицу в том числе `every_position_names_a_key_of_its_own`: он
прогоняет все 256 evdev-кодов и падает, если две позиции назвали один и тот же
`kVK_`. Это ловит опечатку в транскрипции — единственный отказ, который у такой
таблицы реально бывает. Отдельным тестом закреплены две пары, которые Apple
нумерует наоборот относительно всех прочих кодировок: 5/6 в цифровом ряду и G/H
в домашнем.

### Чего у Mac нет

`PrintScreen`, `ScrollLock`, `Pause`, `NumLock`, `Insert`, контекстное меню и
`F21`..`F24` не получают кода. `None` здесь — не ошибка, а «у этой клавиатуры
такой клавиши нет»: вызывающий откатывается на печать символа, то есть ровно на
поведение, которое было у всякой клавиши до этой правки.

`NumLock` не сопоставлен `kVK_ANSI_KeypadClear` сознательно, хотя тот и сидит в
той же позиции: у мака на цифровом блоке нет замка, который можно переключить,
и это другая клавиша. `Insert` не сопоставлен `kVK_Help` по той же причине —
так же, как он уже не сопоставлен в `named_key_vk`.

## Чего это не делает

- **Не трогает провод.** `is_chord`, `names_a_key` и смысл полей `logical` /
  `scancode` — замороженные golden-векторы, и ни один из них не изменён.
- **Не даёт macOS захвата клавиатуры.** ADR 0090 остаётся
  Windows-only: это про гостя, а здесь речь о хосте.
- **Не проверено на живой машине.** Mac на момент правки был недоступен, код
  написан вслепую и ждёт прогона на Mac — таблица прогнана, поведение инжектора
  нет.
