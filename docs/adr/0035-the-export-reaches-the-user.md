# ADR 0035 — The export reaches the user, and every IPC command is declared

Status: accepted
Date: 2026-08-27
Extends: §9.2 (export), §13 (the IPC surface), §2.3 (the webview authorizes
nothing), §17 (session recording)
Builds on: ADR 0031 (the exporter, and recording reaching the UI), ADR 0030
(the shape of a feature that is complete except for the end a person touches),
ADR 0029 (independent grants)

## Context

ADR 0031 ended the recording story except for one step. `crates/media/src/
export.rs` — 598 lines, tested, streaming, producing an Annex-B `.h264` and an
Ogg `.opus` — had **no caller anywhere in the tree**. No IPC command reached
it, no capability named one, no button pressed one. It was the same shape ADR
0030 and ADR 0031 were both written about: a feature that is finished
everywhere except where a person stands.

A second, quieter defect sat next to it. Five commands — `mic_toggle`,
`sas_request`, `sas_available`, `monitor_select`, `monitors_list` — were
registered in `generate_handler!` and named in `capabilities/view.json`, but
were missing from `build.rs`'s `COMMANDS`. Tauri autogenerates one
`allow-<name>` permission per declared command; an undeclared one gets no
permission file. The build only kept working because the `.toml` files a
previous build had generated were committed and `tauri-build` does not delete
what it no longer generates. Deleting `permissions/autogenerated/` — a
directory whose name says it is disposable — would have failed the build, and
in the meantime the ACL entry the view window depends on was being kept alive
by a stale artifact rather than by a declaration.

## Decision

### Two commands, and neither takes a path

`recordings_list` answers with what this device has recorded: a **file name**
per recording, its size, its last-write time, and whether an export of it
already exists. `recording_export` takes one of those names back and writes
the two tracks into `recordings/exports/`.

The name is the whole of the interface on purpose. ADR 0031 established that
the recording's path is chosen in Rust and travels outwards only; an export
that accepted a path would have handed that decision straight back to the
webview. `recording_file_name` accepts a string only when it is exactly its
own `file_name()` and carries the `.lmrc` extension, so a separator, a parent
segment, a drive letter or an absolute path all fail on one rule rather than
on a list of patterns someone has to keep complete.

Both are main-window commands. A guest's view window can neither enumerate
what the host has recorded nor turn it into files.

### Exporting needs no grant, and says so

The `recording` grant of §8.2 governs *making* a recording — the thing the
guest is entitled to a say in, because it is about them. What the host later
does with a file on its own disk is not a permission a guest ever held, and
inventing a grant for it would imply the guest has standing it does not have.
So the export is a local operation gated only on being the host's own window.

The export runs on a blocking thread rather than on the IPC executor: an hour
of session is a streaming read of a file that can run to gigabytes, and the
executor that would be waiting on it is the same one a revoke arrives on.

### The panel is a list, not a per-session control

The button does not live in the session row. A recording outlives the session
it came from, and the person exporting one is usually not in a session at all
— so `recordings.ts` renders its own card next to the address book, refreshed
by the poll that already runs. A second press while an export is running is
refused in the panel as well as being pointless: the second call would stream
the same file over the first one's output.

### `COMMANDS` is now a tested invariant, not a convention

The five missing declarations are added, and
`commands::tests::every_handled_command_is_declared_to_tauri_build` reads both
lists out of the source and asserts they are the same set. The drift it
catches is invisible in a working tree — it only appears once someone cleans
a generated directory — which is exactly the class of defect that has to be a
test rather than a rule in a document.

`capabilities-pilot/main.json` is also brought back in line with
`capabilities/main.json`, whose own description says the two permission lists
must stay identical; it had lost `core:window:allow-start-dragging`.

## Consequences

- The export is reachable, and `crates/media/src/export.rs` has a caller. The
  MKV question of ADR 0031 is unchanged: two files, no muxer, no new
  dependency.
- `recordings_list` scans a directory on every poll. It is one `read_dir` of a
  directory holding one file per recorded session, on the same beat as the
  session list; if that ever becomes a cost, the answer is a cache keyed on
  the directory's mtime, not a slower poll.
- The exported files land in `recordings/exports/` and are never cleaned up.
  Deleting them is the host's business, and a program that deletes recordings
  by itself is not one this project wants to have written.
- A recording made by an older build, or copied in by hand, exports the same
  way: the panel lists whatever is in the directory and carries the extension.
- Adding an IPC command now costs three edits (handler, `COMMANDS`,
  capability) and the test names the one that was forgotten.

## Verification

- `commands.rs`: a plain name passes; a name that is a path, an escape, or a
  file that is not a recording is refused with `BAD_RECORDING`; every handled
  command is declared to `tauri-build` and vice versa (checked to fail by
  removing one entry).
- `recordings.test.ts`: one row per recording; the button asks the core by
  name; the tracks and the directory the core answered with are shown and not
  guessed; a recording with no track says so instead of claiming a file; a
  second press while an export runs is refused; a refusal is rendered rather
  than swallowed; every string is translated in both locales.
- `accessibility.test.ts`: the panel passes the axe audit, empty and full, in
  both locales.
- Against the running app on Windows, through the pilot bridge: the panel
  renders, `recordings_list` answers `[]` on a machine that has recorded
  nothing, the three path-shaped names are refused with `BAD_RECORDING` and a
  name that is well-formed but absent fails with `EXPORT`. With a recording
  placed in the recordings directory, the row appears, pressing **Export**
  writes `recordings/exports/<stem>.h264` beginning `00 00 00 01`, no empty
  `.opus` is left beside it, and the button becomes "Export again".
- `e2e/ci-stand.sh` (ADR 0036): on a real session, on a live display, the host
  records itself, `recordings_list` finds the file, three names that are paths
  are refused, and the exported `.h264` begins with an Annex-B start code.
