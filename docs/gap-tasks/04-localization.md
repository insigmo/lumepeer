# 04 — Локализация: инфраструктура и новые языки

**Пункт бэклога:** 9. **Зависит от:** ничего. **Нужно:** ничего, кроме
носителей языка для вычитки (агент переводит, человек вычитывает).

## Что уже есть (проверено по коду)

- `apps/desktop/src/i18n.ts`, 920 строк, один файл: тип `Locale = 'en' | 'ar'`,
  `SUPPORTED_LOCALES`, `DEFAULT_LOCALE`, объединение `TranslationKey` из **274
  ключей**, два словаря `en` и `ar` и `const dictionaries: Record<Locale,
  Dictionary> = { en, ar }`.
- `t(locale, key, arg?)` — значение словаря либо функция от одного аргумента.
- `dirOf(locale)` — `'rtl'` только для `ar`.
- `detectLocale(nav)` берёт базовый код языка (`raw.split('-')[0]`), то есть
  локали в системе **только базовые**: `pt`, а не `pt-BR`.
- `apps/desktop/src/i18n.test.ts` проверяет подстановку, направление письма и
  что ключи не пустые. Полноту словаря обеспечивает сам TypeScript:
  `Dictionary` — это `Record<TranslationKey, …>`, пропущенный ключ не
  соберётся.
- Ручного выбора языка в интерфейсе нет: локаль определяется только по
  `navigator`.
- `apps/desktop/src-tauri/src/config.rs` — конфиг **только на чтение**
  (`Deserialize`, из `config/default.toml`). Выбор языка туда не пишется.

## Задача 1 — разделить словари по файлам

**Файлы:** `apps/desktop/src/i18n.ts`, новые `apps/desktop/src/locales/*.ts`

1. Вынеси каждый словарь в свой файл (`locales/en.ts`, `locales/ar.ts`),
   оставив в `i18n.ts` тип `TranslationKey`, тип `Dictionary`, реестр
   `dictionaries`, `t`, `dirOf`, `detectLocale`. Один файл на 900 строк с
   десятью языками превратится в шесть тысяч — это единственная причина
   разделения, ничего больше не меняем.
2. Проверь, что типизация осталась строгой: каждый файл экспортирует
   `Dictionary`, а не `Partial<Dictionary>`.

## Задача 2 — ручной выбор языка

**Файлы:** `apps/desktop/src/i18n.ts`, `apps/desktop/src/system-settings.ts`
(или тот файл, где живёт панель настроек), `apps/desktop/src/*.test.ts`

1. В панели настроек — список поддерживаемых языков с подписями на самих
   языках («Deutsch», «Русский»), плюс пункт «как в системе».
2. Выбор сохраняется в `localStorage` под одним ключом. Новое хранилище на
   диске для этого **не заводить**: это настройка одного окна, а не состояние
   сессии.
3. Порядок разрешения: сохранённый выбор → `detectLocale(navigator)` →
   `DEFAULT_LOCALE`. Смена языка перерисовывает интерфейс и переключает
   атрибут `dir` без перезапуска.

## Задача 3 — языки

**Файлы:** `apps/desktop/src/locales/*.ts`, `apps/desktop/src/i18n.ts`

Добавь: `ru`, `de`, `fr`, `es`, `pt`, `it`, `tr`, `uk`, `pl`, `zh`, `ja`.
Коды базовые — `detectLocale` работает с базовыми, региональных вариантов
не заводить.

Правила перевода:
- Переводится смысл, а не слова. `Deny`, `Allow view`, `Full control` — это
  кнопки в диалоге согласия, от их понятности зависит, что человек разрешит.
- Термины держать едиными внутри языка: «грант», «сессия», «хост», «гость» —
  один вариант на весь словарь.
- Плейсхолдеры (`arg`) и их порядок не менять.
- Строки, которые не переведены на конкретный язык, оставлять по-английски
  **нельзя**: тип не позволит, и это правильно — недоперевод хуже отсутствия
  языка.

## Задача 4 — тесты

**Файл:** `apps/desktop/src/i18n.test.ts`

1. Тест «каждый поддерживаемый язык переводит каждый ключ и не оставляет
   плейсхолдеров» — по **всем** `TranslationKey`, а не по трём выбранным,
   как сейчас.
2. Тест на разрешение локали: сохранённый выбор бьёт системный.
3. Тест `dirOf` для всех новых языков (все LTR, `ar` остаётся единственным
   RTL).
4. Прогон axe-core (`accessibility.test.ts`) должен остаться зелёным на
   каждой локали, которую он покрывает.

## Чего НЕ делать

- Не тащить i18n-библиотеку. Здесь нет плюрализации, дат и чисел — есть
  таблица строк и одна подстановка.
- Не переводить строки логов, ошибки в `tracing`, имена ADR и §-ссылки.
- Не менять существующие английские тексты «заодно»: любое изменение `en` —
  это изменение продукта, а не перевод.
- Не добавлять региональные локали (`pt-BR`, `zh-TW`), пока `detectLocale`
  работает по базовому коду.
- Не выносить переводы в JSON, который грузится в рантайме: тип
  `TranslationKey` — единственное, что сейчас гарантирует полноту.

  определение по `navigator`.
