# 10 — Zero-copy захват → энкодер на Windows

**Пункт бэклога:** 33 (первая половина). **Зависит от:** ничего.
**Нужно:** Windows-машина с дискретной или встроенной картой и аппаратным
H.264 (то есть почти любая), вторая машина как гость, и способ мерить
загрузку CPU.

Цель — снять копирование кадра через оперативную память между DXGI Desktop
Duplication и Media Foundation. Это оптимизация, и она обязана быть
доказана числами: без замера «до» пачка считается незакрытой.

## Что уже есть (проверено по коду)

- `crates/media/src/capture/mod.rs`: `Frame { width, height, format,
  timestamp_us, data: Vec<u8> }` — **пиксели всегда в оперативной памяти**;
  `PixelFormat { Bgra8, Nv12 }`.
- `crates/media/src/capture/windows.rs` — DXGI Desktop Duplication (ADR 0012).
- `crates/media/src/encode/windows.rs` — Media Foundation (ADR 0011),
  принимает NV12.
- `crates/media/src/encode/nv12.rs` — конвертация BGRA→NV12 на CPU.
- `crates/media/src/scale.rs` — `fit_within`, `fit_within_budget`,
  `scale_to_percent`: понижение картинки на стороне хоста (ADR 0018, 0060),
  работает по пикселям в памяти.
- `apps/desktop/src-tauri/src/view.rs` — хостовый цикл: тянет кадр из
  `CaptureController`, кодирует, отдельная задача пишет в поток (ADR 0059).
- Путь secure desktop (`crates/service/src/secure_desktop.rs`) снимает кадр
  через GDI и приходит **не** из DXGI — на него это изменение не
  распространяется.

## Задача 0 — измерить «до»

Прогони сессию 1080p60 и запиши: загрузку CPU процесса, время от захвата до
готового кадра, RSS. Без этих чисел остальное бессмысленно.

## Задача 1 — кадр, который может жить на GPU

**Файл:** `crates/media/src/capture/mod.rs`

1. Дай `Frame` возможность нести дескриптор GPU-текстуры вместо байтов, не
   ломая ни один существующий вызов: например, поле `data` становится
   перечислением `FrameData { Cpu(Vec<u8>), Gpu(GpuTexture) }` с методом
   `as_cpu(&mut self) -> Result<&[u8]>`, который делает readback и
   запоминает его.
2. `GpuTexture` — платформенный тип за `cfg`, вне Windows его нет вовсе.
3. Все существующие потребители (`scale`, запись, тесты, декодер-воркер)
   обязаны продолжать работать: они зовут `as_cpu()` и получают то же, что
   раньше. Ни одного `unwrap` на этом пути.

## Задача 2 — путь без копии

**Файлы:** `crates/media/src/capture/windows.rs`, `crates/media/src/encode/windows.rs`

1. Отдавай из DXGI `ID3D11Texture2D` как есть.
2. В MF-энкодере принимай текстуру через `MFCreateDXGISurfaceBuffer` и
   `IMFDXGIDeviceManager`, разделяя одно D3D11-устройство между захватом и
   кодированием. Разные устройства — это скрытая копия, ради устранения
   которой всё и делается.
3. Если разделить устройство не удалось (разные адаптеры, драйвер отказал) —
   честный откат на путь через память, с записью в лог **один раз за
   сессию**, а не на каждый кадр.

## Задача 3 — что делать с масштабированием

Понижение картинки (ADR 0018/0060) на CPU-пути делает `scale.rs`. На
GPU-пути его надо либо выполнять на GPU (видео-процессор D3D11), либо
вынуждать readback — то есть терять весь смысл. Выбери первое, а если не
получается — включай zero-copy **только когда масштабирование не требуется**
(гость просит нативный размер), и напиши это в ADR открытым текстом.

## Задача 4 — фича и ADR

Новая фича `encode-mf-zero-copy` (или расширение `encode-mf` — обоснуй) и
ADR, дополняющий 0011/0012/0059: что именно изменилось в пути кадра, при
каких условиях путь активен, как выглядит откат.

## Чего НЕ делать

- Не менять трейт `ScreenCapturer` и не заводить второй параллельный трейт.
- Не трогать Linux/macOS бэкенды — Linux это пачка `11`.
- Не переносить путь secure desktop на GPU: он идёт через GDI из другой
  сессии, и трогать его здесь нельзя.
- Не удалять CPU-путь: он остаётся и как откат, и как единственный путь без
  фичи.
- Не оптимизировать «заодно» ABR, jitter или запись.

## Definition of done

- `cargo clippy -p lumepeer-media --all-targets --features capture-windows,encode-mf,encode-openh264 -- -D warnings` — чисто.
- `cargo test --workspace` не хуже базового прогона; новые тесты — на
  `as_cpu()` readback и на откат при несовместимых устройствах.
- Числа «до» и «после» на одной машине и одной сцене: загрузка CPU, задержка
  захват→кадр, RSS. Улучшение должно быть видно; если его нет — это тоже
  результат, и тогда путь остаётся выключенным.
- Проверка отката: принудительно сломать разделение устройства — сессия
  продолжается, картинка есть, в логе одна запись.
- `ci/resource-budget.yml` не превышен.
