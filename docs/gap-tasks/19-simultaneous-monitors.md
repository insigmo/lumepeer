# 19 — Несколько мониторов одновременно

**Пункт бэклога:** 25. **Зависит от:** `01` — для macOS, где мониторы пока
не перечисляются вовсе. **Нужно:** хост с двумя физическими мониторами,
гость (желательно тоже с двумя).

## Что уже есть (проверено по коду)

- `CaptureTarget { PrimaryDisplay, Display(u32) }` — **переключатель**, а не
  одновременный показ (`crates/media/src/capture/mod.rs`).
- `HostMonitor { id, width, height, primary }` и `host_monitors()`; `id` —
  это индекс, которым `CaptureTarget::Display` пользуется, порядок обоих
  обязан совпадать.
- Протокол: `MonitorsList` и `MonitorSelect` (минор 1).
- Один медиапоток на сессию: `STREAM_VIDEO` в `crates/net/src/media.rs`,
  рядом `STREAM_AUDIO` и `STREAM_MIC` — то есть мультиплексирование по
  идентификатору потока уже существует как приём.
- Хостовый цикл — `apps/desktop/src-tauri/src/view.rs`: один
  `CaptureController`, который «начинает с первым зрителем и заканчивается с
  последним».
- **Wayland — принципиальное исключение.** Комментарий в
  `crates/media/src/capture/mod.rs` (linux_host_monitors) прямо говорит:
  портал выдаёт ровно один поток, выбранный пользователем в его собственном
  диалоге, и `MonitorSelect` там инертен. Значит на Wayland одновременных
  мониторов не будет — и это не дефект.

## Задача 1 — ADR: сколько и как

1. Один монитор — один поток (`STREAM_VIDEO + n`), а не одна склеенная
   картинка. Склейка ломает попадание пикселя в пиксель (ADR 0060) и делает
   бессмысленным `StreamSizeRequest`.
2. Потолок — константа (рекомендация: 2 одновременно). Это не «пока не
   упрёмся»: каждый поток — свой энкодер, свой битрейт, свой бюджет
   `ci/resource-budget.yml`.
3. Wayland: список остаётся из одной записи, интерфейс честно объясняет
   почему (§18).

## Задача 2 — протокол

**Файл:** `crates/core/src/protocol.rs`

`MonitorSubscribe { ids: Vec<u32> }` — в конец, `PROTOCOL_MINOR` +1,
`FEATURE_MULTI_MONITOR`, потолок числа записей константой.
`MonitorSelect` остаётся и продолжает работать для старых гостей — не
удалять.

## Задача 3 — хост: несколько конвейеров

**Файлы:** `apps/desktop/src-tauri/src/view.rs`, `crates/media/src/capture/`

1. `CaptureController` получает возможность вести несколько целей
   одновременно, сохраняя правило «нет зрителя — нет кадров» **на каждую
   цель отдельно**: отписка от второго монитора должна останавливать его
   захват, не трогая первый.
2. Отдельный энкодер на поток. ABR считается по каждому потоку своим
   `ReceiverReport` — общий битрейт делится, а не удваивается: суммарный
   потолок остаётся `ABR_MAX_BITRATE_KBPS`.
3. Отзыв `view` останавливает **все** потоки немедленно.

## Задача 4 — гость: окна

**Файлы:** `apps/desktop/src-tauri/src/view.rs`, `apps/desktop/src/view-window.ts`,
`apps/desktop/src/toolbar.ts`

1. Одно окно на монитор; заголовок называет монитор. Существующий
   переключатель монитора остаётся для тех, кому хватает одного окна.
2. Закрытие окна = отписка от потока. Закрытие последнего — конец захвата.
3. Горячие клавиши, масштаб и полный экран работают в каждом окне
   независимо.

## Чего НЕ делать

- Не склеивать мониторы в одну виртуальную картинку.
- Не удалять `MonitorSelect` и не ломать старых гостей.
- Не поднимать `ABR_MAX_BITRATE_KBPS`, чтобы «хватило на два потока».
- Не пытаться получить несколько потоков из портала на Wayland.
- Не заводить третий, четвёртый и далее мониторы «раз уж всё равно
  переписали»: потолок — решение из ADR, а не то, что осталось после
  реализации.

## Definition of done

- `cargo test --workspace` зелёный: отписка от одного потока не глушит
  второй; отзыв `view` глушит оба; потолок числа подписок соблюдается.
- Вектор нового сообщения — в конец, старые не тронуты.
- `cargo clippy --workspace --all-targets -- -D warnings` — чисто.
- `cd apps/desktop && npm run typecheck && npm test` — зелёное.
- Ручная проверка на двух мониторах: два окна показывают разные экраны
  одновременно; закрытие одного не роняет другое; суммарный битрейт не
  превышает потолок; `ci/resource-budget.yml` выдерживается.
- На Wayland: одна запись в списке, честное объяснение в интерфейсе.
