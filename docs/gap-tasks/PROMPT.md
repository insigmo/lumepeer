# Как запускать пачку

Один запуск — одна пачка — один worktree — один PR. Параллельные агенты не
делят рабочее дерево: каждому свой `git worktree`, вливать по одному после
ревью.

## Подготовка (делает человек, до запуска агента)

```sh
git worktree add ../lumepeer-gap-NN -b gap/NN-<slug> master
```

Дальше агент запускается **с рабочей директорией `../lumepeer-gap-NN`**.

## Промпт (копировать целиком, подставить NN)

> Работай в этом worktree, ветка уже создана. Задача — пачка `NN` из
> `docs/gap-tasks/NN-<имя файла>.md`.
>
> Порядок действий:
>
> 1. Прочитай `docs/gap-tasks/README.md` целиком — разделы «Обязательно к
>    прочтению», «Правила, нарушение которых заворачивает работу»,
>    «Известные ловушки прогона».
> 2. Прочитай `docs/tasks/README.md` — правила первой волны действуют.
> 3. Прочитай раздел «Ground rules» в корневом `README.md`.
> 4. Прочитай сам файл пачки и **весь код по путям, которые в нём названы**,
>    прежде чем писать первую строчку. Описание в файле — ориентир; истина в
>    коде. Если код противоречит файлу пачки — верь коду и скажи об этом в
>    отчёте.
> 5. Зафиксируй базовый прогон на чистом дереве до своих правок:
>    `cargo test --workspace` и запиши, что уже красное. Сравнивать будешь
>    с этим, а не с нулём.
> 6. Делай задачи из файла пачки **по порядку**. Каждую задачу доводи до
>    зелёных проверок, прежде чем начинать следующую.
> 7. В конце прогони весь блок «Definition of done» из файла пачки и
>    отчитайся по каждому пункту отдельно — что запускал и что получил.
>
> Жёсткие требования:
>
> - Код, комментарии, имена, сообщения коммитов и ADR — по-английски.
>   Трейлеров в коммитах не ставить.
> - Ничего сверх того, что просит файл пачки. Не «улучшай» соседний код, не
>   переформатируй чужие строки, не чини несвязанные предупреждения. Каждая
>   изменённая строка должна прослеживаться до задачи из файла.
> - Никаких магических чисел: новая величина — константа в
>   `crates/core/src/constants.rs` с doc-комментарием.
> - Никаких паник на недоверенном вводе в `crates/core` и `crates/net`.
> - Отклонение от плана оформляется ADR в `docs/adr/`, номер — по правилу из
>   `docs/gap-tasks/README.md`. Молча отклоняться нельзя.
> - Если в файле пачки есть раздел «Чего НЕ делать» — он важнее твоего
>   представления о том, как было бы лучше.
>
> Остановись и спроси человека, не продолжая, если:
>
> - для проверки нужно железо или доступ, которых у тебя нет (в шапке файла
>   пачки написано, что именно нужно);
> - задача требует отменить решение уже принятого ADR, а в файле пачки этого
>   не написано;
> - базовый прогон на чистом дереве красный в тех же тестах, которые ты
>   собираешься трогать.
>
> Формат отчёта в конце: что сделано по каждой задаче, какие файлы созданы и
> изменены, какие ADR добавлены, результат каждой команды из Definition of
> done, и отдельным списком — что осталось незакрытым и почему.

## Если пачка требует железа, которого нет у агента

Агент пишет код и все проверки, которые проходят локально, помечает в отчёте
незакрытые пункты Definition of done и **не выдаёт задачу за завершённую**.
Отдельная сессия на нужной машине потом закрывает ровно эти пункты. Так уже
сделано для macOS в первой волне — см. `docs/tasks/12-macos-completion.md`.

## После агента (делает человек)

```sh
cd ../lumepeer-gap-NN
git log --oneline master..HEAD
git diff master --stat
```

Ревью, затем слияние **по одной пачке за раз**: два параллельных агента,
влитые вместе без промежуточного прогона, дают конфликт в `constants.rs`,
`protocol.rs` и `network.rs` практически гарантированно.
