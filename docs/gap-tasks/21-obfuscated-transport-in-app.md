# 21 — Обфусцированный транспорт: провод в приложение

**Пункт бэклога:** 49. Это **инкремент 3** из дорожной карты ADR 0052
(см. `docs/tasks/17-followup-obfuscated-quic-endpoint.md`, раздел 9).
**Зависит от:** ничего в этом репозитории. **Нужно:** две машины за разными
NAT для настоящей проверки; локально проверяется только сборка и тесты.

## Что уже сделано — НЕ перепроверять и НЕ переписывать

- `crates/net/src/obfuscate.rs` — кодек и `ObfuscatedSocket` поверх
  `noq::AsyncUdpSocket`, GSO/GRO выключены (`max_*_segments() == 1`),
  `obfuscated_transport_config()` с keep-alive.
- `crates/net/src/stun.rs` — `reflexive_addr`, проверено живьём.
- `crates/net/src/obfuscated_endpoint.rs` — `bind_host(invite_id)` →
  `HostObfuscatedEndpoint { endpoint, public_addr, cert_fingerprint }` и
  `connect_guest(...)`; TLS пинится по отпечатку, не по CA; фоновая задача
  раз в `NAT_MAPPING_KEEPALIVE_SECS` держит NAT-маппинг. **У задачи нет
  ручки остановки — это и есть часть этой пачки.**
- `crates/net/src/ticket.rs` — тикет уже везёт `obfuscated_addr` и
  `host_cert_fingerprint: Option<[u8; 32]>` (ADR 0053).
- `crates/net/examples/obfuscated_wan_probe.rs` — двухролевой живой пробник.
- ADR 0051, 0052, 0053. Архитектура решена: прямой обфусцированный QUIC,
  данные никогда не идут через сервер; обнаружение адреса — свой STUN.
  **Не переигрывать.**
- iroh 1.0.2 не даёт хук на свой UDP-сокет — не пытаться обернуть его сокет.

## Задача 1 — время жизни хостового эндпоинта

**Файлы:** `crates/net/src/obfuscated_endpoint.rs`,
`apps/desktop/src-tauri/src/network.rs`

1. Дай `HostObfuscatedEndpoint` явное закрытие: keep-alive-задача
   останавливается, сокет освобождается. Сейчас задача живёт до конца
   процесса.
2. Привяжи жизнь эндпоинта к жизни инвайта (ADR 0062: код не меняется, и
   хранится он через `ActorStores::invite_path`): инвайт создан — эндпоинт
   поднят; инвайт заменён — старый закрыт.
3. STUN не ответил или маппинг непригоден (двойной NAT) — `public_addr:
   None`, в тикет ничего не пишется, всё работает по существующему пути
   iroh. Это штатный исход, не ошибка.

## Задача 2 — три канала поверх нового транспорта

**Файлы:** `apps/desktop/src-tauri/src/network.rs`, `crates/net/src/connection.rs`

1. Сегодня `Channel::from_alpn` различает `rd/control/1`, `rd/media/1`,
   `rd/file/1` на **iroh**-соединениях. Тот же разбор нужен поверх
   `noq::Connection`: ALPN задаётся в `ClientConfig`/`ServerConfig`, значения
   те же — новых ALPN не заводить.
2. Всё, что выше транспорта, не меняется ни на строку: рукопожатие,
   согласие, гранты, отзыв, ленивое `rd/file/1`. Если пришлось менять
   `crates/core` — значит транспорт протёк наверх, и это дефект.
3. Практический приём: свести оба пути к одному внутреннему типу соединения
   (тонкая обёртка над `iroh::endpoint::Connection` и `noq::Connection`) и
   провести его через актор. Копию всей логики актора под второй транспорт
   **не делать**.

## Задача 3 — включение

1. Новый транспорт по умолчанию **выключен**, включается флагом
   (`config/default.toml`, секция вроде `[network] obfuscated = false`;
   `apps/desktop/src-tauri/src/config.rs` только читает конфиг — поле
   добавляется туда же по образцу `relay_only`).
2. Выбор транспорта, автоматический откат и диагностика — пачка `23`.
   Здесь достаточно: флаг включён и в тикете есть адрес и отпечаток →
   пробуем новый путь; иначе — старый.

## Чего НЕ делать

- Не удалять и не «упрощать» существующий путь через `PeerEndpoint`/iroh.
- Не заводить новые ALPN.
- Не менять кодек обфускации, формат тикета и `stun.rs`.
- Не включать транспорт по умолчанию.
- Не браться за hole punching (пачка `22`) и за выбор транспорта с откатом
  (пачка `23`).
- Не пытаться подтянуть `noq` версии, отличной от той, что тянет iroh: два
  разных `noq` дадут два несовместимых `AsyncUdpSocket`.

## Definition of done

- `cargo fmt --all -- --check`, `cargo clippy -p lumepeer-core -p lumepeer-net --all-targets -- -D warnings` — чисто.
- `cargo test -p lumepeer-core -p lumepeer-net` зелёный (полный
  `cargo test --workspace` на машине с установленным `LumepeerHelper` красный
  по независимой причине — сверяйся с базовым прогоном).
- Новый тест: рукопожатие и согласие проходят поверх обфусцированного
  соединения между двумя локальными эндпоинтами — то есть проверен именно
  провод, а не сокет.
- Тест: закрытие эндпоинта останавливает keep-alive-задачу.
- На паре машин за разными NAT с включённым флагом: сессия поднимается,
  видео идёт, файл передаётся, отзыв гранта срабатывает мгновенно.
- С выключенным флагом ничего не изменилось.
