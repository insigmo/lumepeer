# 16 — TCP-туннель (проброс портов)

**Пункт бэклога:** 21. **Зависит от:** ничего. **Нужно:** две машины и
что-нибудь слушающее порт на хосте (веб-интерфейс роутера, RDP, БД).

Самая опасная возможность из всего списка: туннель превращает гостя в узел
внутри сети хоста. Поэтому здесь больше про грант и границы, чем про байты.

## Что уже есть (проверено по коду)

- `crates/net/src/endpoint.rs`: `ALPN_CONTROL` (`rd/control/1`), `ALPN_MEDIA`,
  `ALPN_FILE` — три ALPN, каждый на своём QUIC-соединении; `Channel::from_alpn`
  в `connection.rs` отображает их и возвращает `None` для чужого ALPN.
- `rd/file/1` поднимается **лениво**, только после согласия (ADR 0032) — это
  образец для четвёртого канала.
- Гранты — `crates/core/src/consent.rs`; правило «`match` без `_`-ветки»
  действует.
- Аудит — `crates/core/src/audit.rs`, пиры только солёным хешем.

## Задача 1 — ADR и грант

1. ADR: туннель — независимый грант `tunnel`, приходит только с
   `Role::FullControl` (ADR 0054), отзывается отдельно, и **каждое новое
   соединение** внутри туннеля перепроверяет грант, а не только его открытие.
2. Ограничение цели — часть решения, а не настройка: гость называет
   `host:port`, хост **сам** решает, разрешён ли этот адрес. Минимально
   допустимая политика по умолчанию — только `127.0.0.1` и только порты,
   которые хост явным действием добавил в список на время сессии. Открытый
   выход в чужую подсеть по умолчанию — нет.
3. Список разрешённых целей снимается снапшотом в момент выдачи (правило
   §8.2, как `ControlLimited`): правка политики не расширяет живой туннель.

## Задача 2 — четвёртый ALPN

**Файлы:** `crates/net/src/endpoint.rs`, `crates/net/src/connection.rs`

`ALPN_TUNNEL = "rd/tunnel/1"`, вариант `Channel::Tunnel`, подъём соединения
**лениво**, только после того как хост разрешил конкретную цель. Не
переиспользовать `rd/file/1`: смысл раздельных ALPN в том, что ни один канал
не может задержать отзыв на другом.

## Задача 3 — сообщения

**Файл:** `crates/core/src/protocol.rs`

`TunnelOpenRequest { host: String, port: u16 }`,
`TunnelOpenResponse { stream_id: u32, accepted: bool, reason }`,
`TunnelClose { stream_id }` — в конец перечисления, `PROTOCOL_MINOR` +1,
своя `FEATURE_TUNNEL`, проверки длин в `decode`. Байты идут по `rd/tunnel/1`
с тем же самоописывающим заголовком, что у файлового канала
(`stream_id || len || bytes`), а не постранично в управляющем канале.

## Задача 4 — форвардер

**Файл:** `crates/net/src/tunnel.rs` (новый)

1. Гость слушает локальный порт, каждое TCP-подключение к нему открывает
   поток в туннеле; хост подключается к цели и перекладывает байты.
2. Потолки — константами: число одновременных потоков, размер буфера,
   таймаут простоя. Никаких магических чисел.
3. Обрыв TCP с любой стороны закрывает поток на обеих; отзыв гранта —
   закрывает **все** потоки немедленно.
4. Никаких паник на данных из сети.

## Задача 5 — интерфейс и аудит

**Файлы:** `apps/desktop/src/`, `apps/desktop/src-tauri/src/network.rs`

1. Хост видит список активных туннелей (цель, сколько потоков, сколько
   байтов) и может закрыть каждый и все сразу — одним нажатием.
2. Открытие туннеля, каждая новая цель и закрытие — в аудит.
3. Пока туннель активен, это видно в строке сессии; «тихого» туннеля быть не
   должно.

## Чего НЕ делать

- Не делать полноценный VPN, TAP/TUN-устройство и маршрутизацию подсетей.
- Не разрешать по умолчанию произвольный `host` — только локальные адреса
  хоста, остальное каждый раз явным разрешением.
- Не подразумевать `tunnel` из `input`/`view`.
- Не тянуть туннель по управляющему каналу.
- Не хранить список целей между сессиями «для удобства».

## Definition of done

- `cargo test --workspace` зелёный: тесты форвардера на memory-дуплексах,
  отказ без гранта, немедленное закрытие всех потоков при отзыве, отказ на
  неразрешённую цель.
- Вектор новых сообщений дописан в конец, старые не тронуты.
- `cargo clippy --workspace --all-targets -- -D warnings` — чисто.
- Ручная проверка: `curl` через проброшенный порт на хостовый сервис
  работает; отзыв гранта посреди запроса рвёт соединение; неразрешённая цель
  получает отказ.
- В аудите видно открытие и закрытие с целями.
