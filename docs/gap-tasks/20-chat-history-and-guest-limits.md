# 20 — История чата и лимит одновременных гостей

**Пункты бэклога:** 27, 28. **Зависит от:** ничего. **Нужно:** две машины
для ручной проверки.

Две небольшие задачи в одной сессии: обе — про политику, обе требуют ADR,
отменяющего прежнее решение, и обе не трогают транспорт.

**Внимание.** Задача 1 отменяет действующее решение (§15: чат эфемерен). Если
человек, запустивший эту пачку, не подтвердил, что решение пересматривается,
— остановись и спроси. Явное подтверждение в запуске выглядит так:
«история чата — решение пересматриваем, ADR отменяет §15 в этой части».

## Задача 1 — история чата

### Что уже есть (проверено по коду)

- `crates/core/src/chat.rs`: `validate_text`, `ChatEntry { outgoing, text,
  at_unix }`, `ChatLog` — `BTreeMap<NodeId, Vec<ChatEntry>>`, потолок
  `MAX_TRANSCRIPT_ENTRIES = 200` на пира, `CHAT_MAX_BYTES = 4096` на
  сообщение. В doc-комментарии прямо: «чат эфемерен по устройству (§15),
  никогда не сохраняется», и сессия, которая закончилась, теряет свою
  переписку целиком.
- Чат не требует отдельного гранта: он не даёт контроля над хостом.
- Аудит рядом: `crates/core/src/audit.rs` — append-only SQLite, ретенция
  `AUDIT_RETENTION_DAYS = 30`, пиры **только солёным хешем**
  (`peer_hash = BLAKE3(install_salt || node_id)`), суточная чистка,
  панель с фильтром, экспортом и стиранием (ADR 0041).
- Правило хранилищ: путь к новому файлу на диске приходит через `ActorStores`
  (`apps/desktop/src-tauri/src/network.rs`), а не хардкодится.

### Что сделать

1. **ADR**, отменяющий §15 в части чата. В нём обязаны быть ответы на:
   срок хранения (по умолчанию — тот же, что у аудита, 30 дней), как
   стирается (кнопка «стереть всё» рядом с той, что уже есть у аудита),
   что хранится (текст — да; иначе история бессмысленна) и как называется
   собеседник на диске. Про последнее: аудит хранит **хеш**, история чата
   без имени бесполезна — значит либо имя из адресной книги, либо тот же
   хеш плюс сопоставление через адресную книгу. Выбери и обоснуй.
2. **Хранилище** — по образцу `apps/desktop/src-tauri/src/audit_store.rs`:
   SQLite, миграция, путь через `ActorStores`, `None` = «без истории», и это
   штатное состояние, а не ошибка.
3. **Настройка «вести историю чата»** — выключена по умолчанию. Включение —
   осознанное действие пользователя; интерфейс говорит, где файл лежит и
   какой у него срок.
4. **UI**: история открывается для устройства из адресной книги; поиск —
   нет, это не мессенджер.
5. Потолки `MAX_TRANSCRIPT_ENTRIES` и `CHAT_MAX_BYTES` в памяти **остаются**:
   хранилище не отменяет границу оперативной памяти.

### Чего НЕ делать

- Не включать историю по умолчанию.
- Не писать чат в аудит-лог: там принципиально нет содержимого.
- Не синхронизировать историю между устройствами.
- Не сохранять историю сессии, которая закончилась отзывом гранта, если
  настройка была выключена в момент разговора.

## Задача 2 — лимит одновременных гостей

### Что уже есть (проверено по коду)

`crates/core/src/constants.rs`:
`MAX_CONCURRENT_GUESTS_TRIAL = 1`, `MAX_CONCURRENT_GUESTS_PRO = 1`,
`MAX_CONCURRENT_GUESTS_TEAM = 5`, `TRIAL_SESSION_LIMIT_SECS = 30 * 60`.
Проверяет `crates/core/src/license.rs` (`LicenseGuard`, офлайн-таблица §12.4,
включая строку про откат часов). Тест на предел гостей — в
`tests/integration`.

Правило одного контроллера — отдельное и остаётся: `Role::is_controller`
(`ControlLimited` и `FullControl`) — сколько бы зрителей ни было,
управляющий один.

### Что сделать

1. **ADR**: новые значения и почему. `PRO = 1` при `TEAM = 5` — это
   продуктовое решение; менять его без записи нельзя.
2. Поднять значения в константах. Правило одного контроллера **не трогать**.
3. Проверить и дописать тесты: превышение лимита отклоняет **новое**
   подключение и не рвёт существующие; лимит считается по активным сессиям,
   а не по попыткам.
4. Проверить нагрузку: 5 зрителей — это 5 энкодеров или один поток на всех?
   Ответ есть в `apps/desktop/src-tauri/src/view.rs`; если на каждого свой
   конвейер, то поднимать лимит без замера нельзя — замерь CPU и RSS на
   максимуме и сверься с `ci/resource-budget.yml`.

### Чего НЕ делать

- Не снимать лимит совсем и не делать его настройкой в интерфейсе: это
  лицензионная величина.
- Не ослаблять правило одного контроллера.
- Не менять `TRIAL_SESSION_LIMIT_SECS` заодно.

## Definition of done

- Два ADR (или один с двумя разделами), каждый отменяет прежнее решение явно.
- `cargo test --workspace` зелёный: тесты хранилища истории, тесты лимита
  гостей, тест «история выключена — на диске ничего не появилось».
- `cargo clippy --workspace --all-targets -- -D warnings` — чисто.
- `cd apps/desktop && npm run typecheck && npm test` — зелёное.
- Ручная проверка: с выключенной настройкой файла истории не появляется;
  с включённой — переписка переживает перезапуск, кнопка стирания стирает,
  срок хранения соблюдается.
- Замер на максимальном числе гостей — в отчёте.
