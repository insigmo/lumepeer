# 17 — Удалённый терминал

**Пункт бэклога:** 22. **Зависит от:** `16` (образец четвёртого канала и
шаблон «новый ALPN + новый грант»; если `16` не делается, всё равно читать
её как образец). **Нужно:** две машины, все три ОС для проверки.

Терминал — это выполнение команд на чужой машине от имени её пользователя.
По последствиям это сильнее, чем `input`: там гость хотя бы виден на экране.

## Что уже есть (проверено по коду)

- Гранты и правило «`match` без `_`» — `crates/core/src/consent.rs`.
- Шаблон нового канала — `ALPN_FILE` в `crates/net/src/endpoint.rs`,
  ленивый подъём (ADR 0032).
- Аудит — `crates/core/src/audit.rs`.
- Клиент на Windows **уже запускается с правами администратора**
  (`requireAdministrator` в `apps/desktop/src-tauri/build.rs`, ADR 0057) —
  значит терминал по умолчанию окажется административным. Это надо решить
  явно, а не унаследовать молча.

## Задача 1 — ADR: что именно разрешается

1. Новый независимый грант `terminal`, только с `Role::FullControl`,
   отзывается отдельно, перепроверяется при **каждом** открытии сессии
   оболочки.
2. Уровень прав: терминал запускается от **интерактивного пользователя**
   хоста, а не от процесса Lumepeer. На Windows это означает явное понижение
   до пользователя рабочего стола; унаследовать администратора нельзя.
   Если понижение невозможно — терминал не открывается и честно об этом
   сообщает (§18).
3. Пока терминал открыт, у хоста висит **неснимаемый** индикатор — как
   баннер unattended (ADR 0033). Тихого терминала быть не должно.

## Задача 2 — канал и сообщения

**Файлы:** `crates/net/src/endpoint.rs`, `crates/net/src/connection.rs`,
`crates/core/src/protocol.rs`

`ALPN_TERMINAL = "rd/term/1"`, `Channel::Terminal`, ленивый подъём.
Сообщения управляющего канала: `TerminalOpenRequest { cols, rows }`,
`TerminalOpenResponse { session_id, accepted, reason }`,
`TerminalResize { session_id, cols, rows }`, `TerminalClose { session_id }` —
в конец, `PROTOCOL_MINOR` +1, `FEATURE_TERMINAL`, проверки длин.
Байты ввода-вывода — по `rd/term/1`.

## Задача 3 — PTY на хосте

**Файл:** `crates/media`? Нет — новый модуль в `apps/desktop/src-tauri/src/`
или отдельный крейт `crates/terminal`. Выбери и обоснуй: код, который
порождает процессы, не должен жить в крейте про пиксели.

1. PTY: `ConPTY` на Windows, `openpty` на Unix. Кросс-платформенная обёртка
   (`portable-pty`) допустима — это новая зависимость, значит ADR-строка и
   `cargo deny` должны быть довольны.
2. Оболочка по умолчанию: `$SHELL` / `%COMSPEC%`; выбор оболочки гостем —
   **нет**, это ещё один способ обойти политику.
3. Потолки константами: число одновременных терминалов на сессию, размер
   буфера прокрутки, максимальный размер одного пакета вывода.
4. Закрытие: отзыв гранта, конец сессии, разрыв — процесс убивается, PTY
   освобождается. Осиротевших оболочек оставаться не должно; это проверяется
   тестом на Unix и вручную на Windows.

## Задача 4 — интерфейс

**Файлы:** `apps/desktop/src/terminal.ts` (новый) и тест к нему,
IPC-команды в трёх местах (`main.rs`, `build.rs`, `capabilities/`)

Простой терминал: вывод, ввод, изменение размера. Эмулятор ANSI брать
готовый (`xterm.js`) — писать свой нельзя. Все новые строки — в i18n во всех
локалях, axe-core зелёный.

## Задача 5 — аудит

Открытие терминала, его закрытие и причина закрытия — в аудит. **Содержимое
команд в аудит не пишется**: это переписка человека с машиной, а журнал у нас
принципиально обезличенный (§15, ADR 0041).

## Чего НЕ делать

- Не наследовать права администратора от процесса клиента.
- Не давать гостю выбирать исполняемый файл оболочки и её аргументы.
- Не писать команды и вывод в аудит и вообще на диск.
- Не подразумевать `terminal` из `input`.
- Не писать свой эмулятор терминала.
- Не делать «терминал до входа в систему» — это пачки `25`/`26`.

## Definition of done

- `cargo test --workspace` зелёный: отказ без гранта, убийство процесса при
  отзыве, отсутствие осиротевших PTY (Unix).
- Векторы новых сообщений дописаны в конец.
- `cargo clippy --workspace --all-targets -- -D warnings` — чисто.
- `cd apps/desktop && npm run typecheck && npm test` — зелёное.
- Ручная проверка на всех трёх ОС: терминал открывается от имени
  пользователя рабочего стола (проверить `whoami`), индикатор у хоста виден и
  не снимается, отзыв гранта закрывает терминал немедленно.
