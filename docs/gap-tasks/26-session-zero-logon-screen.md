# 26 — Доступ до входа: экран входа и смена сессий

**Пункт бэклога:** 11 (вторая половина). **Зависит от:** `25`.
**Нужно:** Windows-машина, которую можно перезагружать, блокировать,
переключать пользователей; лучше — с включённым RDP, чтобы проверить
несколько сессий.

## Что уже есть (проверено по коду)

- Служба уже умеет снимать кадр с `Winsta0\Winlogon` и вводить туда события
  (ADR 0056, 0057) — но по одному кадру за раз, через перезапуск воркера, с
  дросселем `SECURE_DESKTOP_CAPTURE_INTERVAL_MS` (константа используется в
  `apps/desktop/src-tauri/src/view.rs`).
- Известная история: гости не могли нажать UAC у хоста, потому что признак
  «сейчас secure desktop» мерцал (500 мс дросселя против цикла 33 мс) —
  починено защёлкой. Тот же класс ошибки ждёт здесь: **состояние сессии
  меняется медленнее, чем цикл захвата**, и любое «спросить прямо сейчас»
  будет мигать.
- Гранты `secure_desktop` и `secure_desktop_input` уже существуют и уже
  независимы (ADR 0056, 0061).
- `ViewStatus` умеет говорить `secure-desktop` и `no-capture` — гость
  показывает состояние, а не замерший кадр.

## Задача 1 — экран входа как обычная цель захвата

**Файлы:** `crates/service/src/secure_desktop.rs`, `secure_desktop_launch.rs`,
новый агент из пачки `25`

1. Пока никто не вошёл, «активная сессия» — это Winlogon. Захват должен идти
   **потоком**, а не одиночными кадрами: воркер, живущий, пока идёт сессия, а
   не перезапускаемый на кадр. Одиночный кадр остался от сценария UAC, где
   он был уместен.
2. Частота на экране входа может быть низкой (там ничего не движется) — но
   это осознанная константа, а не унаследованный дроссель.
3. Ввод на экран входа — существующим путём воркера ввода, под грантом
   `secure_desktop_input`.

## Задача 2 — переходы между сессиями

**Файлы:** служба (обработчик `SERVICE_CONTROL_SESSIONCHANGE`), агент

1. Подпишись на уведомления смены сессии: вход, выход, блокировка,
   разблокировка, быстрое переключение пользователей, подключение и
   отключение RDP.
2. На каждый переход: старый агент гасится, новый запускается в новой
   активной сессии, поток захвата перецепляется. Сессия гостя при этом
   **не прерывается** и гранты не меняются.
3. Состояние на время перехода — честное («переключение сессии»), а не
   последний кадр старой сессии. Последний кадр чужой сессии показывать
   после смены пользователя категорически нельзя: это чужой экран.
4. Применить приём защёлки: состояние переключения удерживается до
   подтверждённого нового состояния, а не читается на каждом тике.

## Задача 3 — раскрытие, когда смотреть некому

1. Вход без человека — событие аудита с явным типом (не тем же, что обычный
   вход).
2. Как только кто-то входит в систему при живой сессии — неснимаемый баннер,
   как у unattended (ADR 0033). Человек, севший за машину, обязан узнать, что
   его экран уже показывают, **до** того как он что-то напечатает.
3. Никакой возможности выключить этот баннер из гостевой стороны.

## Задача 4 — что делать с несколькими сессиями сразу

Активная консольная сессия одна, но RDP-сессий может быть несколько.
В этой пачке: обслуживаем **только активную консольную**; остальные —
честное «эта сессия не обслуживается». Многосессионность — отдельное
решение и отдельный ADR; не делать её тут молча.

## Чего НЕ делать

- Не показывать кадр чужой сессии после переключения пользователя.
- Не оставлять «последний хороший кадр» как заглушку ни в одном переходе.
- Не расширять `secure_desktop_input` до «можно всё, раз мы уже SYSTEM».
- Не обслуживать RDP-сессии наравне с консольной без отдельного ADR.
- Не убирать баннер и не делать его снимаемым.
- Не менять поведение обычного (не служебного) режима хоста.

## Definition of done

- `cargo clippy --workspace --all-targets -- -D warnings` — чисто.
- `cargo test --workspace` не хуже базового прогона; тесты — на конечный
  автомат переходов сессии (юнит, без Windows).
- На настоящей машине проверено по шагам: подключение к машине, где никто не
  вошёл → виден экран входа → введены логин и пароль → сессия продолжается,
  виден рабочий стол → блокировка → разблокировка → быстрое переключение
  пользователя → выход. На каждом шаге у гостя честное состояние, ни одного
  чужого кадра.
- Баннер появляется, когда человек входит в систему при живой сессии.
- События в аудите на каждый вход без человека.
