# 02 — macOS: воспроизведение звука

**Пункт бэклога:** 6. **Зависит от:** `01` (общая фича и опыт с
ScreenCaptureKit; формально можно и параллельно, но конфликт в
`Cargo.toml` гарантирован). **Нужно:** живой Mac с наушниками или колонками.

## Что уже есть (проверено по коду)

- `crates/media/src/playout.rs` — трейт `AudioPlayer`, WASAPI-бэкенд для
  Windows, PipeWire-бэкенд для Linux (`linux_pipewire`, фича
  `audio-capture-pipewire` — та же, что несёт захват, потому что это один
  набор биндингов).
- `platform_player()` (~стр. 105): на macOS возвращает
  `MediaError::CaptureUnavailable("no audio playback backend is compiled in
  for this target")`.
- Обратная конвертация из проводного формата в формат устройства уже написана
  в этом же файле, платформонезависима и всегда тестируется.
- Форма бэкенда, которую надо повторить: `start` открывает устройство вывода
  по умолчанию на его собственной частоте, `push` принимает **один** чанк
  проводного формата (48 кГц s16 стерео) и конвертирует, `stop` освобождает.
  `push` блокирующий, с таймаутом — см. `PLAYBACK_TIMEOUT` в
  Windows-бэкенде.

## Задача 1 — CoreAudio-бэкенд

**Файл:** `crates/media/src/playout.rs` (новый модуль внутри него, как
`linux_pipewire`)

1. Открывай устройство вывода по умолчанию (`AudioUnit` с
   `kAudioUnitSubType_DefaultOutput`, либо `AudioQueue` — выбери одно и
   объясни выбор в комментарии). Частоту устройства не навязывай: спроси и
   конвертируй под неё существующим кодом.
2. Тишина в чанке — это настоящая тишина, а не пропуск: разрывы в часах
   отправителя не должны давать щелчки. Это уже так в других бэкендах,
   повтори поведение.
3. Подключи в `platform_player()` новой `cfg`-веткой. Ветка «нет бэкенда»
   остаётся для сборок без фичи.
4. Фича: если для CoreAudio нужны новые зависимости — новая фича
   `audio-playout-coreaudio` в `crates/media/Cargo.toml` по образцу соседних
   плюс проброс и запись в `[target.'cfg(target_os = "macos")'.dependencies]`
   `apps/desktop/src-tauri/Cargo.toml` и в обе macOS-строки
   `.github/workflows/release.yml`. Если новых зависимостей нет (bindings уже
   в дереве через `objc2-*`) — фичу не плодить, объяснить в комментарии.

## Задача 2 — тесты конвертации

**Файл:** тот же

Конвертация всегда тестируется вне зависимости от платформы — добавь случаи
для частот, которые реально отдают macOS-устройства (44 100 и 48 000), в том
же стиле, что существующие тесты. Тесты самого устройства не писать: в CI
Mac-раннера с аудиовыходом нет.

## Чего НЕ делать

- Не писать второй ресемплер: конвертер в этом файле один и он общий.
- Не менять трейт `AudioPlayer` и его контракт «один чанк за вызов».
- Не трогать Windows- и Linux-бэкенды.
- Не пытаться сделать «микшер»: одна сессия — один поток воспроизведения.
- Не включать фичу в `default`.

## Definition of done

- `cargo clippy -p lumepeer-media --all-targets --features capture-screencapturekit,encode-openh264 -- -D warnings` — чисто, с добавленной фичей воспроизведения тоже.
- `cargo build --workspace` без платформенных фич собирается.
- `cargo test -p lumepeer-media` зелёный, включая новые тесты конвертации.
- На живом Mac: микрофон гостя слышен на хосте, звук хоста слышен у гостя
  (последнее — вместе с пачкой `01`), при завершении сессии устройство
  освобождается (проверить, что второй запуск сессии снова даёт звук).
