# Пачки закрытия пробелов (вторая волна)

Продолжение `docs/tasks/`. Нумерация здесь своя (`01`…`30`) и с номерами
первой волны не пересекается — на неё ссылаются как «gap-tasks/07».

Каждый файл — **одна сессия одного агента**: связанные правки в одних и тех
же файлах, один прогон проверок, один PR. Внутри файла задачи идут по
порядку и опираются друг на друга — не переставлять.

Источник номеров пунктов — `docs/gap-backlog.md`. В заголовке каждой пачки
указано, какие пункты бэклога она закрывает.

Документы на русском. Весь код, идентификаторы, комментарии в коде, имена
файлов, сообщения коммитов и ADR — **на английском**, как весь остальной
репозиторий. Трейлеры в коммитах (`Co-Authored-By`, «Generated with…») в
этом репозитории не ставятся.

---

## Обязательно к прочтению перед любой пачкой

1. `docs/tasks/README.md` — разделы «Обязательно к прочтению» и «Правила,
   нарушение которых заворачивает работу». Всё оттуда действует и здесь; ниже
   только добавления.
2. Раздел «Ground rules» в корневом `README.md`.
3. Профильный ADR из `docs/adr/`. Если поведение выглядит намеренным — оно
   намеренное; менять его без ADR нельзя.
4. Сам код по путям, указанным в пачке. **Не доверять описанию слепо**: пути
   и имена функций надёжны, номера строк — ориентир, репозиторий живёт.

## Правила, нарушение которых заворачивает работу

Сверх правил `docs/tasks/README.md`:

- **`crates/core` — единственная точка авторизации.** Новая возможность,
  которую гость может использовать против хоста, — это новый
  `IndependentGrant` в `crates/core/src/consent.rs`, а не проверка в UI или в
  `apps/desktop/src-tauri`. Добавление варианта требует правки `Grants`,
  `Grants::get`, `Grants::set`, `Grants::from_role` (там `match` без `_`-ветки
  намеренно) и ADR.
- **Протокол растёт только в хвост.** Новый `MessageKind` дописывается в
  конец перечисления, `PROTOCOL_MINOR` увеличивается на 1, в doc-комментарий
  к нему добавляется абзац по образцу соседних, и сообщение отправляется
  только пиру, чей `Hello` объявил соответствующую `FEATURE_*`-строку.
  Переставить или вставить в середину — сломать замороженные векторы
  `tests/interop/golden_vectors.txt`; это дефект, а не «обновление теста».
- **Новая IPC-команда Tauri регистрируется в трёх местах:**
  `invoke_handler` в `apps/desktop/src-tauri/src/main.rs`, массив `COMMANDS`
  в `apps/desktop/src-tauri/build.rs` и соответствующий файл в
  `apps/desktop/src-tauri/capabilities/` (`main.json`, `view.json` или
  `hostbar.json`). Забыть `build.rs` — получить команду, которая не
  вызывается, без ошибки компиляции. Если правишь `capabilities/main.json`,
  правь и `capabilities-pilot/main.json`.
- **Новое хранилище на диске получает путь через `ActorStores`**
  (`apps/desktop/src-tauri/src/network.rs`), как `history_path`,
  `address_book_path`, `invite_path`. Захардкоженный путь означает, что все
  тестовые акторы пишут в один настоящий файл пользователя.
- **Никаких магических чисел.** Любая новая величина — `pub const` в
  `crates/core/src/constants.rs` с doc-комментарием и ссылкой на § или ADR.
- **Никаких паник на недоверенном вводе** в `crates/core`, `crates/net` и на
  любых путях разбора. Возвращай `CoreError`/`NetError`.
- **Не удалять существующие пути.** Новый транспорт, новый кодек, новый
  бэкенд добавляются рядом со старым и включаются по фиче или по
  согласованию, а не вместо него.
- **Отклонение от плана — ADR.** Следующий свободный номер берётся так (не по
  листингу каталога — номера бывают заняты только ссылкой из кода):

  ```sh
  grep -rho "ADR 0[0-9][0-9][0-9]" crates apps docs --include=*.rs --include=*.md | sort -u | tail -3
  ls docs/adr | tail -3
  ```

## Проверка перед завершением любой пачки

Сборка webview обязательна до любой cargo-команды, трогающей `apps/desktop`:
`tauri-build` читает `frontendDist` во время компиляции.

```sh
cd apps/desktop && npm install && npm run build && cd -
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Если трогал TypeScript:

```sh
cd apps/desktop && npm run typecheck && npm test && cd -
```

Если трогал платформенные бэкенды media — прогнать те наборы фич, которые
реально едут в релиз (`.github/workflows/release.yml`, матрица `build`):

```sh
cargo clippy -p lumepeer-media --all-targets --features capture-x11,capture-portal,encode-openh264,audio-opus,audio-capture-pipewire -- -D warnings
cargo clippy -p lumepeer-media --all-targets --features capture-windows,encode-mf,encode-openh264 -- -D warnings
cargo clippy -p lumepeer-media --all-targets --features capture-screencapturekit,encode-openh264 -- -D warnings
```

### Известные ловушки прогона (не чинить, не пугаться)

- **`cargo test --workspace` на Windows-машине с установленной службой
  `LumepeerHelper` красный и без твоих правок.** Сначала зафиксируй базовый
  прогон на чистом дереве, сравнивай с ним, а не с нулём.
- **Плоский `cargo test` собирает `apps/desktop/src-tauri` без единого
  capture-бэкенда**, и тесты про мониторы/захват молча уходят в
  деградированную ветку. Тест, который должен что-то доказать про захват,
  обязан требовать фичу.
- **На Windows тестовый бинарь десктоп-крейта наследует манифест
  `requireAdministrator`** (`apps/desktop/src-tauri/build.rs`) и падает с
  `os error 740`. Запускать с `__COMPAT_LAYER=RunAsInvoker`.
- **Два процесса Lumepeer на одном рабочем столе не живут** (плагин
  single-instance). Для ручной проверки «хост + гость» нужны две машины или
  ВМ.
- **Рабочая копия в CRLF.** Правки скриптом (`sed`, heredoc) обязаны быть
  CRLF-совместимыми: якорь с одним `\n` не совпадёт.
