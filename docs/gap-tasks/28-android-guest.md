# 28 — Android-клиент (гость) - временно снят - не делать, даже если попросят

**Пункт бэклога:** 1. **Зависит от:** `27`. **Нужно:** Android-устройство с
Android 11+, Android SDK/NDK, машина-хост для проверки.

Только **гость**: смотреть чужой экран и управлять им с телефона. Отдача
экрана телефона — пачка `30`.

## Что уже есть (проверено по коду)

- `apps/desktop/src-tauri` — Tauri v2 (`tauri = { version = "2", features =
  ["tray-icon"] }`), **только `[[bin]]`**, никакой библиотечной цели и
  никакой мобильной точки входа. Плагины `single-instance`, `updater`,
  `dialog`, иконка в трее — всё это про рабочий стол.
- Гостевая логика — в `crates/client` после пачки `27`.
- Декодирование у гостя происходит **в webview** через `VideoDecoder`
  (ADR 0058), `apps/desktop/src/view-decoder.ts`; строка кодека выводится из
  потока, поддержка спрашивается у браузера. В Android WebView (Chromium)
  `VideoDecoder` есть — но проверить это надо на устройстве, а не поверить.
- Ввод: гость шлёт `InputEventPayload`; аккорд клавиш — позиция, а не символ
  (ADR 0065), `names_a_key` и таблица `NAMED_KEYS` в `view-window.ts`.
- Размер картинки называет гость (`StreamSizeRequest`, ADR 0060) — для
  телефона это критично: просить надо размер экрана телефона, а не хоста.

## Задача 1 — отдельное приложение, а не мобильная сборка десктопного

**Файлы:** `apps/mobile/` (новое), `Cargo.toml` (член workspace)

1. Отдельное Tauri-приложение с библиотечной целью и
   `#[cfg_attr(mobile, tauri::mobile_entry_point)]`. Пытаться собрать
   `apps/desktop` под Android — тупик: трей, single-instance, updater и
   `requireAdministrator` там неотделимы.
2. Общий фронтенд: окно просмотра, декодер и тулбар переиспользуются из
   `apps/desktop/src` (общая папка или пакет), а не копируются. Копия
   `view-decoder.ts` разойдётся с оригиналом за один релиз.
3. Список IPC-команд свой и **меньше** десктопного: ни трея, ни службы, ни
   автозапуска. Регистрация — те же три места (`invoke_handler`, `COMMANDS`
   в `build.rs`, `capabilities/`).

## Задача 2 — то, чего на телефоне нет

Пройди список и реши каждое явно:

| Что | Решение |
|---|---|
| Keystore | Android Keystore через плагин либо зашифрованный файл в приватном каталоге приложения. Ключи в `SharedPreferences` — нет. |
| Буфер обмена | Системный Android-буфер; гранты те же, поведение то же. |
| Файлы | Storage Access Framework; произвольных путей нет. |
| Инвайт по QR | Камера — это как раз то, ради чего QR и заводили (§7). |
| Фон | Сессия в фоне живёт только под foreground service с уведомлением. Без него Android убьёт процесс, и «сессия молча умерла» — худший вариант. |
| Батарея и сеть | Смена Wi-Fi ↔ мобильная сеть = смена адреса. Проверить, что переподключение отрабатывает (`reconnect.rs`, окно 60 с). |

## Задача 3 — ввод пальцем

1. Касание — это не мышь. Нужны: перемещение курсора относительным
   свайпом, тап = левая кнопка, долгое нажатие = правая, два пальца =
   прокрутка, щипок = масштаб **картинки** (а не удалённого экрана).
2. Экранная клавиатура: модификаторы (Ctrl, Alt, Win) — залипающие кнопки в
   тулбаре, потому что физических у пользователя нет. Правило «аккорд — это
   позиция» (ADR 0065) обязано соблюдаться и здесь.
3. Ничего из этого не должно требовать изменений в `crates/core`: если
   потребовалось — значит протёк слой ввода, и это дефект.

## Задача 4 — сборка

1. `cargo tauri android init`, конфигурация подписи для отладочной сборки,
   инструкция в `docs/`.
2. В релизную CI **не** добавлять, пока нет решения про подпись и
   распространение (магазин или APK).

## Чего НЕ делать

- Не собирать десктопное приложение под Android.
- Не копировать `view-decoder.ts` и `view-window.ts`.
- Не реализовывать роль хоста (пачка `30`).
- Не менять протокол: телефон — обычный гость, никаких «мобильных
  сообщений».
- Не просить у пользователя разрешений, которые не нужны прямо сейчас
  (камера — только при сканировании QR).
- Не тащить приложение в магазин в рамках этой пачки.

## Definition of done

- `cargo tauri android build --debug` проходит; APK ставится на устройство.
- На устройстве: подключение по QR-коду и по коду вручную, согласие на
  хосте, картинка, звук, ввод пальцем, клавиатура, отзыв гранта виден
  сразу.
- `VideoDecoder` в Android WebView проверен на реальном устройстве; если его
  нет — сессия честно сообщает об этом (§18), а не показывает чёрный экран.
- Сессия переживает сворачивание приложения и смену сети.
- `cargo clippy --workspace --all-targets -- -D warnings` и
  `cargo test --workspace` — не хуже базового прогона.
- Десктопное приложение не изменилось (проверить сборку и один сценарий).
