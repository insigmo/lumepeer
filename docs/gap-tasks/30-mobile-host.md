# 30 — Мобильный хост: отдача экрана с телефона - временно снят - не делать, даже если попросят

**Пункт бэклога:** 3. **Зависит от:** `28`. **Нужно:** Android-устройство
(Android 10+), машина как гость.

**Область сужена намеренно: только Android и только просмотр.** Обоснование —
в задаче 0; iOS-хост в эту пачку не входит и, вероятно, не войдёт никогда.

## Задача 0 — что физически возможно (прочитать до кода)

- **Захват экрана Android** — `MediaProjection`. Требует явного согласия
  пользователя в системном диалоге на **каждую** сессию захвата, и это
  ровно та модель согласия, которая у нас уже принята (§8.1: нет скрытого
  захвата). Диалог обойти нельзя и не нужно.
- **Ввод в чужие приложения на Android** обычному приложению недоступен.
  Пути только два: `AccessibilityService` (пользователь включает вручную в
  системных настройках; политика Google Play к такому применению
  враждебна) или системная подпись/root. Значит **Android-хост — view-only**,
  а грант `input` для него просто недоступен, и это надо честно показать
  гостю (§18), а не молча игнорировать события.
- **iOS-хост** — ReplayKit broadcast extension: отдельный процесс, жёсткий
  лимит памяти, никакого ввода вообще, и всё это только через App Store.
  В этой пачке — отказ, оформленный ADR, а не «сделаем потом».

Если человек, запустивший пачку, ждал полноценного управления телефоном —
остановись и скажи об этом до начала работы.

## Что уже есть (проверено по коду)

- Трейт `ScreenCapturer` (`crates/media/src/capture/mod.rs`): `start(target)`,
  следующий кадр или `None`, если картинка не изменилась; `Frame { width,
  height, format, timestamp_us, data }`, `PixelFormat { Bgra8, Nv12 }`.
- `InputCapability { Full, PortalRemoteDesktop, None }` — **`None` уже
  существует** и означает «инъекции нет, сессия честно деградирует до
  просмотра» (§18). Это готовый ответ для Android.
- `host_monitors()` — на Android его нет; телефон отдаёт ровно один «экран».
- Энкодер: аппаратный на Android — это `MediaCodec`; в
  `crates/media/src/encode/mod.rs` он назван как незакрытая работа наравне с
  VideoToolbox.
- Хостовая половина логики после пачки `27` живёт в `crates/client`.

## Задача 1 — захват

**Файлы:** `crates/media/src/capture/android.rs` (новый), `capture/mod.rs`,
`crates/media/Cargo.toml`, `apps/mobile/`

1. Фича `capture-android-mediaprojection`, инертна вне Android.
2. Реализация `ScreenCapturer` поверх `MediaProjection` + `ImageReader`;
   формат кадра — тот же, что у остальных бэкендов.
3. Согласие системы запрашивается при старте захвата и **вместе** с грантом
   `view`, а не заранее «на всякий случай».
4. Отзыв гранта или отзыв системного разрешения — оба останавливают захват
   немедленно.

## Задача 2 — энкодер

**Файл:** `crates/media/src/encode/android_mediacodec.rs` (новый)

`MediaCodec` в аппаратном режиме, H.264, честная проба по образцу
`windows.rs`/`linux_vaapi.rs` — активировать, скормить кадр, только потом
`Hardware`. Программный `openh264` на телефоне — запасной путь, но помни про
батарею: если аппаратного нет, разумнее отказаться от роли хоста, чем греть
устройство.

## Задача 3 — ввод, которого нет

1. `InputCapability::None` для Android-хоста.
2. Гость видит явное «этот хост не принимает управление» — существующий
   механизм честной деградации, не новое сообщение протокола.
3. `AccessibilityService` в этой пачке **не** реализуем.

## Задача 4 — жизненный цикл

Захват в фоне — только под foreground service с постоянным уведомлением.
Уведомление здесь не формальность: это и есть неснимаемое раскрытие того, что
экран показывают, — прямой аналог баннера у настольного хоста.

## Чего НЕ делать

- Не реализовывать ввод через `AccessibilityService`.
- Не делать iOS-хост.
- Не пытаться захватывать экран без системного диалога.
- Не прятать уведомление foreground service.
- Не менять протокол ради мобильного хоста: он обычный хост, просто без
  `input`.
- Не добавлять `host_monitors()` с фиктивным содержимым — телефон честно
  отдаёт один экран.

## Definition of done

- ADR: Android-хост только для просмотра; iOS-хост — отказ с обоснованием.
- `cargo clippy -p lumepeer-media --all-targets --features capture-android-mediaprojection -- -D warnings` — чисто (на кросс-цели).
- `cargo build --workspace` без фич — как раньше.
- На устройстве: гость с настольной машины видит экран телефона; системный
  диалог MediaProjection показан; уведомление висит всю сессию; отзыв
  `view` гасит захват мгновенно; попытка управления даёт гостю честное
  сообщение.
- Замер: нагрев и расход батареи за 10 минут сессии — в отчёт.
