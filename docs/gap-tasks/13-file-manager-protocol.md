# 13 — Файловый менеджер: протокол и ядро

**Пункт бэклога:** 19 (первая половина). **Зависит от:** ничего.
**Нужно:** ничего (всё локально и в тестах).

Сегодня файл можно **предложить** — и всё. Просмотреть удалённую файловую
систему нельзя, потому что таких сообщений нет.

## Что уже есть (проверено по коду)

- Протокол (`crates/core/src/protocol.rs`): `FileOffer { name, size, … }`,
  `FileAccept(bool)`, `FileAbort { transfer_id }`,
  `FileChunkAck { transfer_id, … }`, `FileTransferStart { name, size, … }`,
  плюс `ClipboardFileOffer`/`ClipboardFileAccept` (ADR 0047). Листинга
  каталогов нет ни в каком виде.
- `crates/net/src/file_transfer.rs` (899 строк): `ReceiveTracker`,
  `StagedReceive`, `safe_file_name`, формат чанка
  `u64_be transfer_id || u64_be offset || u32_be len || bytes`, проверка
  длины до аллокации, BLAKE3 проверяется только когда все байты пришли,
  ничего не покидает staging до совпадения хеша.
- Соединение `rd/file/1` поднимается **лениво**, только после
  `FileAccept(true)` (ADR 0032) — так отзыв гранта не может быть задержан
  передачей.
- Константы: `FILE_CHUNK_MAX_BYTES = 256 KiB`,
  `MAX_CONCURRENT_FILE_TRANSFERS = 3`, `FILE_OFFER_MAX_BYTES = 500 MiB`,
  `FILE_NAME_MAX_BYTES = 255`, `MAX_PENDING_FILE_OFFERS = 3`.
- Гранты: `file_transfer` — независимый флаг в `crates/core/src/consent.rs`.

## Задача 1 — ADR: обзор чужого диска это отдельное разрешение

Обоснуй и зафиксируй: `file_transfer` разрешает **обмен предложенными
файлами**, а перечисление содержимого диска — строго больше этого. Значит
новый независимый грант `file_browse`:

- не подразумевается ни `view`, ни `input`, ни `file_transfer`;
- приходит только с `Role::FullControl` (ADR 0054: полный контроль несёт все
  независимые гранты) и отзывается отдельно;
- без него сервер листинга отвечает отказом, а не пустым списком.

## Задача 2 — грант

**Файл:** `crates/core/src/consent.rs` (+ тесты там же)

Добавь `file_browse` в `Grants`, вариант в `IndependentGrant`, ветки в
`get`/`set` (там `match` без `_` — намеренно) и значение в `from_role`.
Тест: `ViewOnly` и `ControlLimited` его не получают, `FullControl` получает,
`set` снимает его, не трогая остальные.

## Задача 3 — сообщения

**Файл:** `crates/core/src/protocol.rs`

1. `DirListRequest { path: String }` и `DirListResponse { entries:
   Vec<DirEntry>, truncated: bool }`, где `DirEntry { name, size, is_dir,
   modified_unix }`. Дописать **в конец** перечисления, `PROTOCOL_MINOR` +1,
   абзац в doc-комментарий по образцу.
2. Новая строка `FEATURE_FILE_BROWSE = "file-browse"`; сообщения уходят
   только пиру, который её объявил.
3. Новые потолки — константами в `crates/core/src/constants.rs`:
   максимум записей в одном ответе (по образцу `MAX_DISPLAY_MODES_PER_HOST`),
   максимум длины пути. Ответ, упершийся в потолок, ставит `truncated: true`
   — не молча обрезает.
4. Проверки в `MessageEnvelope::decode` для новых сообщений — по образцу
   соседних (длина имени, число записей).

## Задача 4 — разбор пути и отказ

**Файлы:** `crates/core/src/` (новый модуль или рядом с `clipboard.rs`),
`crates/net/src/file_transfer.rs`

1. Путь из сети — недоверенный ввод. `..`, симлинки наружу, UNC-пути,
   `\\?\`, устройства Windows (`CON`, `NUL`) — всё отвергается. Уже
   существующая `safe_file_name` покрывает **имя**, но не путь: напиши
   разбор пути в том же духе и покрой тестами так же плотно.
2. Отказ в доступе от ОС — это `DirListResponse` с пустым списком **и**
   явным признаком отказа, а не паника и не тишина.
3. Никаких `unwrap` на этом пути.

## Задача 5 — обработчик на хосте

**Файл:** `apps/desktop/src-tauri/src/network.rs`

1. Обработка `DirListRequest`: проверить грант `file_browse` **в момент
   запроса** (не в момент выдачи — как каждое событие ввода), проверить путь,
   прочитать каталог, ответить.
2. Каждый листинг — запись в аудит (`crates/core/src/audit.rs`), как и
   прочие действия гостя. Пир — только солёным хешем.
3. Отзыв гранта посреди листинга: следующий запрос уже получает отказ.

## Чего НЕ делать

- Не давать листинг по гранту `file_transfer` «чтобы не плодить гранты».
- Не открывать соединение `rd/file/1` ради листинга: он идёт по управляющему
  каналу, как всё остальное.
- Не делать рекурсивный обход по одному запросу: один запрос — один каталог.
- Не отдавать в листинге ничего, кроме имени, размера, флага каталога и
  времени: атрибуты, владелец и права — это лишняя информация о машине.
- Не делать UI в этой пачке (пачка `14`).
- Не трогать существующий путь оффера и его тесты.
