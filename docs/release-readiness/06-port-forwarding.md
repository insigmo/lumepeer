# 06 — Проброс портов: доделать интерфейс или убрать

**Правка из аудита, нужно решение владельца ДО начала.** **Зависит от:**
ответа владельца. **Конфликты:** вариант А — `session-status.ts` (пачка 03),
`toolbar.ts` (02, 07); оба варианта — текст окна согласия (пачка 04).

## Что есть (проверено 2026-11-08 на `b97a6c9`)

- Механизм готов и протестирован в Rust: ADR 0078 «a tunnel is a grant plus an
  address the host named», задание `docs/gap-tasks/16-tcp-tunnel.md`, ALPN
  `rd/tunnel/1`, `crates/net/src/tunnel.rs`.
- **Хост:** `apps/desktop/src/tunnels.ts` — `tunnelPanel` (около строки 86):
  список адресов, которые хост разрешил (`tunnel_set_target`), и «закрыть все»
  (`tunnel_close_all`). **Никто его не импортирует**, кроме
  `tunnels.test.ts`. IPC `tunnel_status` (`commands.rs` около строки 3759,
  «Host side … a tunnel shows up on the row of the session carrying it»)
  интерфейс не вызывает.
- **Гость:** IPC `tunnel_open` (`commands.rs` около строки 3673, «Guest side:
  forwards a local port to an address on the watched host») — вызова в
  интерфейсе нет совсем.
- Право `tunnel` молча входит в «полное управление» (`Grants::from_role`,
  `crates/core/src/consent.rs`). Само по себе оно **ничего не открывает**:
  хост должен назначить адрес, а по умолчанию не назначено ничего (ADR 0078).
  Поэтому сейчас это мёртвая функция, а не дыра.

## Вопрос владельцу

Нужен ли проброс портов в первом выпуске (сценарий техника: зайти на
веб-интерфейс роутера или RDP в сети клиента)?

## Вариант А — доделать

1. **Хост.** Подключить `tunnelPanel` к строке сессии в главном окне
   (`session-status.ts`): разрешённые адреса для этого гостя, живые туннели
   из `tunnel_status` (трафик, число соединений), кнопка «закрыть все».
   Удаление адреса — через `askFirst`.
2. **Гость.** В окне просмотра (меню тулбара или отдельный пункт) — «Проброс
   порта»: адрес на стороне хоста (из разрешённых хостом, если протокол их
   отдаёт; иначе ввод `host:port`, проверка через `parseAddress` из
   `tunnels.ts`), локальный порт, кнопка открыть → `tunnel_open`. Показать
   адрес `127.0.0.1:<порт>`, к которому подключаться, и как закрыть.
3. Тексты во все 13 словарей, тесты на обе стороны, axe.
4. Окно согласия (пачка 04) упоминает проброс в списке полного управления.
5. Проверка на живой паре: гость открывает туннель к веб-странице в сети
   хоста, хост видит его в строке сессии и закрывает. Это двухмашинная
   проверка — стенд описан в памяти проекта (e2e matrix, pilot).

## Вариант Б — убрать

1. `Grants::from_role`: `tunnel: false` для всех ролей. Это правка
   авторизации в `crates/core` — нужен ADR (поправка к ADR 0078), тесты
   `consent.rs` и `tests/integration`.
2. `tunnels.ts` и `tunnels.test.ts` удалить; ключи `tunnel.*` из 13 словарей
   и `i18n.ts`.
3. IPC-команды туннеля: оставить в Rust (механизм рабочий, вернётся) или
   убрать из `main.rs`/`build.rs` `COMMANDS`/capabilities. Предпочтительно
   оставить команды, но не выдавать право: меньше правок, легко вернуть.
4. Маркетинговые и справочные тексты не обещают проброс
   (`grep -rni "tunnel\|port forward" docs/ README*`).

## Приёмка

- А: туннель открывается и закрывается из интерфейса на обеих сторонах, на
  живой паре.
- Б: сессия с полным управлением не получает `tunnel` (тест), в интерфейсе и
  документах нет упоминаний проброса.
