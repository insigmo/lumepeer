# 04 — Окно согласия говорит правду о «полном управлении»

**Риск безопасности из аудита.** **Зависит от:** ничего. Если пачка 06 решит
перестать выдавать `tunnel` с полным управлением — список в этом окне
поправить вместе с ней.

## Что есть (проверено 2026-11-08 на `b97a6c9`)

- `apps/desktop/src/locales/en.ts` около строк 7–8, `consent.request.body`:
  «Granting view lets them see this screen. Input, clipboard, files and
  recording stay off until you enable each one separately.»
- **Отдельных переключателей нет.** `session-status.ts`, комментарий у
  `setGrant` (около строки 327): «The host no longer has a switch per grant: a
  session starts with exactly what its role brings (`Grants::from_role`)».
  Единственное место, где хост сам меняет право, — согласие на запись.
- `crates/core/src/consent.rs`, `Grants::from_role` (около строк 224–252):
  `FullControl` включает `input`, `clipboard_read`, `clipboard_write`,
  `file_transfer`, `file_browse`, `recording`, `display_mode`, `tunnel`
  (адресов не открывает, пока хост их не назначит, ADR 0078), `terminal`
  (оболочка интерактивного пользователя, ADR 0079), `secure_desktop_input`
  (клики и ввод в окне UAC, ADR 0061/0057) и `reboot` (ADR 0084).
  `secure_desktop` (видеть экран UAC) — у всех ролей.
- Кнопки окна — `apps/desktop/src/consent-dialog.ts` около строк 63–100:
  Deny, Allow terminal, Allow view only, Allow full control.

То есть одной кнопкой «Allow full control» выдаётся оболочка, перезагрузка,
ввод в окно администратора и файлы, а текст окна говорит обратное.

## Задача 1 — текст

**Файлы:** `locales/*.ts` (13), `i18n.ts`, `consent-dialog.ts`

1. Переписать `consent.request.body`: что даёт «только просмотр» (видеть
   экран, включая запросы UAC) и что даёт «полное управление».
2. Под кнопкой полного управления (или в теле окна) — короткий список того,
   что оно включает, словами человека, а не именами прав: управлять мышью и
   клавиатурой, в том числе в окнах администратора; открыть командную строку;
   перезагрузить или выключить компьютер (с предупреждением на экране);
   передавать файлы и просматривать папки; буфер обмена; записывать сессию;
   менять разрешение экрана. Проброс портов — только если пачка 06 его
   оставляет.
3. Список строится **из одного источника**, чтобы не разойтись с
   `from_role` снова: либо массив ключей рядом с `consent-dialog.ts` и тест,
   сверяющий его с полями `Grants` (через снимок IPC или явный перечень в
   тесте с комментарием «обновить вместе с `Grants::from_role`»), либо, если
   дешевле, Rust-тест, который перечисляет поля `Grants` и падает на новом
   поле, пока его не добавили в окно.
4. Ничего не обещать про «включить по одному» — такой возможности нет.

## Задача 2 — доступность

`consent-dialog.ts` уже проходит axe-core (`accessibility.test.ts`). Список —
обычный `<ul>` внутри описания окна (`aria-describedby`), чтобы экранный
диктор прочитал его до кнопок.

## Не делать

- Не добавлять переключатели прав в окно согласия. Это другое решение
  продукта (ADR про роли), не правка текста.
- Не менять `Grants::from_role`.

## Приёмка

- Текст окна не содержит обещания «enable each one separately» ни на одном из
  13 языков.
- Перечень для полного управления совпадает с `Grants::from_role`, и тест
  падает, если в `Grants` появилось право, которого нет в окне.
- Скриншот окна согласия в панели браузера (светлая и тёмная тема); axe
  зелёный.
