# Пачка 18 — контрольные точки уровня 2 и карантин

**Репозиторий:** lumepeer · **Зависит от:** 17 · **Нужно:** ВМ Windows (с
включённой и выключенной защитой системы), Linux-ВМ с btrfs + snapper
(например openSUSE или Fedora) и без них, Mac-ВМ. Только ВМ.

## Цель

Перед опасными изменениями — контрольная точка средствами ОС там, где они
реально есть, с проверкой, что она создана; восстановление к ней — отдельный,
явно предупреждающий путь. Подозрительные файлы — штатный антивирус и его
карантин, свой карантин — только перемещение с метаданными. После этой
пачки в каталог входят `dangerous`-действия с `undo: checkpoint`.

## Задачи

### 1. Обнаружение возможностей (в матрицу возможностей)

- **Windows**: включена ли защита системы на системном томе, есть ли
  точки, когда создана последняя; ограничение частоты создания
  (`SystemRestorePointCreationFrequency`, по умолчанию раз в 24 ч — проверить
  текущее поведение) — учитывать, а не обходить правкой реестра.
- **Linux**: корень на btrfs и настроен `snapper` / установлен `timeshift`
  (и в каком режиме); immutable-система (`rpm-ostree`) — свой механизм.
  Ничего нет → уровень 2 недоступен, так и показывается. LVM-снимки не
  делать.
- **macOS**: `tmutil localsnapshot` доступен; честные ограничения:
  снимок временный (система удаляет их), восстановление — только через
  Recovery / Time Machine, из работающего приложения не выполняется.

### 2. Действия

- `checkpoint.create` (`change`, `not_needed`): Windows — точка
  восстановления через WMI `SystemRestore.CreateRestorePoint`, затем
  **проверка по списку точек**, что новая появилась; если сработало
  ограничение частоты и есть точка, созданная до начала задачи, —
  использовать её (это всё ещё состояние «до»), иначе — сообщить, что
  точку создать нельзя. Включение защиты системы, если выключена, — не
  молча: отдельное предложение с объяснением (это само изменение
  системы). Linux — `snapper create` / `timeshift --create` через
  `pkexec`. macOS — `tmutil localsnapshot` с честным статусом
  «частичная».
- `checkpoint.restore` (`dangerous`): Windows — запуск восстановления к
  точке (`rstrui.exe` с выбором пользователя или PowerShell
  `Restore-Computer` — выбрать, обосновать), с перезагрузкой; Linux —
  `snapper rollback` / timeshift / `rpm-ostree rollback` по механизму;
  macOS — только инструкция (Recovery). Перед запуском — отдельное
  подтверждение с предупреждением: пропадут изменения после точки, может
  вернуться исходная проблема (в том числе вредоносный файл), нужна
  перезагрузка, что не охватывается (пользовательские файлы для точек
  восстановления Windows не охватываются).
- В журнале у задачи — ссылка на контрольную точку; UI: «Восстановить
  состояние до начала задачи» — отдельно от «Откатить изменения задачи»,
  не смешивать.

### 3. Опасные действия каталога

Теперь в каталог входят `net.winsock_reset`, `pkg.repair`,
`pkg.install_os_updates` (`dangerous`, `undo: checkpoint`). Политика:
без подготовленной и проверенной контрольной точки — отказ с безопасной
альтернативой. С точкой — подтверждение с перечнем последствий.

### 4. Карантин

- `av.scan_file` (`change`, `not_needed`): Windows — проверка файла
  Защитником (`Start-MpScan -ScanPath` / `MpCmdRun`), если Защитник —
  активный антивирус; найденное помещает в карантин сам Защитник;
  восстановление — его же средствами. Сторонний антивирус → не
  вмешиваться, объяснить пользователю, как проверить его средствами. На
  macOS/Linux штатного сканера с API нет — действие недоступно.
- `quarantine.isolate` (`dangerous`, `exact`): только по явной просьбе
  пользователя для файла, который антивирус не обнаружил, но пользователь
  хочет изолировать. Перемещение в каталог карантина на том же томе с
  сохранением исходного пути, размера, хеша, времён, владельца и прав
  (Windows — SDDL, Unix — режим/владелец/xattr), снятие права исполнения
  в карантине. **Отказ** для файлов в системных каталогах (`C:\Windows`,
  `Program Files` с подписью вендора, `/usr`, `/System`, `/bin`…) —
  вместо этого SFC/DISM или переустановка пакета.
- `quarantine.restore` (`change`, `exact`): возврат с восстановлением
  метаданных и проверкой хеша.
- Окончательное удаление из своего карантина — только отдельным явным
  действием пользователя, не по сроку и не моделью.

### 5. Тесты (ВМ)

Таблица «механизм × ОС»: создание точки и проверка её наличия; отказ
опасного действия без точки; восстановление к точке на Windows-ВМ и
Linux-ВМ со snapper с проверкой, что изменённое после точки вернулось;
карантин и возврат файла с проверкой прав/владельца/хеша на трёх ОС;
отказ карантина системного файла; сценарий «тестовый EICAR-файл → Защитник
находит и изолирует → восстановление из карантина Защитника» на
Windows-ВМ.

## Чего НЕ делать

- Не писать свою систему снимков, копирование дисков, LVM-снимки.
- Не править реестр ради обхода ограничения частоты точек.
- Не удалять файлы как «лечение»; не очищать карантин автоматически.
- Не запускать восстановление системы без отдельного подтверждения и
  предупреждения.
- Не трогать антивирусы сторонних вендоров.
- Не проверять на основной машине владельца.
