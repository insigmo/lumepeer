## Цель

Доверенное ядро AI Support на устройстве, без UI и без сети: каталог
инструментов в `crates/core`, политика «можно / подтверждение / нельзя»,
исполнитель, который безопасно запускает пробы на Windows, Linux и macOS и
возвращает замаскированный, ограниченный по размеру результат. Действия
(изменения) и журнал отката — пачка 17; здесь только чтение.

## Задачи

### 1. ADR

Следующий свободный номер — по правилу из `docs/gap-tasks/README.md`.
Содержание: решения 6, 7, 8, 12 из `docs/ai-support/README.md` в той части,
что касается lumepeer — каталог вместо shell, политика в `crates/core`,
исполнитель в отдельном крейте, шлюз без состояния, локальный режим
первым, без семантического управления UI. Кратко, с «рассмотрено и
отвергнуто».

### 2. `crates/core/src/support.rs`

Чистый модуль без ввода-вывода:

- `ToolId` — newtype со строгой грамматикой (`[a-z][a-z0-9_]*(\.[a-z0-9_]+)+`),
  разбор без паник.
- `ToolKind` (`Probe`, `Action`), `RiskClass`, `UndoKind`, флаги
  (`needs_elevation`, `disrupts_session`, `needs_network`, `slow`) — ровно по
  `contracts.md` § 2.1.
- `ToolSpec` (статическое описание: id, kind, платформы, риск, откат, флаги,
  описание для модели на английском, JSON-схема параметров) и `CATALOG`.
  **В этой пачке в каталоге только пробы из `contracts.md` § 2.2, кроме
  `security.basic_check`** (её добавит 19). Действия добавит 17 — каталог
  не содержит того, что не реализовано.
- Параметры: на каждый инструмент — свой тип с
  `#[serde(deny_unknown_fields)]` и функцией проверки (enum, длины,
  regex). JSON-схему для модели генерировать из этих же типов, чтобы схема
  и проверка не расходились: `schemars`, если `cargo deny` и лицензия
  проходят (обосновать в ADR); иначе — схема рукой + тест, что каждый пример
  схемы разбирается типом и каждый отказ типа отражён в схеме.
- `decide(spec, ctx) -> Decision` (`Auto`, `Confirm { level }`,
  `Refuse { reason }`) — политика из `contracts.md` § 2.1. `ctx`: выданные
  разрешения AI Support (диагностика / изменения), режим (локальный /
  удалённый), есть ли подготовленная точка отката. `match` без `_`-ветки,
  чтобы новый класс риска нельзя было добавить, не решив политику. Тест на
  каждую комбинацию.
- `catalog_fingerprint()` — хеш id + схем, шлюз и клиент сверяют версию.
- Все новые числа — в `constants.rs` с doc-комментарием и ссылкой на ADR.

### 3. Новый крейт `crates/support`

- **Раннер**: только argv, без shell; абсолютные пути к системным
  программам (PowerShell — из `System32\WindowsPowerShell\v1.0`, на Unix —
  из `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin`), не поиск по `PATH`;
  тайм-аут, лимит вывода, отмена (убивает дерево процессов), без
  наследования лишних дескрипторов. PowerShell: скрипт — константа в
  коде, запуск через `-NoProfile -NonInteractive -EncodedCommand`,
  параметры — через переменные окружения после проверки типом.
- **Маскирование** (`redact`): правила `contracts.md` § 2.4; применяется к
  каждому выводу до возврата. Тесты на каждое правило, включая ложные
  срабатывания (номер сборки не должен маскироваться как IP).
- **Пробы** — модуль на ОС (`windows.rs`, `linux.rs`, `macos.rs`) за
  `cfg`, общий тип результата там, где поля совпадают (у `sys.info` —
  одна структура на все ОС). Предпочитать существующие зависимости и
  прямое чтение (реестр через уже используемый в дереве крейт, `/proc`,
  `/sys`, `sysctl`) запуску процесса; процесс — когда иначе никак.
  `fs.read_config` — только закрытый список путей по ОС (константа);
  файлы с секретами (профили NetworkManager с PSK, `shadow`, ключи) в
  список не входят никогда.
- **Матрица возможностей** `capabilities()`: ОС и версия, повышены ли
  права, какие программы реально есть (`nmcli`, `resolvectl`, `ss`,
  `systemctl`, `journalctl`, `pkexec`, пакетный менеджер, `winget`, …) →
  список доступных инструментов и причина недоступности для остальных.
  Модель получит только доступные.
- **Исполнитель** `Executor::run(call, ctx) -> ToolOutcome`: проверка id и
  параметров → `decide` → запуск → маскирование → обрезка по лимиту с
  флагом `truncated`. `ToolOutcome.status`: `ok`, `error`, `timeout`,
  `cancelled`, `unsupported`, `refused` — с машинным кодом причины.
  Параметры от модели — недоверенный ввод: никаких паник, `unwrap` на их
  пути нет.
- Пример `cargo run -p lumepeer-support --example probe -- <id> [json]` —
  для ручной проверки на ВМ (не поставляется).

### 4. Проверка на трёх ОС

Тесты крейта: на текущей ОС каждая доступная проба выполняется, результат
проходит свою схему, в выводе нет ничего, что ловят правила маскирования.
Прогнать на Windows (здесь), Linux (WSL Debian и/или debian-ВМ), macOS
(Mac-ВМ). Для каждой пробы в отчёте: где выполнена, сколько длилась,
размер вывода, что недоступно и почему.

## Чего НЕ делать

- Не добавлять действия, журнал, резервные копии, контрольные точки — это
  17 и 18.
- Не делать UI, IPC-команды, сеть, шлюз.
- Не делать «универсальную» пробу `run_command`/`powershell`/`read_file`
  с произвольным путём.
- Не реализовывать UI Automation / AT-SPI / AX.
- Не тащить крейт `wmi`, `sysinfo` и подобные, если те же данные доступны
  уже имеющимися средствами; новая зависимость — только с обоснованием в
  ADR.
- Не трогать протокол, `consent.rs`, существующие хранилища.
