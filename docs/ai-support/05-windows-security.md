# Пачка 05 — Windows: безопасность

**Репозиторий:** support_knowledge · **Зависит от:** 02 (01 — объём и
источники проверок) · **Нужно:** доступ в веб; ВМ Windows 11 — желательно

Перед началом — `content-workflow.md`, `research/security-assessment.md`
(пачка 01) и `contracts.md` § 3. Каталог: `knowledge/windows/security/`
(документы проверок) — `os: windows`, `categories: [security]`.

## Задачи

### 1. Документ на каждую проверку (`document_type: security_check`)

По одному на каждый id Windows из `contracts.md` § 3, кроме
`win.firewall.profiles` (образец из пачки 02). Для каждого:

- `What is checked` — какой именно сигнал (ключ реестра, командлет, WMI-класс,
  API), минимальные права. Если без прав администратора сигнал не
  читается — так и написать: результат `not_checked (needs elevation)`.
- `Interpreting results` — таблица «значение → status / severity /
  confidence» по `contracts.md` § 3.1; что даёт `unknown`.
- `Remediation` — безопасное исправление, ссылки на `action_ids` там, где
  они есть (`sec.firewall_enable`, `sec.smb1_disable`, `sec.guest_disable`,
  `av.update_signatures`); остальное — ручные шаги.
- `Rollback`, `Limitations` (сторонний антивирус вместо Защитника,
  управляемые организацией ПК — групповые политики, Tamper Protection,
  Windows Home без BitLocker/gpedit и т. п.).
- Обязательно для: `win.update.cu_age` — как сравнивается сборка
  (`CurrentBuild` + `UBR`) с последним накопительным обновлением ветки и
  откуда берётся эталон (пачка 13); `win.os.support_status` — Windows 10
  после 14.10.2025, ESU; `win.accounts.autologon` — проверяется **наличие**
  настройки, значение пароля никогда не читается; `win.apps.outdated` —
  через `winget upgrade`, «устарело» ≠ «уязвимо», связь с KEV только по
  явным данным.

### 2. Вредоносное ПО и подозрительные файлы

1. Подозрение на заражение — порядок действий: не паниковать, не удалять
   руками; проверка штатным антивирусом (Defender quick/full/offline scan),
   журнал угроз, карантин Защитника и восстановление из него.
2. Сторонний антивирус установлен — как определить (`SecurityCenter2`),
   почему не запускать второй антивирус параллельно.
3. Рекламное ПО / угон браузера (поисковик, расширения, политики браузера,
   ярлыки) — безопасное удаление.
4. Подозрительный элемент автозапуска — как оценить (подпись, путь,
   издатель) и отключить обратимо (`startup.disable`), а не удалять.
5. Системный файл подменён/повреждён — SFC/DISM из доверенного источника
   (Windows Update), а не «скачать DLL».

### 3. Восстановление после инцидента

6. Признаки шифровальщика и первые шаги (отключить от сети, не платить, не
   перезагружать без нужды, сохранить заметку о вымогателе), где искать
   официальные расшифровщики (No More Ransom — проверить статус проекта).
7. Резервное копирование для дома: История файлов, OneDrive (что он
   защищает и что нет), образ системы — базовые меры против шифровальщика.
   Без рекламы сторонних продуктов.
8. Скомпрометирована учётная запись Microsoft — официальные шаги.

## Чего НЕ делать

- Не расширять список проверок сверх `contracts.md` § 3; идеи — в отчёт.
- Не писать инструкции по отключению защиты «для диагностики», по обходу
  SmartScreen/UAC, по анализу образцов вредоносного ПО, по эксплуатации
  уязвимостей.
- Не утверждать «система защищена», «уязвимостей нет».
- Не советовать сторонние антивирусы/«очистители» поимённо как решение.
- Не описывать CIS/STIG-бенчмарки целиком — это расширенный аудит (пачка
  23), и копирование бенчмарков нарушает их лицензии.
