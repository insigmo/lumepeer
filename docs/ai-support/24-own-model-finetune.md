# Пачка 24 — своя модель: дообучение поведения малой открытой модели

**Репозиторий:** lumepeer (скрипты и конфиг маршрута) + отдельный
**приватный** каталог/репозиторий для данных и весов (не lumepeer, не
support_knowledge) · **Зависит от:** 21 (обязательно), 22 · **Нужно:**
решение владельца после пачки 21, бюджет на аренду GPU

## Сначала — проверка, нужна ли пачка вообще

Агент начинает с чтения отчёта пачки 21 и отвечает владельцу на три
вопроса цифрами из этого отчёта. Пачка выполняется, только если
владелец сказал «да».

1. Есть ли регион или тариф, где нужный маршрут недоступен или слишком
   дорог (например, пользователи там, где Anthropic и другие крупные
   провайдеры не работают)?
2. Проигрывает ли лучшая открытая модель именно **в поведении**: путает
   инструменты, пропускает диагностику, нарушает запреты, отвечает не на
   том языке? Дообучение лечит поведение. Нехватку знаний оно не лечит:
   знания приходят из базы через поиск (решение 17).
3. Окупается ли своя модель: месячный объём токенов из реальной нагрузки
   (или прогноза владельца) против точки окупаемости из пачки 21. Пока
   объём мал, дешёвый API почти всегда дешевле аренды GPU. Аренда GPU 24/7
   стоит сотни долларов в месяц ещё до учёта поддержки.

Если ответы «нет» — пачка закрывается отчётом «не нужна, вот почему», и это
нормальный исход.

## Цель (если «да»)

Маленькая открытая модель (порядка 7–32 млрд параметров), дообученная
LoRA/QLoRA на правилах поведения AI Support. Она работает через тот же шлюз
как обычный маршрут OpenAI-совместимого адаптера и пользуется базой
знаний через `kb_search` так же, как остальные модели.

## Задачи

### 1. Выбор базовой модели

2–3 кандидата из открытых моделей, лучших в пачке 21 по вызову
инструментов. **Лицензия** должна разрешать коммерческое использование и
производные веса: проверить текущий текст лицензии и ограничения
(пороги пользователей, запреты по сферам) и записать в model card.

### 2. Данные

Обучающий набор — траектории разговоров по нейтральному протоколу (вызовы
проб, `kb_search`, результаты, ответы). Источники только такие:

- траектории сценариев пачки 21, сгенерированные **открытой** моделью-учителем,
  чьи условия разрешают обучение на её ответах (проверить и записать);
  траектории оставляются, только если скрипт проверки сценария подтвердил
  «починено» и не сработал ни один запрет;
- примеры, написанные или исправленные владельцем вручную;
- разговоры пользователей — **только** при отдельном явном согласии
  «использовать мой разговор для обучения», которого сейчас в продукте нет.
  Без него — не использовать вовсе. Согласие пачки 22 на отправку итога
  это не покрывает.

**Ответы Claude в набор не входят** — без письменного разрешения Anthropic
это запрещено (Commercial Terms). Набор маскируется теми же правилами, что
и выводы проб. Нужна карточка набора: источники, лицензии, число
примеров, разбиение train/val/test **по сценариям**, а не по ходам, чтобы
тест не просачивался в обучение. Хранится в приватном месте, не в Git
публичных репозиториев.

### 3. Обучение

Готовый открытый инструментарий для LoRA/QLoRA — выбрать один и обосновать
(PEFT/TRL, Unsloth, Axolotl или аналог). Один воспроизводимый скрипт, все
гиперпараметры в конфиге, арендованный GPU на время обучения. Своего
фреймворка не пишем, RLHF и предобучение не делаем.

### 4. Оценка

Тот же стенд пачки 21. Сравниваются базовая модель, дообученная модель и
лучший маршрут API по цене решённой задачи. Безопасность и инъекции не
должны стать хуже базовой модели — это условие, а не пожелание. Если
дообучение не улучшило поведение на тесте, вывод так и формулируется,
маршрут не включается.

### 5. Варианты запуска (сравнить цифрами)

- **Хостинг открытых моделей** с поддержкой своих LoRA-адаптеров, если
  такой есть у выбранного провайдера: без своего железа.
- **Свой GPU-сервер** с vLLM (OpenAI-совместимый API): новый маршрут в
  конфиге шлюза. Отдельный сервер, его мониторинг и обновления.
- **На устройстве пользователя** (квантованная модель через llama.cpp):
  бесплатно для владельца, но это скачивание в гигабайты, требования к
  железу и заметно более слабая модель. Допустимо только как
  необязательный режим «объяснить и подсказать» **без изменений системы**,
  скачиваемый по желанию. Установленный Lumepeer по-прежнему не должен
  ничего требовать (правило проекта).

Для каждого варианта: стоимость в месяц, стоимость решённой задачи,
задержка ответа, кто и как обновляет модель при изменении каталога и
промпта.

## Чего НЕ делать

- Не начинать без «да» владельца по трём вопросам.
- Не дообучать модель «знаниям» базы вместо поиска и не убирать поиск из
  маршрута.
- Не использовать ответы Claude и данные пользователей без отдельного
  согласия.
- Не публиковать веса и набор данных.
- Не включать модель на устройстве по умолчанию и не давать ей действия,
  изменяющие систему.
- Не держать GPU-сервер включённым, когда он не нужен для задачи.
