## Цель

Пользователь включает AI Support в настройках, проходит согласие, открывает
панель «AI Support», описывает проблему — модель через шлюз вызывает пробы
этого компьютера и поиск по базе знаний, объясняет причину и что делать.
Изменений системы в этой пачке нет (они в 17), поэтому подтверждений
действий здесь тоже нет — но каркас состояний под них закладывается.

## Задачи

### 1. Настройки и согласие

- Раздел «AI Support» в существующих настройках: главный переключатель
  (**по умолчанию выключен**), два разрешения — «Диагностика (только
  чтение)» и «Изменения системы (каждое — с подтверждением)»; второе
  становится доступным только в пачке 17 — до этого его в UI нет.
  Кнопка «Удалить историю AI Support». Других переключателей нет.
- Первое включение открывает экран согласия: что умеет AI Support, какие
  данные и куда уходят (`contracts.md` § 5: устройство → сервер Lumepeer →
  провайдер модели), что хранится локально и сколько, как отозвать и
  удалить. Провайдер называется фактический — шлюз отдаёт его имя и ссылку
  на условия для маршрута устройства (добавить в `/health` или отдельный
  эндпоинт шлюза — по `docs/api.md`); про провайдера — только факты из его
  опубликованных условий, без придуманных сроков хранения. Смена провайдера
  маршрута → согласие запрашивается заново. Без согласия включение не
  действует.
- Настройки хранятся там же, где остальные настройки приложения; адрес
  шлюза — ключ конфигурации (не секрет). Отзыв согласия сразу блокирует
  новые ходы и вызовы инструментов, текущий ход останавливается.

### 2. Клиентский цикл (Rust)

Модуль в `crates/runtime` (или в `crates/support`, если там естественнее —
решить по коду): разговор → `POST /v1/ai/turn` (подпись ключом узла) →
разбор SSE **нейтрального протокола** (`contracts.md` § 4.1) — клиент не
знает, какой провайдер отвечает → сообщение ассистента сохраняется вместе с
непрозрачным `provider_payload` **как пришло**, `route` разговора
запоминается → для каждого `tool_call`: проба каталога → `Executor::run`
(пачка 14), `kb_search` / `kb_get_document` → шлюз; все `tool_result` хода —
одним сообщением → следующий ход, пока `stop` не `end_turn`.

- HTTP — уже имеющийся в дереве `ureq` в отдельном потоке (потоковое
  чтение тела), без нового HTTP-стека в десктопе, если `ureq` справляется;
  иначе — обоснование.
- Проверка ввода инструментов: шлюз уже разобрал ввод, но исполнитель
  проверяет параметры сам (пачка 14) — ошибка → `tool_result` с
  `is_error`.
- `stop`: `max_tokens`, `refusal` (показать категорию человеческим
  текстом, если есть), `error` — по `services/ai-gateway/docs/api.md`.
- Ошибки сети/шлюза/квоты → понятное состояние, без повтора изменяющих
  операций (их пока нет, но правило закладывается).
- **Остановка**: обрывает поток и убивает идущую пробу; незавершённый
  ответ ассистента в историю не попадает; если в истории остался
  `tool_call` без результата — дописывается `tool_result` «cancelled by
  user». История всегда остаётся валидной для следующего хода.
- Предел числа шагов одного хода (константа) — защита от зацикливания.

### 3. Локальная история

Хранилище SQLite (как `audit_store`), путь — новое поле `ActorStores`.
Разговоры: id, время, состояние, `route`, сообщения нейтрального протокола
с `provider_payload` (только дописываются). Отдельно от чата сессий. Срок хранения — константа с
очисткой при старте; удаление по кнопке. Секреты в историю не попадают:
результаты инструментов уже замаскированы исполнителем; текст пользователя
не маскируется (это его текст), но в логи приложения не пишется.

### 4. Панель AI Support

В главном окне — по образцу существующей навигации. Использовать
существующие компоненты сообщений и поля ввода, стили, светлую/тёмную
тему.

- Пустое состояние с 3–4 примерами запросов.
- Реальные состояния этой пачки: выключено, нужно согласие, готов,
  анализирует (идёт поток модели), выполняет диагностику (идёт проба —
  название пробы человеческим языком), завершено, остановлено, ошибка
  (шлюз недоступен / квота / отказ модели / проба не удалась). Никаких
  состояний, за которыми нет механизма.
- Карточки вызовов инструментов: что проверялось, итог, раскрываемые
  детали (замаскированный результат). Ссылки на документы базы, на
  которые модель опирается.
- Кнопка «Стоп» активна только когда есть что останавливать.
- Текст модели — экранированный (lit-html по умолчанию), без
  `unsafeHTML`/`innerHTML`: модельный текст — недоверенные данные, и
  подделанная разметка не должна уметь нажать на кнопки. Простое
  форматирование (абзацы, код) — безопасным рендером.
- Черновик ввода и прокрутка сохраняются при уходе из панели и возврате.

IPC-команды — в трёх местах (`invoke_handler`, `COMMANDS` в `build.rs`,
`capabilities/main.json` + `capabilities-pilot/main.json`). Обновления
потока — тем же механизмом, что уже используется в приложении для
push-событий (если его нет — Tauri events, обосновать).
