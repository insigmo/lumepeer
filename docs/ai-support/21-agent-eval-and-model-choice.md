# Пачка 21 — eval агента, выбор модели и стоимость задачи

**Репозиторий:** lumepeer · **Зависит от:** 17 (лучше и 18–19), контент
03–09, рабочий стек шлюза с несколькими маршрутами · **Нужно:** ключи API
выбранных провайдеров и **бюджет, одобренный владельцем до первого
запуска**; ВМ трёх ОС со снимками для сброса

## Цель

Измерить, насколько AI Support реально чинит типичные проблемы, сколько
стоит одна решённая задача на разных моделях и где агент ошибается.
Цифры — основание для выбора модели по умолчанию (решение владельца) и
для правки системного промпта. Без этих цифр нельзя ни ставить цену, ни
что-то обещать пользователям.

## Прочитать перед началом

- Skill `claude-api`: `shared/evals/build-eval.md` (и `eval-audit.md`,
  который он загружает), `shared/cost-optimization.md`; для доработки
  промпта — `shared/evals/eval-hillclimb.md`. **Следовать им**: интервью
  build-eval включает согласование входов, способа оценки и стоимости с
  владельцем — без его «да» не запускать.
- `services/ai-gateway/prompts/system.md`, код цикла (пачка 16).

## Задачи

### 1. Набор сценариев

15–25 сценариев на ВМ трёх ОС, по темам самых частых документов базы.
Каждый сценарий: скрипт поломки (воспроизводимый, из снимка ВМ),
пользовательская фраза (как пишут люди, ru и en), объективная проверка
«починено» (скрипт), список запрещённого (удаление файлов, отключение
защиты, действие без подтверждения, выдуманный «успех»). Плюс 3–5
сценариев, где правильный ответ — «не чинить самому» (умирающий диск →
бэкап и замена; требование отключить антивирус; проблема вне компьютера),
и 2–3 с инъекцией в выводе пробы/документе (текст «ignore previous
instructions…» в логе) — агент не должен ей следовать.

### 2. Прогон

Автоматический прогон через настоящий цикл клиента (подтверждения —
автоматом по правилу сценария; запрещённые действия ловит проверка).
Метрики на сценарий: починено (по скрипту), запрещённое нарушено, число
ходов и вызовов, токены (`usage`, включая кэш), стоимость по ценам из
skill, время. Сброс ВМ к снимку между прогонами. Каждый сценарий —
несколько повторов (число — по build-eval, с оглядкой на бюджет).

### 3. Сравнение маршрутов

Все прогоны идут через маршруты шлюза (пачка 15), набор — согласовать с
владельцем до запуска:

- Anthropic: `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5` с
  явно заданным `effort` (уровни — по `cost-optimization.md`);
- 1–2 дешёвых сторонних API через OpenAI-совместимый адаптер (кандидаты —
  по актуальным официальным ценам на момент пачки: семейства DeepSeek,
  Gemini Flash, GPT mini/nano);
- 1–2 открытые модели (например, семейства Qwen / GLM / DeepSeek с
  лицензией, разрешающей коммерческое использование) через хостинг-провайдера
  открытых моделей — без своего GPU;
- если владелец рассматривает регион, где Anthropic недоступен, — маршруты,
  которые там допустимы.

Итог — таблица «маршрут × effort → доля починенного, нарушения запретов,
отказы, стоимость **решённой** задачи, время ответа», плюс отдельно —
качество на инъекциях и на сценариях «не чинить самому». Маленькой модели
проваливать безопасность нельзя: маршрут, который хоть раз выполнил
запрещённое, не рекомендуется для тарифов с изменениями системы (только
для чтения/объяснений). Рекомендация — в отчёте; маршруты по тарифам и
регионам выбирает владелец, пачка конфиг не меняет без его слова.

Отдельная строка таблицы — оценка «нужна ли своя модель» (вход в пачку
24): лучший открытый маршрут против лучшего по цене решённой задачи, и
объём токенов в месяц, при котором аренда GPU окупилась бы (по
фактическим токенам на задачу из прогона, а не из блогов).

### 4. Разбор ошибок и промпт

Для каждого провала — причина: нет документа в базе (→ запись в
`coverage/gaps.md` support_knowledge), нет действия в каталоге
(→ предложение), промпт (→ правка `system.md`), модель. Правки промпта —
по hillclimb с разделением train/test; итоговая версия промпта — с
цифрами до/после на test.

## Чего НЕ делать

- Не запускать платные прогоны без согласованного бюджета; не превышать
  его.
- Не гонять сценарии на основной машине владельца.
- Не подгонять сценарии под агента; не выдумывать «успех» без проверки
  скриптом.
- Не менять маршруты, модель по умолчанию и цены квот без решения
  владельца.
- Не сохранять ответы Claude как обучающий набор для пачки 24 — это
  запрещают Commercial Terms Anthropic без письменного разрешения.
- Не публиковать цифры как маркетинговые утверждения.
