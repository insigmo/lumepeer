# Пачка 08 — Обновления ставит session-host

**Репозиторий:** lumepeer · **Зависит от:** 03 · **Нужно:** этот ПК; `beta`
без человека у экрана — для последнего пункта

Прочитать до начала: ADR 0169 §8, ADR 0117 (проверка обновлений при
запуске), ADR 0148 (перезапуск в обновление). Код: команды
`update_check`/`update_install` в `apps/desktop/src-tauri/src/commands.rs`,
`apps/desktop/src-tauri/tauri.conf.json` (`plugins.updater`,
`installMode: perMachine`, публичный ключ), NSIS-хуки бандла,
`.github/workflows/release.yml` (как подписывается `latest.json`),
`CLOSE_RESTARTING` в рантайме.

## Задачи

### 1. Проверка и загрузка в session-host

Session-host (без Tauri) читает тот же манифест обновлений, что
`tauri-plugin-updater`, скачивает установщик в
`%ProgramData%\Lumepeer\updates\` (список: `SY` + `BA`, создаётся через
`program_data.rs` с теми же защитами от точек повторной обработки) и
проверяет подпись minisign **публичным ключом, вшитым в бинарь при сборке**
(тот же, что в `tauri.conf.json`). Не прошло — файл удалён, событие в лог.

### 2. Установка

- Запуск установщика тихо (`/S` для NSIS), отсоединённым процессом, который
  переживёт остановку службы установщиком.
- Перед запуском — `CLOSE_RESTARTING` всем гостям (ADR 0148), как сейчас
  делает клиент.
- Когда: по расписанию session-host, если у машины нет активной сессии, или
  по сообщению клиента «установить сейчас» — оно в перечне канала пачки 03
  допустимо: пакет выбирает не вызывающий, а session-host.

### 3. Клиент

Окно обновления клиента показывает состояние из канала и кнопку «установить
сейчас». Свой `update_install` клиента на Windows при хосте-session-host не
вызывается.

## Чего не делать

- Не принимать от клиента путь, URL или файл установщика — ни в каком виде.
- Не запускать установщик из папки, куда может писать пользователь.

## Статус (2026-10-28)

Код — ветка `unelev/08-updates-by-session-host` (свой worktree, поверх
`befaa2b` с пачками 02+03), **не закоммичено**. Неповышенные юнит-тесты,
`clippy -D warnings`, `fmt`, `npm test` зелёные; повышенный прогон и все живые
пункты ниже **не сделаны** (нужен UAC, установленная NSIS-сборка и `beta`).

Где что:

- `apps/desktop/src-tauri/src/host_update.rs` — проверка, загрузка, minisign,
  запуск установщика, расписание, «установить сейчас», повторный запуск
  клиента после обновления;
- `crates/service/src/program_data.rs` — `updates_directory()`:
  `%ProgramData%\Lumepeer\updates`, `UPDATES_SDDL` = `D:P(A;OICI;GA;;;SY)(A;OICI;GA;;;BA)`,
  владелец `BA`, точка повторной обработки отвергается, чужая (пользовательская)
  папка — **отвергается** (`Foreign::Refuse`), не усыновляется;
- `crates/service/src/console_idle.rs` — `GetLastInputInfo` сессии;
- канал: `Request::InstallUpdate` (вид `0x40`, без полезной нагрузки) с
  новым классом `Effect::Updates`; состояние — поле `update` в
  `HostSnapshot` (`host_panel.rs`, `HostUpdate`: `unknown | off | current |
  available | downloading | installing`);
- `SESSION_HOST_EXIT_UPDATING = 10` (`lib.rs`), служба паркует его как отказ;
- клиент: `update_check`/`update_install` в `commands.rs` идут через канал,
  когда session-host отвечает и обновления ставит он; окно говорит «ставит
  служба» (`system.installNoteService`, `system.installingByService`).

Что сделано не буквально по тексту пачки / ADR:

- **Манифест** — канал по умолчанию (`Settings::default()`: stable,
  GitHub `latest.json`), а не конфиг человека: session-host не читает файлы,
  которые может править любая программа пользователя (так же, как
  `system_host.rs` не читает их для реле). Ключ — `windows-<arch>-nsis`.
  Человек на канале `beta` или со своим `manifest_base_url` от session-host
  получит stable; для этого нужна машинная настройка — не сделано.
- **Публичный ключ** берётся из `tauri.conf.json` (`include_str!` при
  сборке), а не из `apps/desktop/src-tauri/updater.key.pub`: тот файл
  **устарел и не совпадает** с ключом в конфиге (id `B55F…` против `3E3F…`).
- **Проверка подписи** — как у плагина: `minisign-verify` (legacy и
  prehashed), затем доверенный комментарий: если там есть `version:`, он
  должен совпасть с объявленной версией; версия должна быть **новее**
  текущей. Подпись проверяется дважды: в памяти до записи и с диска прямо
  перед запуском (`verified_installer`); не прошло — файл удалён, запись в лог.
- **Когда ставит сам**: нет ни одного гостя **и** консоль без ввода
  `UPDATE_INSTALL_IDLE_SECS` (15 мин) — «никого у машины»; пачка говорит
  только «нет активной сессии», но установка закрывает окно клиента (Restart
  Manager установщика), а с ним — исходящие сеансы человека (ADR 0117 §3).
  По просьбе клиента — сразу, с новой проверкой канала. Неудачная версия по
  расписанию повторно не берётся до следующей проверки (6 ч).
- **Аргументы установщика** — `/S /UPDATE`, **без `/R`**: установщик идёт от
  `LocalSystem`, и его «перезапуск приложения» (`nsis_tauri_utils::RunAsUser`)
  от `SYSTEM` не проверен — риск поднять клиента с WebView под `SYSTEM`.
  Вместо этого session-host перед запуском оставляет в `updates\` файл
  `relaunch-client` (если клиент был подключён), а следующий session-host
  (уже новой версии) запускает клиента токеном человека
  (`client_launch::start_client`) и удаляет файл.
- **Установщик не из NSIS** (dev-сборка, `.msi`): session-host обновлений не
  ставит (`HostUpdate::Off`), клиент идёт своим прежним путём
  (`tauri-plugin-updater`). После пачки 09 это будет UAC — принято.
- Неудача установки в канале отдельным состоянием не показывается: хост
  возвращает `available`, причина — в логе session-host.

## Definition of done

- [ ] Подложенный в `updates\` файл с неверной подписью не запускается
      (тест + живая проверка).
- [ ] Обновление на этом ПК ставится без UAC; гость перезванивает в новую
      версию (ADR 0148).
- [ ] На `beta` без человека у экрана обновление ставится само, хост после
      него доступен.
- [ ] Процесс среднего уровня не может писать в `updates\` (вывод).
- [ ] Повышенный `cargo test`, `npm test`, `fmt`, `clippy`.
