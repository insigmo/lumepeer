# Пачка 07 — Гостевая личность клиента и перенос гостевых хранилищ

**Репозиторий:** lumepeer · **Зависит от:** 03 · **Нужно:** этот ПК и второй
узел-хост, который доверяет этой машине как гостю

Прочитать до начала: ADR 0169 §3 и «Consequences», ADR 0123 §5, ADR 0120,
ADR 0128 (как macOS хранит секреты в файлах профиля). Код:
`apps/desktop/src-tauri/src/placement.rs` (ветка «повышенный запуск» и
«профиль»), `crates/net/src/keystore*`, `crates/core/src/address_book.rs`
(`is_trusted(&NodeId)`), история и запомненные пароли
(`history_*`, `remembered`), `crates/net/src/endpoint.rs`.

## Задачи

### 1. Раскладка для клиента без прав на Windows

Новая ветка `placement.rs`: клиент, когда хостом машины является
session-host, держит **гостевые** хранилища в профиле — гостевая личность
(свой ключ эндпоинта, Credential Manager), список запомненных хостов,
пароли, запомненные для других хостов. Хостовых хранилищ у него нет вовсе.
Документ-комментарий модуля — обновить: какая ветка за что отвечает и почему
(ADR 0169 §3).

### 2. Однократный перенос

При первом подключении клиента к каналу (пачка 03) session-host отдаёт
клиенту гостевую часть из админского дерева **одним сообщением канала
«чтение»** — список запомненных хостов и запомненные для них пароли — и
удаляет её из админского дерева после подтверждения клиента. Хостовая часть
(личность, пароль устройства, адресная книга с доверенными устройствами,
приглашение, аудит) не двигается. Сообщение — в перечне чтения пачки 03, оно
ничего не расширяет: это данные самого пользователя о других машинах.

### 3. Новая гостевая личность

Клиент создаёт новый ключ при первом запуске в этой раскладке. Хосты,
которые доверяли этой машине как гостю, видят новый ключ: один ввод пароля
устройства там восстанавливает доверие. В клиенте при первой неудаче
доверенного входа после переноса — понятная подсказка «этот компьютер
получил новый ключ гостя — введите пароль один раз».

## Чего не делать

- Не давать клиенту ключ хоста ни копией, ни через «подпись по запросу» —
  два эндпоинта с одним ключом дерутся за relay и DHT.
- Не гнать гостевые сессии через session-host (разбор чужих медиа — на
  уровне пользователя, ADR 0169 §3).

## Статус (2026-10-28)

Код — ветка `unelev/07-guest-identity` (свой worktree, поверх `befaa2b`, не
закоммичено). Юнит-тесты, `clippy`, `fmt`, `npm test` зелёные неповышенно;
живые пункты DoD **не сделаны** — нужен маркер `session-host-enabled`,
установленная сборка и второй узел.

Где что:

- раскладка — `placement.rs`: `session_host_guest()` (маркер есть и не
  `LUMEPEER_KEYSTORE=file`) → `guest_only`: ключ гостя, список хостов, пароли
  для них — в профиле; адресной книги, приглашения, аудита и политики нет;
- ключ гостя — обёртка `GuestIdentity`: `IDENTITY_ENTRY` хранится под своей
  записью `lumepeer.guest.identity`, записи политики читаются как пустые и не
  пишутся;
- перенос — `placement::guest_stores` (обе стороны) + запросы канала
  `Request::GuestStores` (`Reads`) / `Request::GuestStoresTaken` (`Narrows`),
  ответ `Reply::GuestStores` (`host_channel_protocol.rs`); session-host отвечает
  в `host_panel.rs` (`Served::keeps_guest_stores`), клиент спрашивает из
  `placement::choose` при старте, до запуска актора;
- слияние списка — `ConnectionHistory::adopt` (строка, уже бывшая в профиле,
  выигрывает; результат проверяется перечитыванием файла);
- подсказка — файл `guest-key-renewed.json` рядом со списком хостов, IPC
  `guest_key_hint` (одноразово на хост), строка `invite.newGuestKey` под
  формой подключения (`invite-view.ts`).

Что сделано не буквально по тексту пачки:

- **«Один ввод пароля восстанавливает доверие» — код так не умеет, и это
  правильно.** Хост предлагает пароль только доверенному устройству
  (`may_try_unattended`: `address_book.is_trusted`), а доверие ставит только
  клик человека у хоста (ADR 0034, ADR 0120: «Nothing about connecting, being
  admitted or finishing a session trusts a device»). Новый ключ гостя хосту
  незнаком, поэтому первый вход идёт через окно согласия (или отказ
  `CONSENT_UNAVAILABLE`, если у хоста никого нет); человек у хоста впускает и
  жмёт «Сохранить устройство» — после этого запомненный пароль снова входит
  сам. Подсказка говорит именно это. Сделать «пароль восстанавливает доверие»
  — расширение допуска в `crates/core`, это ADR, не эта пачка. ADR 0169
  («One device-password entry there re-trusts it») в этом месте расходится с
  кодом.
- **Отдельная запись ключа гостя**, а не `IDENTITY_ENTRY` профиля: профиль
  может ещё держать копию ключа хоста (перенос ADR 0123, у которого не
  прошло удаление), и тогда клиент поднял бы второй эндпоинт с ключом хоста.
  Первый старт в этой раскладке всегда создаёт новый ключ.
- **Раскладка гостя — для повышенного и неповышенного клиента одинаково**
  (было: только повышенный при маркере). `claim_host_role` читает тот же
  `session_host_guest()` и не берёт роль ни в каком случае.
- **Перенос — при старте клиента**, а не на «первом подключении к каналу»
  вообще: список хостов актор читает один раз при запуске, и писать файл
  из-под работающего актора бесполезно. Если session-host ещё не отвечает
  (вход в Windows, гонка автозапуска) — перенос на следующем старте.
- **Session-host хостит без гостевых хранилищ** (`placement::for_session_host`:
  `history: None`, пароли — в памяти): иначе его актор фоновым поиском
  сохранённых хостов (`refresh_saved_hosts` → `remember_addrs`) переписал бы
  удалённый список обратно. Логон-хост не тронут (`for_system_host` как был);
  после переноса файла нет, и ему нечего загружать.
- **Подтверждение принимается только на том же соединении**, где был
  отдан ответ `GuestStores`. Прочитать гостевую часть может любая программа
  пользователя — это его же пароли к чужим машинам, после переноса они в
  Credential Manager профиля с той же доступностью (ADR 0169,
  «Consequences»).
- **Подсказка** — только при повторном подключении из списка хостов, к
  хосту, для которого был запомнен пароль (значит, хост доверял старому
  ключу), и только один раз на хост.
- **Откат** (маркер убрали) не обработан: повышенный клиент вернётся к
  админскому дереву уже без списка хостов. Маркер живёт до пачки 09.

## Definition of done

- [ ] После переноса клиент без прав видит все прежние сохранённые хосты и
      входит к ним с запомненными паролями.
- [ ] Админское дерево больше не содержит гостевой части; хостовая — на
      месте, гости этой машины входят как раньше.
- [ ] Хост, доверявший машине как гостю: первый вход — пароль и подсказка,
      второй — без пароля.
- [ ] Клиент и session-host одновременно онлайн с разными ключами, оба
      достижимы (лог relay без вытеснения).
- [ ] Повышенный `cargo test`, `npm test`, `fmt`, `clippy`.
