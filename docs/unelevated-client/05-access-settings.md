# Пачка 05 — Политика доступа через `--access-settings`

**Репозиторий:** lumepeer · **Зависит от:** 02 · **Нужно:** этот ПК, клик
UAC владельца; стандартная учётная запись (ВМ или `beta`) — для одного пункта

Прочитать до начала: ADR 0169 §5 (второй пункт), ADR 0123 §5, ADR 0033,
ADR 0126 §3, ADR 0133 §3. Код: `apps/desktop/src-tauri/src/placement.rs`,
`crates/service/src/program_data.rs`, команды `unattended_*` и
`address_book_*` в `apps/desktop/src-tauri/src/commands.rs`, панель
неприсмотренного доступа во фронтенде, `claim_host_role` в `main.rs`.

## Задачи

### 1. Режим `--access-settings`

- Клиент запускает **сам себя** через `ShellExecuteExW` с `runas` и
  аргументом `--access-settings`. Один UAC — в момент, когда человек нажал
  «Изменить настройки доступа» (кнопка со щитом).
- Этот процесс — нынешний повышенный клиент без хостинга: роль занята
  session-host, `claim_host_role` уже даёт «не хост». Он открывает только
  окно настроек доступа: пароль устройства, второй фактор (QR), роль
  неприсмотренного доступа, экран входа Windows, список доверенных устройств.
  Пишет в админское хранилище тем же кодом, что сейчас (`placement.rs`).
- Никаких исходящих подключений и окна гостя в этом режиме.

### 2. Сигнал session-host

После записи процесс настроек сигналит именованное событие
`Global\lumepeer-policy-changed-<SID>`, список `SY` + `BA` (тест строки).
Session-host ждёт его и перечитывает политику; идущие сессии
переоцениваются как при отзыве (пароль сменили — неприсмотренные сессии по
старому паролю не рвём, но новый вход — по новому; так же, как сейчас при
смене пароля в повышенном клиенте — проверить по коду и сохранить
поведение).

### 3. Клиент без прав

- Панель неприсмотренного доступа в обычном клиенте — **только чтение**
  (состояние из канала пачки 03) и кнопка со щитом.
- Выключить неприсмотренный доступ — сужение, допустимо через канал без UAC
  (ADR 0169 §4); включить, задать пароль — только через `--access-settings`.

## Чего не делать

- Не передавать новый пароль из клиента без прав в session-host по каналу,
  даже с подтверждением в диалоге — подменённый в клиенте пароль диалог не
  покажет (ADR 0169 §5).
- Не открывать админское дерево для чтения пользователю.

## Статус (2026-10-28)

Код — ветка `unelev/05-access-settings` (свой worktree, поверх `befaa2b` с
пачками 02+03), не закоммичено. Неповышенно зелёные: `cargo test` по
`lumepeer-service` (110), `lumepeer-runtime` (335), `lumepeer-desktop` (38 + 1
известный красный `the_pilot_capabilities_allow_everything_production_does`),
`clippy -D warnings` по трём крейтам (и десктоп с
`capture-windows,encode-mf`), `fmt`, `npm run typecheck`, `npm test` (982),
`npm run ipc-contract`. Повышенный прогон и все живые пункты DoD **не
сделаны** — нужен UAC и маркер.

Где что:

- **Запуск со щитом** — `lumepeer_service::access_settings::open_elevated`
  (`ShellExecuteExW`, `runas`, `SEE_MASK_NOASYNC`), команда IPC
  `access_settings_open` (в `COMMANDS`, `capabilities/main.json` и pilot-копии,
  `permissions/autogenerated/access_settings_open.toml`). Отказ в UAC —
  `ACCESS_SETTINGS_CANCELLED`. Команда работает только когда хостит
  session-host (`host_panel` есть), иначе `ACCESS_SETTINGS_NOT_NEEDED`.
- **Режим `--access-settings <SID>`** — `apps/desktop/src-tauri/src/access_settings.rs`.
  Проверяется в `main()` до single-instance: процесс без роли хоста, без
  актора, без эндпоинта, без трея, без окна гостя. Отказывается стартовать не
  повышенным (код 3), без маркера `session-host-enabled` (код 4: без ADR 0169
  политику держит актор повышенного клиента, который сигнала не слышит), без
  открываемого защищённого каталога (код 5). Окно — то же `main` (его
  capability и `check_window`), но страница `access.html`
  (`src/access-settings-window.ts`, свой вход в `vite.config.ts`), обычная
  рамка. Команды `unattended_*` и `address_book_*` находят управляемое
  `AccessSettings` вместо актора и пишут через те же `UnattendedStore` /
  `AddressBookStore`; смена доверия пишется в аудит, как у актора.
- **Сигнал** — `Global\lumepeer-policy-changed-<SID>`, список
  `D:(A;;GA;;;SY)(A;;GA;;;BA)` (тест строки: нет `IU`/`WD`/`AU`/`BU`/SID),
  auto-reset. Session-host создаёт его (`PolicyChanges::create`) и на каждом
  тике открытого состояния при сигнале зовёт новую команду актора
  `reload_policy` (лог «the access policy changed on disk; read it again
  without restarting»). Процесс настроек сигналит после каждой записи.
- **Перечитывание** (`ActorCommand::ReloadPolicy`, `UnattendedStore::reload`,
  `AddressBookStore::reload`): поведение — как при смене в повышенном клиенте,
  проверено по коду (`on_unattended_set_password`, `on_unattended_disable`,
  `on_address_book_set_trusted`): новый пароль/роль решают следующий вход,
  идущие сессии не рвутся (и при отзыве доверия тоже — актор их и сейчас не
  рвёт), выключение сбрасывает входы в полёте. Счётчик неудач и блокировка
  перечитыванием **не сбрасываются** (иначе сигнал = лишние попытки).
- **Клиент без прав**: `HostSnapshot.unattended` (новое поле, `serde(default)`)
  несёт состояние из актора session-host; `unattended_status` в клиенте при
  `hosted_by_service` читает его, `managed_by_service: true`. Панель
  (`unattended-settings.ts`, ветка `managedByService`) — только чтение, кнопка
  со щитом и «Выключить». Выключение — новый сужающий запрос канала
  `Request::UnattendedOff` (`0x15`, `Effect::Narrows`, без полезной нагрузки).
  `unattended_set_password` / `_set_totp` / `_set_role` / `_set_logon_screen` в
  этом клиенте отвечают `ACCESS_SETTINGS_REQUIRED`; **пароль по каналу не
  ходит никогда**.

Что сделано не буквально по тексту пачки:

- **SID в командной строке.** `--access-settings` несёт SID того, чью политику
  править: на стандартной учётке UAC просит пароль администратора, и
  повышенный процесс работает уже от *администратора* — его собственный SID
  указал бы не тот каталог. Подставить чужой SID ничего не даёт: прошедший UAC
  и так администратор. Отсюда же `set_logon_screen_for(account)` и
  `host_logon_screen_unless_declined_for(account)` в `commands.rs` (вынесено из
  существующих функций, поведение для обычного клиента прежнее).
- **Без актора в процессе настроек.** Повторить «нынешний повышенный клиент»
  целиком значило бы поднять эндпоинт с ключом, который держит session-host
  (драка за реле, ADR 0169 §3), и разбор сетевого ввода в повышенном
  процессе. Логика записи повторена в `AccessSettings` по образцу методов
  актора (≈60 строк), хранилища и их типы — общие.
- **Логон-экран в режиме только-чтения не показывается** (`logon_screen: null`
  в снимке): владельца читает только админ; меняется он в окне настроек.
- **Адресная книга в клиенте без прав не читается из канала**: доверенные
  устройства видны и правятся только в окне настроек. В обычном клиенте при
  маркере книга пуста (так было и после пачки 03).
- **Каталог, которого нет.** Если человек ни разу не запускал повышенный
  клиент, окно настроек создаст защищённый каталог и запишет пароль, но
  session-host всё равно выйдет `NO_STORE` (нет личности) — вопрос пачки 09.

Осталось (нужен владелец):

- Повышенный прогон: `Start-Process -Verb RunAs` →
  `cargo test -p lumepeer-service` (в т.ч.
  `access_settings::tests::an_unadmitted_caller_cannot_signal_a_change` — в
  повышенном прогоне проверяет, что администратор *допущен*) и
  `cargo test -p lumepeer-desktop`.
- Живые пункты DoD ниже: маркер `session-host-enabled`, установленная сборка,
  гость с `beta`, стандартная учётка.

Неповышенные пробы, уже сделанные (DoD п. 3, наполовину): запись файла в
`C:\ProgramData\Lumepeer\users\<SID>` и даже его листинг из процесса среднего
уровня — `Access to the path ... is denied`; сигнал события со списком
`SY`+`BA` из процесса среднего уровня — `ERROR_ACCESS_DENIED` (тест выше, на
`Local\`-имени: `Global\` неповышенный процесс не может даже создать).

## Definition of done

- [ ] Кнопка со щитом → UAC → окно настроек → пароль задан → гость входит по
      новому паролю, по старому — нет; session-host перечитал без
      перезапуска (лог).
- [ ] Выключение неприсмотренного доступа из обычного клиента — без UAC.
- [ ] Процесс среднего уровня не может записать политику (попытка записи в
      каталог и сигнала события — `ACCESS_DENIED`, вывод в отчёте).
- [ ] На стандартной учётке кнопка просит пароль администратора — так и
      должно быть; записано.
- [ ] Повышенный `cargo test`, `npm test`, `fmt`, `clippy`.
