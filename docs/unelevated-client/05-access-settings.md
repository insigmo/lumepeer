# Пачка 05 — Политика доступа через `--access-settings`

**Репозиторий:** lumepeer · **Зависит от:** 02 · **Нужно:** этот ПК, клик
UAC владельца; стандартная учётная запись (ВМ или `beta`) — для одного пункта

Прочитать до начала: ADR 0169 §5 (второй пункт), ADR 0123 §5, ADR 0033,
ADR 0126 §3, ADR 0133 §3. Код: `apps/desktop/src-tauri/src/placement.rs`,
`crates/service/src/program_data.rs`, команды `unattended_*` и
`address_book_*` в `apps/desktop/src-tauri/src/commands.rs`, панель
неприсмотренного доступа во фронтенде, `claim_host_role` в `main.rs`.

## Задачи

### 1. Режим `--access-settings`

- Клиент запускает **сам себя** через `ShellExecuteExW` с `runas` и
  аргументом `--access-settings`. Один UAC — в момент, когда человек нажал
  «Изменить настройки доступа» (кнопка со щитом).
- Этот процесс — нынешний повышенный клиент без хостинга: роль занята
  session-host, `claim_host_role` уже даёт «не хост». Он открывает только
  окно настроек доступа: пароль устройства, второй фактор (QR), роль
  неприсмотренного доступа, экран входа Windows, список доверенных устройств.
  Пишет в админское хранилище тем же кодом, что сейчас (`placement.rs`).
- Никаких исходящих подключений и окна гостя в этом режиме.

### 2. Сигнал session-host

После записи процесс настроек сигналит именованное событие
`Global\lumepeer-policy-changed-<SID>`, список `SY` + `BA` (тест строки).
Session-host ждёт его и перечитывает политику; идущие сессии
переоцениваются как при отзыве (пароль сменили — неприсмотренные сессии по
старому паролю не рвём, но новый вход — по новому; так же, как сейчас при
смене пароля в повышенном клиенте — проверить по коду и сохранить
поведение).

### 3. Клиент без прав

- Панель неприсмотренного доступа в обычном клиенте — **только чтение**
  (состояние из канала пачки 03) и кнопка со щитом.
- Выключить неприсмотренный доступ — сужение, допустимо через канал без UAC
  (ADR 0169 §4); включить, задать пароль — только через `--access-settings`.

## Чего не делать

- Не передавать новый пароль из клиента без прав в session-host по каналу,
  даже с подтверждением в диалоге — подменённый в клиенте пароль диалог не
  покажет (ADR 0169 §5).
- Не открывать админское дерево для чтения пользователю.

## Definition of done

- [ ] Кнопка со щитом → UAC → окно настроек → пароль задан → гость входит по
      новому паролю, по старому — нет; session-host перечитал без
      перезапуска (лог).
- [ ] Выключение неприсмотренного доступа из обычного клиента — без UAC.
- [ ] Процесс среднего уровня не может записать политику (попытка записи в
      каталог и сигнала события — `ACCESS_DENIED`, вывод в отчёте).
- [ ] На стандартной учётке кнопка просит пароль администратора — так и
      должно быть; записано.
- [ ] Повышенный `cargo test`, `npm test`, `fmt`, `clippy`.
