# Пачка 04 — Согласие и расширение прав в нативном окне session-host

**Репозиторий:** lumepeer · **Зависит от:** 03 · **Нужно:** этот ПК; второй
узел-гость (`beta` или локальный второй экземпляр)

Прочитать до начала: ADR 0169 §5, ADR 0054 (роли и гранты), ADR 0057 §4
(`secure_desktop_input` не даёт ни одна роль), ADR 0120 (сохранить
устройство), ADR 0131 (терминальные сессии рядом с управлением).
Код: обработка `ConsentRequest`/`session_grant`/`session_set_grant` в
`crates/runtime/src/network.rs` и `crates/core`, окно согласия во фронтенде
(`apps/desktop/src`), `apps/desktop/src/i18n.ts` (строки ru/en).

## Задачи

### 1. Диалог

- `TaskDialogIndirect` из session-host (манифест бинаря уже тянет
  Common-Controls v6 — `build.rs`). Модуль
  `apps/desktop/src-tauri/src/session_host/consent.rs` (или рядом с
  `session_host.rs`), `unsafe` под обоснованием как в `crates/service`.
- Содержимое — только текст: имя гостя и устройства, ОС, запрошенная роль.
  Строки от пира — экранированы как простой текст, длина обрезана; никаких
  гиперссылок (`TDF_ENABLE_HYPERLINKS` выключен).
- Кнопки: «Разрешить», «Только просмотр» (если запрошено управление),
  «Отклонить»; флажок «Запомнить это устройство» (ADR 0120). Тайм-аут —
  как у нынешнего окна согласия, по тайм-ауту — отказ.
- Язык — системный UI-язык, ru/en; строки — в Rust-таблице рядом с
  диалогом, тексты сверить с `i18n.ts`.

### 2. Что идёт через диалог

- впуск гостя без пароля устройства (attended);
- повышение роли в идущей сессии (просмотр → управление);
- включение `secure_desktop_input` для гостя;
- «доверять этому устройству».

Каждое — решение актора session-host после ответа диалога; клиент об этом
только узнаёт из канала (пачка 03).

### 3. Клиент

- Окно согласия клиента при хосте-session-host не показывается (иначе два
  окна на один запрос); вместо него — строка «запрос подключения — ответьте в
  системном окне».
- Кнопки расширения в панели хоста клиента — убрать или сделать
  «попросить хост показать диалог» — **не** командой расширения: канал
  такой не знает. Допустимо сообщение «покажи диалог повышения для сессии X»,
  если оно само ничего не повышает — проверить это тестом.

## Чего не делать

- Не открывать WebView в session-host — ни для красоты, ни для QR.
- Не оставлять путь согласия через клиента «на всякий случай».
- Не давать `secure_desktop_input` роли «полное управление» по умолчанию —
  ADR 0057 §4 в силе.

## Definition of done

- [ ] Гость без пароля → у хоста появляется системный диалог; «Разрешить» —
      сессия есть, «Отклонить» и тайм-аут — нет.
- [ ] Пробник среднего уровня (`SendInput` по координатам кнопки,
      `PostMessage(BM_CLICK)`, UI Automation `Invoke`) диалог не нажимает —
      записать вывод.
- [ ] «Запомнить устройство» → следующий вход этого гостя без диалога.
- [ ] Повышение до управления и включение `secure_desktop_input` — только
      через диалог; клиентский канал не умеет (тест).
- [ ] Русский и английский тексты на машинах с соответствующим языком.
- [ ] Повышенный `cargo test`, `npm test`, `fmt`, `clippy`.
