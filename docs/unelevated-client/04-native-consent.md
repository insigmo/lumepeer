# Пачка 04 — Согласие и расширение прав в нативном окне session-host

**Репозиторий:** lumepeer · **Зависит от:** 03 · **Нужно:** этот ПК; второй
узел-гость (`beta` или локальный второй экземпляр)

Прочитать до начала: ADR 0169 §5, ADR 0054 (роли и гранты), ADR 0057 §4
(`secure_desktop_input` не даёт ни одна роль), ADR 0120 (сохранить
устройство), ADR 0131 (терминальные сессии рядом с управлением).
Код: обработка `ConsentRequest`/`session_grant`/`session_set_grant` в
`crates/runtime/src/network.rs` и `crates/core`, окно согласия во фронтенде
(`apps/desktop/src`), `apps/desktop/src/i18n.ts` (строки ru/en).

## Задачи

### 1. Диалог

- `TaskDialogIndirect` из session-host (манифест бинаря уже тянет
  Common-Controls v6 — `build.rs`). Модуль
  `apps/desktop/src-tauri/src/session_host/consent.rs` (или рядом с
  `session_host.rs`), `unsafe` под обоснованием как в `crates/service`.
- Содержимое — только текст: имя гостя и устройства, ОС, запрошенная роль.
  Строки от пира — экранированы как простой текст, длина обрезана; никаких
  гиперссылок (`TDF_ENABLE_HYPERLINKS` выключен).
- Кнопки: «Разрешить», «Только просмотр» (если запрошено управление),
  «Отклонить»; флажок «Запомнить это устройство» (ADR 0120). Тайм-аут —
  как у нынешнего окна согласия, по тайм-ауту — отказ.
- Язык — системный UI-язык, ru/en; строки — в Rust-таблице рядом с
  диалогом, тексты сверить с `i18n.ts`.

### 2. Что идёт через диалог

- впуск гостя без пароля устройства (attended);
- повышение роли в идущей сессии (просмотр → управление);
- включение `secure_desktop_input` для гостя;
- «доверять этому устройству».

Каждое — решение актора session-host после ответа диалога; клиент об этом
только узнаёт из канала (пачка 03).

### 3. Клиент

- Окно согласия клиента при хосте-session-host не показывается (иначе два
  окна на один запрос); вместо него — строка «запрос подключения — ответьте в
  системном окне».
- Кнопки расширения в панели хоста клиента — убрать или сделать
  «попросить хост показать диалог» — **не** командой расширения: канал
  такой не знает. Допустимо сообщение «покажи диалог повышения для сессии X»,
  если оно само ничего не повышает — проверить это тестом.

## Чего не делать

- Не открывать WebView в session-host — ни для красоты, ни для QR.
- Не оставлять путь согласия через клиента «на всякий случай».
- Не давать `secure_desktop_input` роли «полное управление» по умолчанию —
  ADR 0057 §4 в силе.

## Статус (2026-10-28)

Код — ветка `unelev/04-native-consent` (отдельный worktree поверх `befaa2b`,
не закоммичено). Юнит-тесты, `clippy -D warnings`, `fmt`, `npm test`
(981 тест), `npm run ipc-contract` зелёные **неповышенно**; повышенный
прогон и все живые пункты DoD **не сделаны** — нужен UAC, маркер
`session-host-enabled` и второй узел.

Где что:

- диалог — `crates/service/src/consent_dialog.rs`: `TaskDialogIndirect`,
  `unsafe` под обоснованием как в остальном крейте. Флаги —
  `TDF_ALLOW_DIALOG_CANCELLATION | TDF_CALLBACK_TIMER`, **без**
  `TDF_ENABLE_HYPERLINKS`; окно `HWND_TOPMOST`; таймер закрывает его по
  тайм-ауту или когда вопрос отозван (`Outcome::{Expired, Withdrawn}`), Esc и
  крестик — `Dismissed`; NUL внутри строки выбрасывается. Язык —
  `GetSystemDefaultUILanguage` (русский → ru, иначе en). Не в
  `desktop`-крейте, потому что там `forbid(unsafe_code)`. Функция `ask`
  резолвится только в процессе с манифестом Common-Controls v6 (десктопный
  бинарь) — в тестах `lumepeer-service` её не вызывать: импорт не даст
  тестовому exe загрузиться;
- слова, кнопки и смысл ответа — `apps/desktop/src-tauri/src/session_host_consent.rs`
  (`Consents`): таблица ru/en, `plain` (обрезка до
  `CONSENT_DIALOG_PEER_TEXT_MAX_CHARS`, без управляющих и bidi-символов),
  `decide` (только нажатие «да» что-то расширяет; отозванный вопрос не
  отклоняет никого — гостя мог уже впустить пароль устройства), `carry_out`
  (перед действием сверяет, что запрос/сессия всё ещё те же);
- session-host: `attendance()` = `Attended`; каждый тик `Consents::follow` по
  `status()` ставит вопрос на каждую ожидающую строку и снимает вопросы,
  чья строка исчезла. Правило §7 и «закрыть невидимые сессии» теперь считают
  только **активные** строки: ожидающий запрос — дело диалога, иначе через
  10 с без клиента он отзывался бы посреди ответа;
- канал: новый запрос `Request::AskToWiden { peer, widening }` (вид `0x30`,
  `widening` — закрытый байт `Control | SecureDesktopInput | TrustDevice`),
  класс `Effect::Asks`. Он **только ставит диалог** session-host и отвечает
  `Done`/`Refused`; ни поля «да», ни роли на проводе нет (тесты
  `an_ask_to_widen_carries_no_answer`, `no_request_widens_anything`,
  `a_widening_happens_only_on_a_yes`, `a_closed_host_asks_nobody_anything`);
- клиент: новая IPC-команда `session_ask_host` (`build.rs`, `main.rs`,
  `capabilities/main.json`, `capabilities-pilot/main.json`, autogenerated
  permission); при `hostedByService` окно согласия не рисуется — вместо него
  строка `consent.answerInSystemWindow`; в меню карточки сессии вместо
  «Сохранить устройство» — «Дать управление… / Разрешить запросы
  администратора… / Сохранить это устройство… (спросит в системном окне)»,
  каждая показывается только когда есть что спрашивать; 4 новых ключа i18n
  во всех 13 локалях;
- константы — `CONSENT_DIALOG_TIMEOUT_SECS = 60`,
  `CONSENT_DIALOG_PEER_TEXT_MAX_CHARS = 64` в `crates/core/src/constants.rs`.

Что сделано не буквально по тексту пачки:

- **`secure_desktop_input` у «полного управления» уже есть.** Пачка просит не
  давать его роли по умолчанию (ADR 0057 §4), но код — `Grants::from_role` —
  с ADR 0061 даёт его `FullControl`. Не менял: это решение ядра и ADR. Через
  диалог включается обратно то, что клиент сузил по каналу (`LowerGrant`), и
  текст диалога на «Разрешить полный доступ» прямо говорит про запросы UAC.
- **Тайм-аут.** У нынешнего окна согласия тайм-аута нет (ждёт, пока гость
  сдастся), поэтому завёл свой — 60 с, по тайм-ауту отказ.
- **«Запомнить устройство» = доверять (ADR 0120)**, не «впускать без
  согласия»: следующий вход без диалога — только по паролю устройства
  (диалог и проверка пароля идут параллельно, ADR 0063; пароль приходит —
  диалог снимается сам). Без заданного пароля устройства доверие диалога не
  отменяет — ADR 0034 §1 не трогал.
- **Повышение до управления** — повторный `grant(label, FullControl)` по
  активной сессии (ядро это поддерживает: `grant_as` сохраняет id и цели
  туннелей). На живой паре не проверено.
- **Несколько гостей сразу** — по диалогу на каждого, параллельно (не
  очередь); на одного гостя — не больше одного вопроса.
- **Ответ на просьбу записи** в режиме session-host по-прежнему не
  предлагается (пачка 03 его скрыла) — в списке пачки его нет.
- Пока экран заблокирован, диалог на `Default` никто не видит — запрос
  отклоняется по тайм-ауту.

Осталось (нужен владелец: UAC, маркер, второй узел):

- повышенный прогон: из повышенного PowerShell в корне worktree
  `$env:CARGO_TARGET_DIR='C:\Users\beta_win\git\lumepeer\target'; $env:CARGO_INCREMENTAL='0'; cargo test -p lumepeer-service`
  и `$env:__COMPAT_LAYER='RunAsInvoker'; cargo test -p lumepeer-desktop --features capture-windows,encode-mf`;
- все пункты DoD ниже, кроме «клиентский канал не умеет (тест)».

## Definition of done

- [ ] Гость без пароля → у хоста появляется системный диалог; «Разрешить» —
      сессия есть, «Отклонить» и тайм-аут — нет.
- [ ] Пробник среднего уровня (`SendInput` по координатам кнопки,
      `PostMessage(BM_CLICK)`, UI Automation `Invoke`) диалог не нажимает —
      записать вывод.
- [ ] «Запомнить устройство» → следующий вход этого гостя без диалога.
- [ ] Повышение до управления и включение `secure_desktop_input` — только
      через диалог; клиентский канал не умеет (тест).
- [ ] Русский и английский тексты на машинах с соответствующим языком.
- [ ] Повышенный `cargo test`, `npm test`, `fmt`, `clippy`.
