## Текущие открытые вопросы

### 1. Аудио: какой кодек Opus-крейт брать в воркспейс?
Спецификация (§5.1) называет Opus единственным аудиокодеком, но конкретный крейт
не зафиксирован. Кандидаты: `opus` (sys-биндинги к libopus), `audiopus` ,
`opus-rs`, либо чистый Rust `opus-native`/`magnum-opus`. Системный libopus даёт
лучше качество/зрелость, но ломает «build needs no platform SDK by default».
**Предлагаю:** `audiopus_next`/`opus` за фичей `audio-opus` с системным libopus,
как уже сделано для openh264.

### 2. Unattended-пароль: argon2 или PBKDF2 через существующие зависимости?
В воркспейсе нет ни одной KDF-зависимости. Для паролей устройств нужен медленный
хеш. `argon2` (RustCrypto) — современный стандарт; PBKDF2 можно собрать из уже
имеющихся `sha2`+`hmac`, если они есть транзитивно.
**Предлагаю:** добавить `argon2` как workspace-зависимость.

### 3. TOTP 2FA: реализовывать самим (RFC 6238, ~50 строк) или брать крейт?
Крейт `totp-rs` тянет много зависимостей. RFC 6238 поверх уже имеющегося
`blake3`/HMAC-SHA1 не покрывается — нужен SHA1-HMAC. Вариант: минимальная
своя реализация HMAC-SHA1 без новых зависимостей (SHA1 нужен только для
совместимости с Google Authenticator).
**Предлагаю:** своя минимальная реализация + unit-тесты на RFC-векторах.

### 4. Приоритет платформ: подтверждаете порядок Windows → Linux → macOS?
Сейчас машина разработки — Windows. macOS-бэкенд фактически уже написан
(ScreenCaptureKit, ADR 0013), Wayland — портал есть, кадров нет. Я предлагаю:
сначала всё кроссплатформенное ядро (протокол, unattended, адресная книга,
файловый канал), затем Windows-специфика (SendInput, WASAPI, privacy mode),
затем Linux (PipeWire-кадры, uinput), macOS-доделки — по остатку.
Нужен ли другой порядок?

### 5. Мобильные/web клиенты: делать заготовки сейчас или отложить?
В ADR заявлены iOS/Android viewer'ы, кода нет вообще. Это отдельные большие
проекты. **Предлагаю:** отложить до готовности десктопа; в questions.md они
остаются открытыми.

### 6. Relay: свой сервер или документация поверх iroh-relay?
iroh уже содержит релейную инфраструктуру (`iroh-relay`). Разворачивать свою
инфраструктуру или просто написать deployment-документ и конфиг для
самостоятельного запуска iroh-relay?
**Предлагаю:** документация + docker-compose для self-host iroh-relay, без
собственного кода релея.

### 7. Запись сессии: формат записи?
Session recording упоминается в протоколе (`RecordRequest`), но формат файла
не определён. Варианты: MKV с h264+opus, кастомный контейнер, последовательность
frames+логов.
**Предлагаю:** кастомный контейнер (последовательность фреймов с таймстемпами +
аудио-чанки + лог событий) — без внешних зависимостей, экспорт в MKV потом.
